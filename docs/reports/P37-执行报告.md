## 1. 改了什么

### 1.1 服务端 `server.js`

| 位置 | 改动 |
| --- | --- |
| 顶部输出兜底 | `process.stdout/stderr.on('error')`：`EPIPE` / `ECONNRESET` 静默；其它输出错误尝试打印到另一条流 |
| 崩溃兜底 | `uncaughtException` / `unhandledRejection` 打印并**追加**写入 `tmp/server.log`（含 `[崩溃兜底]`、方法/路径或 `- -`、错误栈），**不退出进程** |
| 全局错误中间件 | 所有路由之后：先保留 413 / JSON 解析 400；其它错误写入 `tmp/server.log`（`METHOD URL` + 栈），响应 `500 {"error":"服务器内部错误"}`，不回传栈 |
| 监听错误 | `server.on('error')`：EADDRINUSE 输出端口、`netstat -ano | findstr :<port>`、`set PORT=3001 && node server.js`，退出码 1；其它监听错误打印栈并退出 1 |
| 启动自证 | 保留原打印，新增四行：`监听地址`（含 PORT 是否外部指定）、`数据库文件`（SQLite 绝对路径 / MySQL 无本地文件）、`数据目录`、`页面根目录`，均 `path.resolve` |

## 6. 不确定项

1. **跨端口探测与 CORS**：同 host 不同端口属于跨源，后端未加 `Access-Control-Allow-Origin`；用 `mode:'no-cors'` 只判断端口是否有响应，并兼容 Service Worker 合成的 503（视为不可用）。因此无法读取目标端口响应体/版本内容，只能判定“有服务”。未改任何后端 CORS。
2. **端口漂移验证方式**：7 条用真实 3000→3001；8 条用沙箱 3005→3006，并在测试浏览器中拦截生产 3000 的探测请求，避免第二次停生产。两条链路使用同一份 `nav.js`。
3. **横幅遮罩**：按 C3 使用 `position:fixed; top:0` 覆盖页面顶部 38px（不推挤布局）；它不会改变页面文档流高度。
4. **uncaughtException 状态风险**：按提示词要求不退出进程；若未来在未结事务中抛错，进程状态可能不一致，届时需另行评估是否改为记录后退出让面板重启。
5. **SW 缓存键**：D12 验收在全新测试 profile 上执行，旧版本留下的 Cache Storage 条目未纳入；生产用户升级后由 SW 版本轮换清理旧缓存。
6. **范围**：`home.html` / `setup.html` 未引入 `nav.js`，本批未覆盖；其它四页已引入。
