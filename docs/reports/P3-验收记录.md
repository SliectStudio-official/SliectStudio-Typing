## 四、不确定项与处置

| # | 项 | 处理 |
| --- | --- | --- |
| 1 | 改密后旧 token 仍有效 | K-05 已登记的残留，需 `token_version` 列（schema 变更），留待后续；不得悄悄当作已修 |
| 2 | 初始化接口没有 72 字节上限 | 新登记坑库 **K-18**：同一业务规则在多入口，只改了提示词列举的那几处；建议随 P5 补一行 |
| 3 | 局域网无法首次初始化 | 拍板后接受的取舍，已写进上线提示；`launcher.ps1` 本来就在本机打开 setup 页 |
| 4 | 限流计数在内存 | 重启即清空；若有人恶意刷登录，进程重启前会持续锁定该 `ip+用户名` 组合。可接受，不引入持久化 |
| 5 | Node v25 / MySQL 未实测 | 沿已定 #16 / #17 |
| 6 | 生产 token 是否真的全部失效 | 取决于部署是否沿用 `launcher.config.ps1` 的同一 `JWT_SECRET`。若沿用，旧 token 理论仍有效；按上线提示统一要求用户重登 |

## 五、结论

**通过。** 32 项核对全部达成。三条要点：① 鉴权链闭环（降级即失权、删号即失效），但**改密不失效**是明确残留，不许当已修；② 密钥体系已无硬编码，重启复用与环境污染两条都用独立进程验过；③ 初始化接口的回环限制实测生效（局域网 403 / 本机 400），副作用已在报告与上线提示中写明。另新登记 K-18（校验入口不全），并要求本轮同步更新模块图与架构图。
