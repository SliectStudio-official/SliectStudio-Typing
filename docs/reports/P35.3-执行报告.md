## 1. 改了什么

### 1.1 服务端 `server.js`

| 位置 | 改动 |
| --- | --- |
| `GET /api/admin/code-languages` | admin 端点：返回 `{ all: [{id,name,articleCount}], selected: [ids] }` |
| `PUT /api/admin/code-languages` | admin 端点：校验 `ids` 为非负整数数组、长度 ≤20、去重、逐个确认分类存在（否则 400「分类不存在」），写回 `setCodeCategoryIds` |
| `PUT /api/articles/:id` | 可选接收 `status`（只允许 `approved` / `pending`）；不传时保留原状态。用于 C5 上下架，未新增端点 |
| `DELETE /api/leaderboard` | 可选 `category=code`：只删 `article_id` 属于当前代码分类的成绩；不传参数保持清空全部；其它参数值 400 |

## 6. 不确定项

1. **概览统计显示 0（既有问题，本批未改）**：`GET /api/admin/dashboard` 返回 camelCase（`totalUsers` 等），`loadDashboard()` 读 snake_case（`total_users` 等），因此概览数字为 0。该问题与 P35.3 无关，未顺手修改；建议单独一批修。
2. **C5 的 PUT 扩展**：现有 `PUT /api/articles/:id` 原本不接收 `status`。为满足「复用 PUT 上下架、不得新增端点」，只在该端点增加可选 `status` 校验与更新；不传时行为不变。
3. **难度写入需要两步**：`POST /api/articles` 不接受难度，代码素材新增先 POST 建立文章，再立即 PUT 写入所选 `difficulty_override`；若第二步失败会提示「素材已创建，但难度设置失败」，不会静默吞掉。
4. **D1 的 `#new-content`**：普通 tab 的分类下拉按 A7 排除了语言分类，因此正常 UI 无法把 `#new-content` 切到代码块；代码素材新增使用独立的 `#code-new-content`。`#new-content` 的切换逻辑已接入，供分类变更时复用，验收第 11 条用代码素材编辑弹窗（`#edit-content`）实测。
5. **测试数据位置**：代码素材 id 22、代码/游客成绩、语言分类临时切换只在 `tmp/p35.3-app` 副本库；生产库未写测试数据。沙箱验收结束后停止。
