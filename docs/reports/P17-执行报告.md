## 一、改了什么

### A 组：后端（`server.js`）

| # | 改动 |
| --- | --- |
| A1 | `upload` 的 `limits.fileSize` 从 2MB 改为 `5 * 1024 * 1024` |
| A2 | `fileFilter` 白名单改为 `.jpg/.jpeg/.png/.webp`，移除 `.gif`；不允许时文案「仅支持 JPG/PNG/WebP 格式」 |
| A3 | `/api/user/avatar` 对 multer `LIMIT_FILE_SIZE` 单独返回 400「图片不能超过 5MB」；其它 multer 错误仍返回其 message |
| A4 | 保留原 `filename = userId_timestamp + 扩展名`、旧头像文件删除与 `users.avatar` 更新逻辑 |
| A5 | 服务端不缩放/裁剪，只做大小/类型兜底 |
| A6 | 新增 `avatarExtension()`：有扩展名按白名单原样使用；无扩展名按 MIME（jpeg/png/webp）推导，落盘必带扩展名 |

`storage` 的 filename 回调改为调用 `avatarExtension(file) || '.jpg'`；无扩展名 webp 的 curl 测试落盘为 `.webp`。

### B 组：前端（`profile.html` / `profile.js` / `style.css`）

- `profile.html`：文件 input 的 accept 改为 JPG/PNG/WebP；新增 `#avatar-crop-overlay` 裁剪确认框（1:1 圆形预览、原生 canvas、缩放滑杆、重新选择/取消/确认）。
- 个人中心头像 id 从 `avatar-img` 改为 `profile-avatar-img`，**修复导航栏与个人中心同 id 的冲突**，保证上传成功刷新的是个人中心头像；导航栏仍由 nav.js 自行管理。
- `profile.js`：
  - `change` 先本地校验：`>5MB` 提示「图片不能超过 5MB（当前 x.x MB）」；MIME 不在 jpeg/png/webp 提示「仅支持 JPG/PNG/WebP」；两种情况都不发请求并清空 input；
  - `createImageBitmap(file, { imageOrientation: 'from-image' })` 读取原图，失败回退 `<img>` + `URL.createObjectURL`；
  - 320×320 预览画布，1×–3× 缩放、Pointer 拖动、滚轮/滑杆缩放；偏移 clamp，保证不露空白；
  - 导出新建 256×256 canvas，`toBlob(..., 'image/jpeg', 0.9)`，FormData 字段名 `avatar`，文件名为 `avatar.jpg`；
  - 取消/遮罩/Esc/重新选择都清理 `input.value`、关闭弹窗、`revokeObjectURL` / `ImageBitmap.close()`，不发请求；
  - 上传时确认按钮禁用并显示「上传中…」；成功后 `avatarImg.src = data.avatar + '?t=' + Date.now()`；失败显示后端 `error`。
- `style.css`：新增裁剪弹窗、圆形预览、缩放滑杆、错误文案、420px 弹窗宽度和按钮布局；零新依赖。

## 二、怎么验证

测试环境：`tmp/p17-app`，复制 `server.js` + `public/`，独立 SQLite 库，端口 **3077**；`public/avatars` 为沙箱副本，未触碰生产库/生产头像。A 用 curl（header 放临时文件，不在终端打印 token）；B 用 headless Chrome + CDP 合成事件。

### A 组：curl 五条

| 场景 | 读数 |
| --- | --- |
| 6MB jpg | HTTP **400**，`{"error":"图片不能超过 5MB"}`；无新文件落盘 |
| 4.9MB png | HTTP **200**，`{"success":true,"avatar":"/avatars/2_1793986716518.png"}`；落盘文件 **5,138,022 字节**；前一张旧头像文件已不存在 |
| `.gif` | HTTP **400**，`{"error":"仅支持 JPG/PNG/WebP 格式"}` |
| `.txt` 改名 `.png` | HTTP **200**（后端仅按扩展名放行，未做魔数校验；这是已知边界） |
| 无扩展名 webp | HTTP **200**，落盘 `/avatars/2_1793986471067.webp` |

A4 旧头像删除：先上传小 jpg 得到旧文件名 `2_1793986451985.jpg`，再上传 4.9MB png；旧文件查询为「old deleted」，只留下新头像文件（以及沙箱自带的历史文件）。

### B 组：七条场景

| 场景 | 读数 |

## 三、怎么回滚

- A：`git revert efdace1`，恢复 2MB、`.gif` 白名单、原 fileFilter 文案与无扩展名落盘行为。
- B：`git revert 3e0f727`，删除裁剪弹窗标记/样式/逻辑，并把个人中心头像 id 恢复为 `avatar-img`。
- 手工回退时注意：B 同时修了 `profile-avatar-img` 的重复 id；只删裁剪逻辑而保留新 id 不影响 nav，但旧 `getElementById('avatar-img')` 会重新指向导航头像，需一并恢复 selector。

## 四、不确定项

1. **A 的 4.9MB png 是随机字节文件**，后端按扩展名放行（A 明确不要求魔数），能落盘但不是可显示图片；真实图片的 5MB 边界未用相机原图复测。
2. **B 的 4.9MB 前置校验用“有效小 PNG + 填充”构造**，只验证了大小门槛与裁剪框打开，没有真正上传这张 4.9MB 文件；确认上传用的是小尺寸有效图片（导出后 1,145 字节 JPEG）。
3. **EXIF 用 PIL 合成 fixture**，不是手机实拍原图；验证了浏览器 `from-image` 的方向，未在真实手机照片上复测。
4. **移动端只改了视口并用 CDP 鼠标/合成 Pointer 拖动**；没有真实触屏双指/触摸拖动，也未测试原生文件选择器的“重新选择”流程（headless 无法可靠弹出文件对话框）。
5. **B9 的资源释放**：取消后 `avatarCrop.source=null`、弹窗关闭，代码路径调用 `close()`/`revokeObjectURL()`；浏览器内部是否立刻回收无法直接读数，仅做代码与状态验证。
6. **个人中心头像 id 改动**是 P17 为 B5 “刷新头像”补的既有冲突修复（导航与个人中心同 id）；不在提示词显式条目内，但属于头像上传链路。
7. **A 文件类型判断只看扩展名/无扩展名时看 MIME**，前端看 MIME；两端对“扩展名对、内容假”的文件会放行，符合 A 的已知边界。
