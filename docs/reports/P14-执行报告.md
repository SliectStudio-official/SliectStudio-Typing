## 四、不确定项

1. **全部交互为自动化合成事件**：内置 browser-use 的 `navigate_page` / `evaluate_script` / `click` 在测试中途开始返回 `Tool not found`，改用 headless Chrome 156.0.8078.80 + CDP（`Runtime.evaluate`、`Input.dispatchMouseEvent`、`Input.dispatchKeyEvent`）。没有真人点击，也没有截图；以上都是 DOM、接口响应与时序读数。
2. **C4/C5 的二次确认是合成的**：`window.confirm` 被替换为 `() => true`；真实浏览器原生弹窗的视觉与取消分支未点。
3. **K-30 的浏览器侧未做端到端复验**：B 组验证了「不重启服务，HTML 的 `?v=` 与 `/api/asset-version` / SW 注入版本立即更新」；但测试过程中多次手动注销 Service Worker 并清 CacheStorage 以排除旧缓存。已有旧 SW 的客户端在真实网络下首次导航是否一定能拿到新 HTML，需要在真实浏览器再复验一次。
4. **B 组耗时口径**：2.755ms / 2.700ms 是同一实现下「文件未变」与「文件变更后」的 curl 中位数，不是「旧实现 vs 新实现」的对照；差值在噪声内，不能据此得出显著性能结论。
5. **A5 大数字格式**：菜单对 `chars >= 10000` 仍显示「1.2万」这种缩写，不是接口原始整数；本次用 245 字验证精确值，未验证大数字场景。
6. **A4 桌面点击语义**：鼠标悬停会先打开菜单，因此桌面端在「已悬停展开」状态下再点头像会收起；从关闭状态用 DOM 点击可打开。触屏/键盘（无 hover）点击可打开，已实测；真人鼠标的完整「悬停→点击→移动」序列未由人操作。
7. **C 失败态是模拟的**：通过页面上下文把 `/api/admin/races` fetch 替换成 500 响应，不是真实服务端宕机。
8. **提交范围**：仓库中仍有本批之前未提交的规划侧改动（`style.css`、`index.html`、`profile.html`、`service-worker.js`、`race.*` 等），本批没有顺手提交它们；A 提交的 `nav.js` 为首次入库，B/C 提交的文件包含各自既有的未提交内容。
