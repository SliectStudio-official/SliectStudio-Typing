## 三、新发现：K-20（不属于本批，但必须记）

抽代码跑桩时暴露了一个**不是我要求、也不是本批引入**的问题：编辑用户的四个输入框语义不一致——

| 输入 | 留空时的实际行为 |
| --- | --- |
| 用户名 | 不修改 |
| 邮箱 | **清空该用户邮箱**（body 会带 `"email":""`） |
| 密码 | 不修改 |
| 角色（本批新增） | 不修改 |

于是「只想改角色，邮箱框留空」就会把对方的邮箱抹掉。执行方在报告里也点到了这条（不确定项 3），处理正确、没有擅自改。已登记 **K-20**，需要用户先定语义（改成「留空不修改」还是保留「留空即清空」）再动代码。
