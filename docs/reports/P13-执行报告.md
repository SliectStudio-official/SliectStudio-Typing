## 二、id 矩阵审计（§2.1）

一次性脚本放在 `tmp/p13-audit-ids.mjs`，执行完已按提示词删除。方法：从四个脚本抽 `getElementById('X')`（`race.js` 另抽 `$('X')` 别名），从对应 HTML + `nav.js` 抽 `id="X"`，按页面求差集；同时用花括号深度扫描顶层直接取元素/绑定的语句。

| 页面 | 脚本引用 id | HTML id | nav.js id | 差集 | 顶层直接取元素/绑定 |
| --- | --- | --- | --- | --- | --- |
| `index.html` | `script.js` 81 | 77 | 20 | **0** | 79 条 |
| `race.html` | `race.js` 41 | 50 | 20 | **1（非缺陷）** | 0 条（整文件在 IIFE 内） |
| `profile.html` | `profile.js` 46 | 53 | 20 | **0** | 39 条 |
| `admin.html` | `admin.js` 127 | 141 | 20 | **0** | 277 条 |

**差集里唯一的 `btn-spec-leave` 不是缺 id。** `race.js:330` 在 `renderSpectate()` 里用 `innerHTML` 自己创建这个按钮，随后 `race.js:331` 立即取回并绑定；它不在静态 HTML/nav 中属于设计如此。

顶层空指针风险点：

- 四个页面都是 `nav.js` 先于页面脚本执行（`index/profile/admin`：nav 为普通脚本、页面脚本 `defer`；`race`：nav 在 `race.js` 之前），当前所有被顶层读取的 id 都能在 HTML 或 nav 渲染结果中找到；本轮浏览器矩阵中四页均未出现 `TypeError`。
- 但 `script.js`（79 条）、`profile.js`（39 条）、`admin.js`（277 条）仍保留**大量顶层 `const X = getElementById(...)` 与顶层 `addEventListener`**。这意味着一旦 `nav.js` 自身加载失败，三页会整体停摆——不是当前会复现的 bug，但是同类故障的结构性风险。本批没有把这些全部改成判空写法：涉及数百处、超出「修实际缺陷」的范围，按提示词只登记风险。
- `race.js` 的所有取元素都在 IIFE 内的函数或末尾 `bind()` 中，页面元素已解析，未发现顶层裸取。

   - 1200px 补测：`340px 718px`，侧栏 340px，三种形态与 CSS 断点（1024 / 768）一致。
   - 900px 下没有汉堡按钮是当前 CSS 断点（768）的结果，不是本批改动；如果需求要求 900px 也走抽屉，需要改样式，属另一批。

## 六、不确定项与未验证

1. **双窗口未做到**：内置浏览器只有一个页面且视口不可见，比赛全流程是两个登录账号 + 一个匿名观战账号**顺序**跑完的，不是同一时刻的两个窗口；无痕会话用不同源（127.0.0.1 / localhost）模拟独立存储。观战的“实时”是在页面重新选中后读到的 1.2s 轮询结果，未做三窗同屏。
2. **真实中文输入法未验证**：只派发了 `CompositionEvent`，没有在操作系统拼音输入法下点候选词；这一点需要人工在浏览器里补一次。
3. **900px 的汉堡菜单**：当前断点是 768px，900px 显示桌面导航，没有汉堡；若验收口径要求 900px 也能抽屉，需要改 CSS，本批未改。
4. **观战数据缺口（后端，未改）**：`buildSnapshot` 只在 `finish` 时写入 `speed/accuracy`，比赛中的观战导播台「速度 / 正确率 / 用时」始终是 `—`。这是 P12 后端快照的字段缺口，不是前端可修；要补需在 tick 时计算并回传，属后端批次。
5. **游客刷新/重连（前端，未改）**：`doJoin` 把游客 token 存进 `sessionStorage`，但页面重载后没有任何代码读回它；服务端其实支持凭该 token 重连。当前游客刷新后只能重新入座，同 IP 会被「同一 IP 只能有一个游客席位」拦住。是否为 P13 范围有争议（更像重连功能），本批只登记，未实现。
6. **id 审计的顶层风险未消除**：`script.js/profile.js/admin.js` 仍有大量顶层取元素；当前 id 全部存在，但 nav.js 失败会整体停摆。按提示词只登记风险点，未做大范围判空改造。
7. **比赛结果对比**：主流程的两行名次（141s/166s）是修复前 `race.js` 跑出的；修复后仅针对房间码、实时速度、单人名次做了复测，未把双人全流程再跑一遍。
8. **首页错字记录**：实测到 `stat-wrong=1` 与错字标红；未等待/检查“错题本”持久化数据的接口落库，`error_logs` 未读。
9. **角色切换登记**：本批规划侧前端改动（P12.5–P12.7）仍未提交在 Git；执行方只改了 `race.js`，没有提交任何文件（提示词未要求提交；工作区还混有其它未提交改动，避免误提交）。
10. **数据结构与关系清单**：本批无表结构、字段、枚举、外键变化；`CONTRACT_VERSION` 未动。

## 七、typing-engine 与首页 script.js 的差异（只记录，不合并）

| 项 | 首页 `script.js` | 比赛页 `typing-engine.js` |
| --- | --- | --- |
| 分段规则 | 32 字/行、`0.65` 最小断点、同一组标点断点 | 完全复制同一套规则 |
| 输入框 | `.typing-page` / `.typing-line-text` / `.typing-line-input`，`compositionstart/end` 守卫 | 同上，类名与样式一致 |
| 渲染 | 虚拟化窗口（`VIRTUAL_THRESHOLD=200`）+ 增量 update | 每次输入全量重建所有段落的 HTML |
| 统计 | 增量缓存 `cachedCorrect/cachedWrong`、朗读、错题练习、限时/全文模式 | 每次重算，无朗读、无错题、无模式与计时器 |
| 自动填充防护 | 渲染后 `requestAnimationFrame` 清空非用户输入 | 无 |
| 段落 `name` | `typing-segment-<时间>-<序号>` | 无 |

合并会牵动首页计分、朗读、错题与计时，按提示词停止点未做合并；本批只把比赛页的速度显示与首页对齐的结果做了记录（见改动 #2）。
