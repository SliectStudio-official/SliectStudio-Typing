# P12.7 打字一致性与观战席（规划侧直接实现）

> 触发：用户指出「比赛界面输入与首页不一致，会改变用户操作习惯」，并要求加观战席（房主可设、导播视角看全场）。
> 角色声明：本轮为快速迭代，规划侧直接改了前端与部分后端；验收由我事后自查 + 隔离实例复跑，不等同于独立验收。

## 一、打字一致性：抽出 `typing-engine.js`，比赛页与首页同一套交互

| 项 | 首页做法（来源 `script.js`） | 比赛页现在 |
| --- | --- | --- |
| 分段 | `splitTextIntoSegments`：每行最多 32 字，向前找标点/空格断行 | **同一函数同一参数**（引擎内复制自首页） |
| 渲染 | 每段一张 `.typing-page`，内含 `.typing-line-text` 的 `span.char` | 同样结构、同样类名 |
| 输入 | 每段一个 `.typing-line-input`，input 事件 + `compositionstart/end` 兼容中文输入法 | 同样 |
| 状态 | pending / correct / wrong / current 四态 | 同样 |
| 翻页 | 本段全对自动进入下一段 | 同样 |
| 样式 | 等宽 22px、错字标红、当前字高亮 | 复用同一套类（比赛内只做容器收边） |

比赛页不再使用自制的隐藏 textarea + 自绘字符，**手感与首页一致**。

**遗留（已记待办）**：首页 `script.js` 里仍有一份同样的引擎实现。彻底去重要把首页也切到 `typing-engine.js`，需回归全部打字用例（计时/统计/错字记录/朗读），单独一批再做，避免把已验收的练习流程改坏。

## 二、观战席（导播台）

| 能力 | 实现 |
| --- | --- |
| 房主开关 | 房间页勾选「允许观战」（`POST /api/race/spectator-setting`，房主可随时开关，关闭后新观战者进不来，已在场的不受影响） |
| 观战加入 | 大厅「以观战身份加入」勾选，凭房间码+密码进入；**不占比赛名额**、不受比赛阶段限制 |
| 观战身份 | 登录用户直接用账号；游客填昵称，拿房间内短期 JWT；身份与选手彻底分开（`room.spectators` 单独一张表） |
| 观战上限 | 每房 8 个观战席位 |
| 导播台视图 | 左栏：焦点选手（进度/速度/正确率/用时，点击任意一行切换焦点）+ 比赛信息 + 观战人数；右侧：**全场实时战况**（名次、进度条、百分比、速度或完成用时） |
| 观战者限制 | 不能准备、不能完赛（服务端直接 400），只读快照 |
| 解散/结束 | 客房取消时观战者同样收到提示并回大厅 |

## 四、隔离实例复跑（观战链路）

| # | 场景 | 读数 |
| --- | --- | --- |
| 1 | 建房 → B 以选手加入 → 游客以观战加入 | 200 / 200 / 200，`spectator=true` |

## 五、结论与遗留

通过（自查）。遗留三项：① 首页与比赛页的引擎去重；② 观战席目前没有`观众发言/表情`这类互动，也未做「切换回选手视角」；③ 移动端导播台把进度条隐藏成三列，信息略少。
