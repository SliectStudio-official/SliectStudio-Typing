## C. 管理端备份与恢复

### C1. 实现口径

| 项 | 实现 |
| --- | --- |
| 快照 | 通过适配器暴露的 `db._sqlite.backup(临时文件)`（better-sqlite3 官方 API，实测返回 Promise）生成一致性快照；不直接拷活动库 |
| 打包 | `execFile('powershell', ... Compress-Archive ...)`，`-NoProfile`、120s 超时、`windowsHide`，无 `shell: true`；解包用 `Expand-Archive -LiteralPath` |
| 目录 | 临时产物全部落 `tmp/`，`try/finally` 清理；成品落 `backups/`，已加入 `.gitignore` |
| 备份内容 | `typing.db`、`VERSION`、`CONTRACT_VERSION`、`version.json`、`manifest.json`；`db-config.json` / `public/avatars` 默认不含，分别由复选框控制 |
| 清单 | 每次备份另写一个 `<zip>.meta.json` sidecar（仅含名字/大小/时间/版本/是否含配置/是否含头像/是否 pre-restore），供列表显示“含配置”而不必反复解包；ZIP 内仍以 `manifest.json` 为准 |
| 恢复 | 校验 manifest/sha256/schema_version → 强制先生成 `backup-...-pre-restore.zip` → 写 `data/typing.db.import` 与 `data/restore-pending.json` → 返回 `needRestart`；启动时在 `initDatabase()` 之前换库，失败回滚并继续用现库启动 |
| 并发 | 模块级 `backupTaskBusy`；create/restore 开始时占用，结束/上传失败时释放，重复请求 409 |
| 保留 | `backups/*.zip` 最多 10 份（pre-restore 计入），按文件名时间从旧到新删除并打日志 |
| 下载/删除 | 文件名白名单 `^backup-\d{8}-\d{6}-[0-9.]+(?:-pre-restore)?\.zip$`；另加 `download/*` 兜底，带路径分隔符的请求统一 400 |

> **与提示词字面不同的一处**：pre-restore 备份命名为 `backup-YYYYMMDD-HHMMSS-<VERSION>-pre-restore.zip`，因此下载/删除白名单在正常版本号分支之外增加了受控的 `-pre-restore` 后缀分支。否则列表里会出现无法下载/删除的合法备份。恶意路径仍全部拒绝。

## 4. 不确定项 / 需要用户知道的

1. **并行提交污染**：A 组代码进了 `64da1ee`（docs 提交），C 组主体进了 `c79c8cc`（design 提交）；用空提交/补丁提交保留了规定 message，但没有改写共享历史。若要求严格“三提交各自只含对应代码”，需要规划侧在合并前整理提交历史。
2. **pre-restore 文件名/白名单**：为了让 pre-restore 备份也能下载/删除，下载/删除白名单增加了 `-pre-restore` 安全分支；与提示词里给出的单一正则不完全字面一致。
3. **MySQL**：在线备份/恢复仅对 SQLite 实现；MySQL 会返回 400（不支持在线备份/恢复），本轮未启动 MySQL 实例实测。
4. **头像选项**：已用测试文件验证 `includeAvatars` 会把 `public/avatars/*` 打进 ZIP；但真实头像数量多/体积大时的 120s 打包超时未压测。
5. **列表“含配置”**：通过 `<zip>.meta.json` sidecar 显示；若手动删除 sidecar，列表会显示“否”，ZIP 内 manifest 仍为准。
6. **A 的 522/540**：打字引擎分段会省略换行处空白字符，`.char` 数量少于文章字符数；这是既有的分段行为，不是本次防御逻辑造成。若用户截图里的“272 个字符”与此有关，建议另开 P 条目核对文章/分段统计口径。
7. **生产 3000**：验收时本机 3000 端口无进程；所有读数来自隔离端口。部署时必须重新启动 `server.js`，备份面板与页面 302 才会生效。
8. **删除确认截图**：原生 `confirm` 为浏览器级弹窗，CDP 截图只能截到页面本体；已用 CDP `Page.javascriptDialogOpening` 捕获确认原文作为证据（`确定删除备份 …？此操作不可恢复。`），截图见 `C13-delete-confirm-page.png`。
9. **Service Worker 离线边界**：在线导航（含 `setup.html → /`）已实测不打架；首次 setup 的 302 响应可能被 SW 按原请求键缓存，极端断网首访的缓存命中未单独复测。B 组文件白名单不含 `service-worker.js`，本轮未改 SW；如规划侧认为需要，可另开条目处理。
