## 一、改了什么

### A 组：公告统一（`index.html` / `profile.html` / `script.js` / `profile.js` / `style.css` / `announcement-bar.js`）

- `index.html`、`profile.html` 删除静态 `.announcement-bar` 标记，改为在 `nav.js` 之后引入 `announcement-bar.js`；两页与 `race.html` 共用同一模块。
- `announcement-bar.js` 的插入点从 `#site-nav` 之后改为 `.sub-nav` 之后；没有 `.sub-nav` 时才退回主导航之后。
- `script.js` 删除 5 个 `announcement*` 常量、`LEVEL_LABELS`、`loadAnnouncement()`、`setInterval(...,60000)` 与初始化调用；`profile.js` 删除同名公告常量、函数、关闭监听与调用。公告只剩 `announcement-bar.js` 一份实现。
- `style.css` 新增 `--nav-h` / `--subnav-h`：默认 `44/56`，≤768px 为 `56/52`，≤480px 为 `52/48`；`nav`、`.sub-nav` 与 `.announcement-bar` 使用变量，公告 `top: calc(var(--nav-h) + var(--subnav-h))`、`z-index: 51`、`width: 100%`。
- 公告关闭按钮从 `top:50% + translateY(-50%)` 改为 `top:0; bottom:0; display:flex`，避免桌面高度下按钮上下越界。
- `profile.html` 删除内联 `.announcement-bar / .announcement-level-badge / .announcement-title / .announcement-text / .announcement-close`；同时删掉内联 `nav` 高度、`.sub-nav` 的 `height/top` 覆盖，改用 `style.css` 的变量规则。**这是本批唯一一处实际高度变化：profile 在 ≤480px 的 nav 从旧内联 44px 变为全局 52px；桌面与 768 档不变。** 需要回退就恢复这几处内联声明。
- `admin.html` 未引入模块，公告管理区块的 `section-announcements` 与 `announcement-list` 保持原样。

### B 组：通知中心（`server.js` + `nav.js` + `style.css`）

- 新增只读 `GET /api/notifications?limit=20`（需要登录）：
  - 公告复用 `getActiveAnnouncement()`，最多 1 条，`id = announcement:<id>`；
  - 比赛结果从 `race_participants JOIN races` 取当前用户、`status IN ('finished','aborted')`，按 `finished_at` 倒序最多 10 条；正文为「你第 N 名 / 共 X 人 · 字数 · 字/分 · 正确率」，`link = race.html?code=<code>`；
  - 两类按 `time` 倒序合并，`limit` 最终截断；无新表、无新依赖。
- 头像菜单新增「通知中心」入口与未读角标（>9 显示 `9+`，0 隐藏）；游客额外有导航栏铃铛入口，打开后只看公告和「注册后可保留比赛记录」。
- 通知面板为右上角固定面板（移动端左右各 8px、最大 60vh），支持关闭、全部标为已读、点击比赛通知跳转。
- 已读状态存 `localStorage.notification_read_ids`，去重并最多 200 条；展开通知面板时把当前列表全部标为已读并归零角标。
- 登录态在页面加载后拉一次通知用于角标；展开时若距上次拉取超过 60 秒才再次请求，**不跟随 1.2s 比赛轮询**。

### C 组：比赛重连（`server.js` + `race.js` + `race.html` + `typing-engine.js` + `style.css`）

- 新增只读 `GET /api/race/active`：
  - 用户 token：先找选手席位（仅活动房间），再找观战席位；
  - 游客 token：按 token 中的 `raceCode + guestId` 查，房间没了也返回 `200 { code: null }`，不返回 401；
  - 找到时返回 `{ code, state: buildSnapshot(...), isSpectator }`。
- `race.js` 加载时调用 `/api/race/active`：有房间自动 `enterRoom(code)` 并提示「已恢复上次的比赛」；`race.html?code=ABC` 只用于已在房间的直达，不在房间则预填房间码并提示「请用房间码和密码加入」。
- 每次成功 tick 写 `localStorage.lastRaceCode`；游客短期 token 只写 `sessionStorage.raceToken:<CODE>`（登录用户不再把用户 JWT 写 sessionStorage）；离开房间、房间解散、比赛结束都会清掉恢复点。
- `typing-engine.js` 新增 `restore(typedCount)`：按服务端 `me.progress` 回填分段内容、字符状态和当前输入框，刷新后可从中途继续。`race.js` 在首次挂载 engine 时调用。
- 轮询连续失败不清界面；连续 **3 次**后在顶部显示「连接中断，正在重试…」，恢复后隐藏并提示「已重新连接」；不再把网络失败当成离开房间。服务端重启/房间丢失时提示「比赛已中断」。
- 不改房间生命周期、数据表、`VERSION`、`CONTRACT_VERSION`。

## 四、不确定项

1. **全部交互为合成操作**：本批使用 headless Chrome + CDP 的 DOM 事件、合成鼠标/键盘和 Network.emulateNetworkConditions；没有真人点击、没有截图。真实输入法、真实网络切换、真实 Service Worker 冷启动未验证。
2. **A 的 480px 高度变化**：为了让三页共用 `--nav-h`，删除了 `profile.html` 旧内联 nav/sub-nav 高度覆盖，≤480px 的 profile nav 从 44px 变为全局 52px。提示词的停止点要求改高度先报；我判断这是“去掉失准的页面级覆盖，使变量与全局值一致”，但这是本批唯一的实际布局变化，汇报给规划侧确认。
3. **B 的原始样例含公告**：两场比赛 + 活动公告时角标是 3；为对齐验收“2 场比赛 → 角标 2”，测试时临时停用了公告。公告停用/恢复通过管理接口完成，最终已恢复启用。
4. **B 未实测 `9+` 与大列表滚动**：只造了 2 场比赛，`>9` 格式和 200 条已读上限是按代码核对，没有构造 10 条以上数据。`全部标为已读`按钮存在并已绑定，但主要归零路径是“展开即已读”，未单独点击验证。
5. **C 的“关标签页 30 秒再开”**：用户侧用刷新/重新打开同源页面验证了 localStorage 恢复；没有真正关闭标签页再等 30 秒。游客 token 按设计存 `sessionStorage`，**关闭标签页会丢失游客 token**，因此“游客关标签页再开仍能回房”在现有存储方案下做不到；本批验证的是游客刷新/页面导航恢复。若必须支持游客关标签，需要改游客 token 的存储策略（与 §20.2 的共享电脑安全取舍冲突），属需拍板项。
6. **C 的断线提示**：用 CDP 网络离线模拟触发 3 次失败；服务端重启用“重启后重新加载页面”验证「比赛已中断」。没有在真实断网/真实杀进程的长时间窗口下观察横幅计时，也没有验证恢复请求与 engine `restore()` 在极慢网络下的竞态。
7. **提交流程提示**：B 提交 `c0f0c58` 之后的 420px 通知抽屉 CSS 修复随 C 提交 `4a5b922` 一起入库（同一 `style.css` 文件，先 B 后 C 无法在文件级拆开）；代码本身已实测 `left=8 / right=397`。
8. **A 的 `grep` 口径**：`grep -Rw loadAnnouncement` 只命中模块；普通 `grep loadAnnouncement` 还会命中 `admin.js` 既有的 `loadAnnouncements`（公告管理，不是重复实现）。管理页的公告管理 id 未改动，但没有在管理员登录态下逐项点公告管理区块。
