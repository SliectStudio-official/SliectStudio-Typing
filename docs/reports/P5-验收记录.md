## 五、新登记：K-19

`public/service-worker.js` 第 1 行 `let CACHE_NAME = 'typing-fallback'` 是模块级回退值，只有 install 才会改成 `typing-<version>`；而第 258/284/304/317 行的运行期写缓存用的就是这个变量。SW 被回收重启后，写入落到 `typing-fallback`，且下一次 activate 会把 `typing-<version>` 当成「旧缓存」删掉——缓存名来回抖动，永远不会因为资源变化而正确轮换。附带一处遗留：`CRITICAL_ASSETS` 第 8 行仍写着 `/loading-indicator.js?v=2`，回退清单会预热一个没人访问的地址。

**有条件通过。** A 组（指纹 + HTML 重写 + 只读端点）19 项里 18 项通过、1 项属我的假设错误，A 组目标达成——客户端一定会因为 URL 变化拿到新资源；B 组实现符合提示词，但「缓存名自动轮换」这一条在现有设计下不可能发生，已登记 K-19，随 P6 把 SW 注册 URL 版本化后收尾。K-13 因此**不算完全闭环**，在坑库标注为「主目标已达成、缓存轮换待 K-19 收尾」。
