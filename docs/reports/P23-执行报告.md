## 2. 验证（§4 十一条）

1. **取窗口**：选手 p1 `progress=118`，正文长 281。计算结果 `start=106, pos=118, end=130`；原文 `before=理解 Token，是走进`、`cursor=' '`、`after=AI 世界的第一步。\n`。页面焦点迷你条为 `…理解 Token，是走进AI 世界的第一步。↵…`（before/after 与 `content.slice` 一致）。
2. **单行不乱**：焦点迷你条 `clientHeight=19`，计算 `lineHeight=16.8px`，`19 ≤ 16.8×1.2=20.16`；外层 `scrollWidth=clientWidth=677`（内层 `.race-mini-clip` 裁剪长文本），未换行。
3. **换行折叠**：窗口右端包含换行时页面文本出现 `↵`（上例 `after` 为 `AI 世界的第一步。↵`），没有产生实际换行。
4. **列表预算**：3 人房页面 `#spec-board .race-mini-line` 数量为 3；代码对每行使用 `i<8 || p===focus` 作为渲染条件，100 人房上限为 8 或 9 条（前 8 + 焦点）。100 人房未在本批重新开房，列入不确定项。
5. **插值**：把焦点选手 `progress` 从 100 推进到 108 后，在 spectator tick 后的 30ms 采样中读到连续窗口变化；共记录 10 个不同窗口，约 300ms 内收敛到目标（例如 `…理解 Tok…` → `…理解 Token…` → `…理解 Token，…`）。只改变显示窗口。
6. **跳跃不慢放**：代码判断 `delta>12` 直接 `setMiniContent(target)`，不建立 `miniAnims` 条目；未单独构造 100→140 的浏览器帧，按代码路径核对。
7. **rAF 单循环**：`startMiniLoop` 使用模块级 `state.miniRaf`，所有选手的动画条目合并到 `state.miniAnims` 后由一个循环推进；循环在条目清空后停止，`stopPolling` / 离开观战会 `cancelAnimationFrame`。
8. **名次不受影响**：迷你条使用独立 DOM 文本；`renderSpectate` 的 `#spec-board` 百分比始终由服务端 `p.progress` 计算，插值函数不写 `progress`。两帧对比中行顺序/百分比文本未随动画节点变化。
9. **完赛/观战中**：p1 完赛（rank=1）后焦点迷你条 `class=race-mini-done`、显示尾段 `…个 Token（词元）。` 且右侧 `已完成 · 第 1 名`，无光标；转为观战席的 `race-board-spectating` 行不创建迷你条。
10. **主题与断点**：`before` 使用 `--ink`，亮/暗对 `--surface-strong` 分别约 **14.73:1 / 10.60:1**；`after` 使用 `--body`，约 **5.27:1 / 5.48:1**；光标 `--primary` 线条约 **3.12:1 / 4.24:1**（均 ≥3）。420 下焦点仍 6/6、列表行迷你条 CSS `display:none`；页面 `scrollWidth=clientWidth`。
11. **正文按需（P22）**：观战者页面迷你条实际使用 P22 的 `state.raceContent` 缓存；P22 tick 仍按 `wantContent` 取一次正文，后续 tick 无正文时迷你条保持缓存内容；缓存为空时显示「正在加载正文…」并设置 `needContent`。
