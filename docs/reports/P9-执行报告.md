## 1. 改了什么

### A 组：K-05 改密/降权即失效（提交 85737ee）

- `db-config.js`：MySQL 与 SQLite 的 `users` 建表 SQL 增加 `token_version`（INT/INTEGER NOT NULL DEFAULT 0）；两分支迁移列表各增加一条 `ALTER TABLE users ADD COLUMN token_version ...`。
- `server.js`：
  - `authMiddleware` 查询增加 `token_version`，比对 `Number(decoded.token_version || 0)` 与库值，不一致 → 401 `登录已失效，请重新登录`。
  - 五处 `jwt.sign` payload 增加 `token_version`：初始化管理员、注册、登录、`PUT /api/auth/me` 两处重签。
  - `PUT /api/user/password`、`PUT /api/auth/me`（带 newPassword 的两条分支）、`PUT /api/admin/users/:id`（改密码或改角色）在业务 SQL 内 `token_version = token_version + 1`；管理员接口密码与角色同时改只自增一次。

### B 组：K-04 成绩上报（提交 dcd8f6a）

- `server.js` `POST /api/leaderboard`：
  - 先解析可选 token 并查用户；登录用户的昵称一律用库中 `nickname`（空则 `username`），忽略客户端值；匿名仍用客户端昵称。
  - `article_id` 有效且 `time_seconds > 0` 时按 `LENGTH(content)`（MySQL `CHAR_LENGTH`）复算理论速度，偏差 >30% 返回 400 `成绩与文章长度不符，已拒绝`，并 `console.warn` 记录 user_id / article_id / 上报值 / 理论值。
  - `article_id` 为空时 `source` 记为 `unverified`。
- `server.js` `GET /api/leaderboard`：非 `?guest=true` 恒加 `s.user_id IS NOT NULL`，不再读 `allow_guest_leaderboard`。
- `db-config.js` `seedData`：不再写入 `allow_guest_leaderboard`（已有行不删不读）。

### C 组：K-20 邮箱留空语义（提交 95d5ac1）

- `public/admin.js`：邮箱 prompt 文案改为 `修改邮箱（留空不修改，输入 - 清空）：`；留空不提交 `email`，输入 `-` 提交 `email:""`，其它提交去空格值。用户名/密码/角色分支未改。

### D 组：版本真值与 schema_version（提交 0e3546b）

- `server.js` 启动段：读根目录 `VERSION` 与 `CONTRACT_VERSION` 并 trim；VERSION 校验 `大版本.小版本.YYMMDD.HHMM`，CONTRACT_VERSION 校验 `v` 加整数；不合法直接抛错退出。不再读 `version.json`（文件保留）。
- `GET /api/version` 返回 `{ version, name, fullName, contractVersion }`，fullName = `Typing-` + VERSION。
- `initDatabase` 末尾：`settings.schema_version` 缺失则写入当前 CONTRACT_VERSION；存在但不一致则抛错，错误信息同时包含库里值与代码值。

## 4. 不确定项

1. **生产库迁移前后 table_info**：迁移前 8 列，迁移后 9 列（token_version），Luca 默认 0；备份为 `tmp/p9-typing-backup-20261106-202153.db`。
2. **复算阈值是否误伤**：只做了合成数据测试（100 字 / 30 秒 / 200 分通过，999 分拒绝）。真实用户的计时口径、标点/换行计数与理论值可能有差异，±30% 是否合适需上线后观察；本次没有真实用户数据可评估。
3. **MySQL 分支未实测**：`CHAR_LENGTH`、`INT NOT NULL DEFAULT 0` 与 MySQL 的 token_version 迁移只做了代码核对，无 MySQL 实例。
4. **VERSION 临时测试**：只临时改过 VERSION 且已逐字节复原（sha256 与改前一致）；CONTRACT_VERSION 未动。
5. **v99 测试环境**：在一次性 `tmp/p9-d-bad` 空库夹具上执行，生产库未置为 v99；生产库当前 schema_version 为 v1。
6. **测试数据**：所有 `__verify_` 账号/成绩/文章都在 tmp 实例；生产库 users=1、articles=3、scores=1，`__verify_` 为 0；tmp 实例已删除。
7. **B 组旧设置行**：生产库仍有 `allow_guest_leaderboard=true`，代码已不再读取；未删除该行。
8. **成绩上报的 token 版本**：`POST /api/leaderboard` 是公开端点，只验签并查用户，不校验 token_version；失效 token 仍可作为登录用户上报昵称（不涉及改密后的受保护接口）。本批未扩大范围。
