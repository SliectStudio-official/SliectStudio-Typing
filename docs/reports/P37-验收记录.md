## 二、必须修的一处（本批引入的新缺陷）

`public/service-worker.js` 第 294 行用了从未声明的变量：

```js
if (NETWORK_ONLY_API.includes(url.pathname) || NETWORK_ONLY_PREFIXES.some((prefix) => url.pathname.indexOf(prefix) === 0)) {
```

整份文件里 `NETWORK_ONLY_PREFIXES` **只出现这一次**，没有任何 `const` / `let` / `var` 定义。

**证据**（我用 CDP attach 到 Service Worker 目标抓到的原文）：

```text
Uncaught ReferenceError: NETWORK_ONLY_PREFIXES is not defined
service-worker.js:294:49  (scriptId 3)
```

**影响**：每个走到这一行的请求（`/style.css`、`/nav.js`、以及除 `/api/articles`、导航、leaderboard 之外的所有请求）都会在 SW 里抛错。Chrome 兜底改成直连网络，所以页面表面还能用，但：

| 后果 | 说明 |
| --- | --- |
| SW 缓存写入与离线兜底全部失效 | 等于装了 SW 但没有离线能力 |
| SW 上下文持续抛未捕获异常 | 排查噪音极大，正好和 K-44 想解决的“别误导”相反 |
| 兼容风险 | 严格按规范的浏览器/未来版本可能直接把请求判为网络错误 |

## 三、一处小问题（不阻塞，但会误导）

横幅文案写「服务已换到 :3000」，实际含义是**探测到 :3000 上有服务**。我这次把服务放在 3198→3199，探测范围写死 3000–3010 找不到 3199，就报了 3000（我本机另一个实例）。真机端口都在 3000–3010 内不会错，但文案应更诚实：**「检测到 :3000 有服务，点此继续（当前 :3198）」**。
