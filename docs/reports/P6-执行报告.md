## 4. 不确定项

1. **为什么不加 CSP**：页面包含大量内联脚本、`onload=` 属性，并依赖 `cdn.jsdelivr.net` 的 Chart.js；本批硬加 CSP 会直接破坏页面。CSP 留到能梳理内联脚本与资源白名单的批次。
2. **`theme-toggle.js` 已复原且哈希一致**：sha256 与改前相同，`cmp` 逐字节一致。
3. **六位以下密码文案**：按 `validatePassword` 定义统一为 `密码至少6位`；`PUT /api/auth/me` 与 `PUT /api/user/password` 原先的 `新密码至少6位` 随之统一。若需保留两套文案，需要让函数支持调用方文案。
4. **Stop SW 的做法**：内置浏览器不支持 `chrome://serviceworker-internals`，改为离开页面 40 秒让 SW 空闲回收，再刷新验证；结果（写缓存仍为 `typing-<当前版本>`、无 `typing-fallback`）符合验收意图。
5. **install 请求计数**：内置浏览器的 Network 面板不暴露 SW 内部请求，使用 `tmp/` 包装脚本在 HTTP 层计数，结果为 1 次；不是 DevTools 面板读数。
6. **Chart.js 画布宽度**：内置浏览器可视区域不可见，canvas CSS 宽度为 0；但 `Chart.getChart` 实例、类型与标签数据均存在，脚本未被响应头阻断。真实浏览器窗口下应正常显示。
7. **Node 版本**：执行机为 v25.3.0，锁定的 22.14.0 未实测。
8. **B 组写库测试环境**：为遵守「不改 `data/` 下库文件」，注册/改密/初始化/删文章均在 `tmp/p6-app/` 空库实例完成；生产库只做只读与浏览器读请求。
