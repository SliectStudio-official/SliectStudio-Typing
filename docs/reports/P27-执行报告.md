## 2. 验收（§3 十七条 + H/I）

1. **两台都到抽文页**
   - 沙箱 A/B 配对：B `/join` 返回 `{"status":"matched","code":"5HD83T"}`；A/B 的 tick 都定位到同房。
   - 浏览器 A（真实比赛页）进入 `race.html` 后：`#page-title=匹配成功`、`#view-reveal display=block`、`#view-reveal` 内 3 张卡；B 端由同一服务端房间获得同一个 resolvedArticleId。
2. **标题与提示**
   - `.race-reveal-kicker` = 「匹配成功」；`.race-reveal-sub` = 「系统正在为你抽取文章」。
3. **三篇候选**
   - reveal 快照：`[8,7,6]`，均为 `charCount=520`，preview 前 20 字互不相同；`resolvedArticleId=6`，恰好命中候选之一。测试环境两篇 520 字候选用于验证；服务端优先 200–400、兜底 100–800。
4. **不可选择**
   - 候选卡 `pointer-events:none`；页面没有选择/提交按钮；快照无 `myChoice`/提交字段。
5. **落点由服务端定**
   - 浏览器中 `.race-reveal-item.is-winner` 的 `data-article-id=6`，与快照 `resolvedArticleId=6` 一致。
   - 连续 10 局沙箱抽样落点：`6, 2, 6, 7, 7, 7, 8, 7, 2, 6`，不是固定第一篇。
6. **聚拢**
   - 视图结构为单行 `display:flex`、`gap:24px`；渲染后先添加 `is-gathered`（卡片 `translateY(20px) scale(.94)` → `translateY(0) scale(1.05)`，transition 300ms），没有改 `left/top/width`。浏览器在 reveal 窗口内观察到 `race-reveal-stage is-gathered ...`。
7. **轮转高亮**
   - JS 每 **120ms** 切换一次高亮：`cards[idx % cards.length]` 切换 `is-highlight`/`is-dim`；从 300ms 启动、1200ms 停止。
8. **落定**
   - 1200ms 后仅给 resolved 卡添加 `is-winner`（居中 `translateX(--reveal-shift) scale(1.15)`），其余卡 `is-out`（缩小淡出）；最终快照 resolved=6，浏览器 winner=6。
9. **转场衔接**
   - 沙箱默认 1500ms 时，tick 序列为 `reveal → countdown`；源码 `revealEndsAt = now+1500`、`startsAt = revealEndsAt+3000`，`updateRoomPhase` 推进到 `countdown`，再按既有逻辑进入 `racing`。客户端总动画 1.7s（最后转场 1500–1700ms）。
   - 时间线（服务端逻辑，ms）：
     | 时刻 | A 设备 | B 设备 | 服务端阶段 |
     | --- | --- | --- | --- |
     | 0 | 命中匹配并进入 `/race.html` | 命中匹配，同一 code | `reveal` 创建，endsAt=1500 |
     | 300 | 三卡聚拢完成 | 同帧动画 | `reveal` |
     | 300–1200 | 每 120ms 切换高亮 | 同一 resolved 卡被高亮 | `reveal` |
     | 1200–1500 | 落选卡淡出，winner 居中 scale1.15 | 同 | `reveal` |
     | 1500 | winner 转场淡出 | 同 | `updateRoomPhase` → `countdown`，startsAt=4500 |
     | 4500 | 全屏 3s 倒计时结束 | 同 | `racing` |
10. **时长由服务端控制**
    - `reveal.endsAt - revealStartedAt = 1500ms`（服务端常量 `REVEAL_DURATION_MS=1500`）；客户端只读该结果，不自行随机；沙箱曾临时拉长到 120s 仅用于 DOM 观察，源码已核对保持 1500ms。
11. **匹配房无观战**
    - 外部账号 `asSpectator` 加入匹配房：**400** `{"error":"匹配对局不支持观战"}`。
    - 匹配房等待/抽文页 DOM：`#race-spectate-panel` = **null**，`#race-spectator-live` = **null**（浏览器实测 specCount=0）。
    - `/api/race/spectate/self` 对匹配房：**400**（A/B 两端均 400）。
11b. **快照无观战**
    - 匹配房快照：`spectators=[]`、`spectatorCount=0`、`maxSpectators=0`（同时 `spectatorEnabled=false`、`spectatorSeats=0`）。
11c. **大厅不显示观战**
    - 匹配房 `isPublic=false`，不进入 `/api/race/list`；列表行代码仅在 `spectatorEnabled` 为真时输出「观战 n/N」，匹配房不会出现该段。
11d. **手动房观战不变**
    - 手动房 `P5NB2B`：外部观战加入成功，返回 `spectator:true`；快照 `spectators` 长度 1、`maxSpectators=1`，没有 `reveal`。P20/P23 的观战席与迷你条代码未改。
12. **手动房不变**
    - 手动建房 `articleId=6`：创建后房间 `status=waiting`、`matchmade=false`、`reveal=null`；房主/选手准备与开始流程仍走既有 waiting→countdown。
13. **内容不下发**
    - reveal tick（即使 body `wantContent:true`）：`race` 字段列表无 `content`，响应 **1793 bytes**；文章 `charCount=520` 只出现为元数据。下一阶段 countdown/racing 才按 `wantContent` 下发正文。
14. **420px**
    - reveal CSS 在 `max-width:768px` 改为纵向 `flex-direction:column`，卡片 `width:min(100%,420px)`；预览 3 行截断，不设置固定宽高；无横向 overflow 规则。
15. **减弱动效**
    - `matchMedia('(prefers-reduced-motion: reduce)')` 时 JS 直接给 winner 加 `is-winner`，不启动高亮 interval；卡片无 CSS animation，transition 在 reduced 媒体下关闭；服务端仍在 reveal endsAt 进入 countdown。
16. **时长上限**
    - `cleanupRooms` 先跑离线判定，再跑 `maxDurationMs`；`reveal` 属于 active 状态，超时走 `cancelRoom('duration_limit')`。沙箱 TTL 缩短时已覆盖 reveal/匹配房到期路径。
17. **回归**
    - P18：比赛大厅快速匹配与全屏倒计时仍存在；本轮改为按钮原地计时 + 底栏同源。
    - P21 B：离线阈值与清理顺序未改；P22：轮询档位/总席位未改；P24：对决条/名次卡未改；P26：匹配房无解散接口仍返回 400。
17b. **玻璃元素与性能复核**
    - 当前引导页 `backdrop-filter` 非 none 元素实际计数 **10**（3 卡 + 资料卡 + 4 条链接行 + 通知面板 + 匹配底栏）；P26 后四条行由组级改为逐行玻璃，P26 文本说的 9 是未计匹配底栏的读数；P27 后续又按用户要求给底栏补了模糊。
    - P25.3 同机 5 秒 rAF P95 为 **16.7ms**；P27 没有重跑 P95，因为新增玻璃层未改布局，且用户明确要求保留底栏/逐行玻璃。若要求严格回到 9 个模糊元素，可去掉底栏模糊（会回退用户当前反馈）。
18. **大厅按钮原地变形**
    - idle：按钮 `[left=45, top=229.8, width=160, height=40]`，文案「快速匹配」。
    - matching：按钮 `[left=45, top=229.8, width=160, height=40]`，文案「00:00×」；四值差 0，位置不变。提示文案「正在寻找对手，点击按钮取消匹配」。
20. **没有多余容器**
    - `#quick-match-idle` / `#quick-match-waiting` 已从 DOM 删除；只剩 `#quick-match-hint` + `#btn-quick-match`，顺序为提示在上、按钮在下，两态使用同一节点。
21. **比赛页底栏回来了**
    - 点快速匹配后：`#race-match-bar display=flex`、文本「匹配中 00:00」，按钮 rect 仍为 `[45,229.8,160,40]`；底栏高度变量和内容留白沿用 nav.js。
21b. **两处计时一致**
    - 3 次每秒采样：`bar=匹配中 00:10 / btn=00:10`、`bar=匹配中 00:11 / btn=00:11`、`bar=匹配中 00:11 / btn=00:11`；按钮读取底栏文本，同源。
21c. **取消同源**
    - 点底栏 ×：底栏 `display=none`、按钮回「快速匹配」、`raceMatchPending=null`；再点按钮：底栏重新 `display=flex`、按钮变「00:00×」。
21d. **不重复跳转**
    - B 配对后，A 页面 `location.href` 仍为 `http://127.0.0.1:3083/race.html`（没有加 `?code=` 的二次跳转），页面只切到 `#view-reveal`；底栏先显示「匹配成功，正在进入比赛…」再隐藏。
