## 三、K-31 结案

坑库 K-31（粘性层高度改了一个、另一层偏移失准）**已修**：三层高度抽成 `--nav-h` / `--subnav-h`，偏移用 `calc()`，断点覆盖各一处。**纪律保留**：以后改导航高度只改变量，不得再写字面量。

## 四、执行方主动上报的一处布局变化（我判定接受）

`profile.html` 旧内联样式里 `nav` 高度 44px、`.sub-nav` 高度各档覆盖，与本批的变量规则冲突。执行方删掉了这些覆盖，于是 **≤480px 时个人中心的导航高度从 44px 变成全局的 52px**。

我核过：现在 `profile.html` 内联的 `nav` 已无 `height`、`.sub-nav` 已无 `height` 与 `top`（只剩 sticky 与 z-index，高度与偏移都走 `style.css`），四页在 ≤480px 下表现一致。**这是"去掉失准的页面级覆盖"，不是新引入的偏差，接受。**

## 五、口径问题（需你知情）

1. **游客关标签页回不到房间**：游客 token 存 `sessionStorage`（共享电脑安全取舍），关标签即丢失。刷新/站内跳转可恢复，**关标签不行**。要支持就得把 token 落 `localStorage`，与既有安全取舍冲突 → 属待拍板项，我没有擅自改口径。
2. **提交流程不干净**：B 提交后的 420px 通知面板 CSS 修复随 C 提交一起入库（同一 `style.css`）。可接受，但回滚粒度受影响。
3. **`9+` 角标与"全部标为已读"按钮未构造大列表验证**：执行方按代码核对；我这边也无法造 10 场以上比赛做视觉确认。
4. **所有交互仍是合成事件**：headless Chrome + CDP，无真人点击、无截图；真实输入法与真实断网未验。
