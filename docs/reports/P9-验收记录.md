## 五、规划侧对生产库的唯一一次写入（必须记录）

**问题**：P9 的 A 组已给生产库加上 `token_version` 列，但 `settings.schema_version` 当时写的是 `v1`；我把代码侧规范版本升到 v2 后，**下次启动会被 D 组的校验直接拒绝**（库里 v1 / 代码 v2）。

**处置**：执行一条 `UPDATE settings SET value='v2' WHERE key='schema_version'`，把登记值对齐到库的真实结构（列已经加上了）。这是唯一一次由规划侧直接写生产库，理由是「不写就起不来」，且只改一行登记值、不动任何业务数据。

**核对**：写入前后 users / articles / scores 计数不变；随后用**生产库副本**跑真实启动，服务正常起来且 `/api/version` 返回 `3.0.261106.2038 / v2`。
