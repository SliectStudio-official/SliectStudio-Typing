# P36-引导页通知条收起（无公告时只留铃铛）

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。**只改引导页**（`public/home.html` / `public/home.js` / `public/style.css` 的 `.home-page` 段）。
> 用户原话：「这里没通知的话就让整个通知条隐藏 只留一个打开通知列表的按钮」

## 0. 现状（我核过）

| 项 | 事实 |
| --- | --- |
| 那条“通知条”其实是顶栏 | `public/home.html` 里的 `header.home-topbar`：`position:fixed; height:48px;` 半透明底 + 下边框，**与有没有公告无关，永远占 48px** |
| 公告条 | `announcement-bar.js` 生成 `#announcement-bar`，`home.js` 的 `mountAnnouncement()` 把它搬进 `#home-announce-slot`；无公告或已关闭时 `display:none` |
| 结果 | 无公告时→ 一条 48px 空黑条 + 右上角一个铃铛（就是截图那个样子） |
| 其它页面 | 练习/比赛/个人中心的公告条不在固定顶栏里，无公告时 `display:none` **不占位**，本来就没问题 |

## 1. 目标两态

| 状态 | 顶栏 | 铃铛 / 登录 |
| --- | --- | --- |
| **有公告** | 保持现状：48px、半透明底、下边框、公告文字在左、可 × 关闭 | 在条内右端（现状） |
| **无公告**（含被 × 关闭、接口失败、初始未加载完） | **收起**：`height:0`、`background:transparent`、`border-bottom:none`、`pointer-events:none`，**不占任何视觉空间** | **悬浮**：`#home-bell`（以及未登录时的 `#home-login`）改为 `position:fixed; top:10px; right:12px`（登录按钮在铃铛左侧 8px），**玻璃底 + 1px 描边**，尺寸沿用现在 28×28 |

## 2. 要求

| # | 要求 |
| --- | --- |
| A1 | 用一个状态类表达两态：`body.home-page.topbar-collapsed`（无公告）与不带该类（有公告）。**只切这个类，不要改 HTML 结构** |
| A2 | **初始态即收起**：页面首帧就是收起态（避免先闪一条空黑条），公告数据到达且有效时再展开 |
| A3 | 展开/收起加 **160ms 过渡**（高度或 transform 任一，**不要用 `display:none` 造成瞬时跳**） |
| A4 | 公告被 × 关闭后**立即转收起态**（`announcement-bar.js` 只是把 `#announcement-bar` 置 `display:none`，你需要在 `home.js` 里监听它的可见性变化或监听关闭按钮，把 `topbar-collapsed` 加上） |
| A5 | `/api/announcement` 返回空或请求失败 → 保持收起态（不要把错误当公告显示） |
| A6 | 通知面板 `#home-notify-panel` 的定位要跟着变：有公告时 `top:58px`（现状），收起时改为基于铃铛的位置（约 `top:46px`），**不允许出现面板悬在半空或压住铃铛** |
| A7 | 登录按钮 `#home-login` 在收起态与铃铛同组悬浮；展开态回到条内（现状） |
| A8 | 收起态下顶栏 `pointer-events:none`，但**铃铛本身必须 `pointer-events:auto`**（否则点不到） |
| A9 | 视差/内容不受影响：`#view-dashboard` 里三卡与资料卡的位置**不因顶栏收起而变化**（顶栏本来就是浮层） |
| A10 | 420px：悬浮按钮不遮挡内容；点击区 ≥28×28（现状 28×28 即可） |
| A11 | **不碰** `announcement-bar.js`、`nav.js`、任何其它页面 |

## 3. 验收（逐条贴读数 + 截图）

| # | 场景 | 判据 |
| --- | --- | --- |
| 1 | **无公告** | 管理面板停用公告后刷新引导页：`#home-topbar` 的 `height=0px`、`background-color` 透明、`border-bottom-width=0`；`document.body.classList` 含 `topbar-collapsed`（贴四个计算值） |
| 2 | 铃铛悬浮 | `#home-bell` 的 `position=fixed`、`top≈10px`、`right≈12px`、尺寸 `28×28`、有背景色与描边（贴计算值 + 截图） |
| 3 | **有公告** | 启用一条公告后刷新：`#home-topbar` 高度 **48px**、有背景与下边框；公告文字可见；铃铛回到条内（贴计算值 + 截图） |
| 4 | × 关闭 | 有公告时点 ×：顶栏**立即收起**（同一帧内 `height` 变 0）、`topbar-collapsed` 出现；刷新后仍收起（localStorage 生效）（贴读数） |
| 5 | 不闪空条 | 3G 节流下抓时间线：首帧顶栏高度 0；公告到达后变 48（贴两个时刻的 `getBoundingClientRect().height`） |
| 6 | 通知面板定位 | 收起态点铃铛：面板可见、`top` 值 ≈46px、**不覆盖铃铛**；展开态点铃铛：`top` ≈58px（各贴计算值） |
| 7 | 登录按钮 | 未登录+无公告：`#home-login` 与铃铛同一水平线、右侧跟随铃铛；未登录+有公告：回到条内（各贴 `top` 值） |
| 8 | 内容不位移 | 切换两态时 `#dash-stage` 里三张卡的 `getBoundingClientRect().top` **不变**（贴两组值） |
| 9 | 420 宽度 | 悬浮铃铛不遮挡三卡；点击区 ≥28×28（贴读数 + 截图） |
| 10 | 其它页面不受影响 | 练习/比赛/个人中心：公告条无公告时 `display:none` 且不占高度（各贴一条） |
| 11 | 回归 | 引导页：视差、三卡入场、匹配入口（含计时）、通知面板打开/关闭 各贴一条读数；控制台 0 错误 |

## 4. 允许改什么 / 不许改什么

| 允许 | 不许 |
| --- | --- |
| `public/home.html`（只加状态类相关，不改结构）、`public/home.js`（公告可见性 → 状态类、面板定位）、`public/style.css` 的 `.home-page` 段 | 改 `announcement-bar.js`、改 `nav.js`、改其它页面、改服务端、改 `VERSION`、引第三方库 |

## 5. 停止点

- 若收起后三卡与资料卡位置发生位移（说明有布局依赖顶栏高度）→ **停**，先报依赖点；
- 若必须改 `announcement-bar.js` 才能知道公告状态 → **停**，先报（我的建议是监听 `#announcement-bar` 的 `display` 变化，用 `MutationObserver`，不要改公共脚本）；
- 若通知面板定位只能靠 JS 硬算导致滚动错位 → **停**，先报方案；
- **不要**顺手加未读角标、红点、消息计数——本批只做收起。
