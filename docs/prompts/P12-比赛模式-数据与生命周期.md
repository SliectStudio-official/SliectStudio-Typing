## 2. 数据（两张新表，一次到位）

在 `db-config.js` 的 **SQLite 与 MySQL 两套建表 SQL 里各加两张表**（用 `CREATE TABLE IF NOT EXISTS`，老库启动时自动建，不需要 ALTER 迁移）：

| 表 | 列 | 说明 |
| --- | --- | --- |
| `races` | `id`、`code` VARCHAR(8) UNIQUE、`cancelled_reason` VARCHAR(20)、`cancelled_by` INT、`password_hash`、`host_user_id` INT、`article_id` INT、`article_title` VARCHAR(200)、`content_snapshot` TEXT、`char_count` INT、`status` VARCHAR(20)、`is_public` TINYINT DEFAULT 1、`max_players` INT DEFAULT 8、`player_count` INT DEFAULT 0、`started_at`、`finished_at`、`created_at` | `code` 唯一；开赛时写 `content_snapshot`/`char_count`/`player_count` |
| `race_participants` | `race_id` INT、`user_id` INT NULL、`nickname` VARCHAR(50)、`is_guest` TINYINT DEFAULT 0、`ready` TINYINT DEFAULT 0、`progress` INT DEFAULT 0、`speed` DOUBLE、`accuracy` DOUBLE、`time_seconds` INT、`rank_no` INT、`finished_at`、`joined_at` | 主键 `(race_id, user_id)` 不行——游客 `user_id` 为 NULL 会撞主键，**改用自增 `id` + 唯一索引 `(race_id, user_id)`（游客走 `guest_id` 唯一索引）**，见下 |

**补充列（游客需要）**：`race_participants.guest_id` VARCHAR(40) NULL，配 `UNIQUE(race_id, guest_id)`。游客行 `user_id` 为 NULL、`guest_id` 有值；登录用户反之。

外键：`race_id` → `races(id) ON DELETE CASCADE`；`user_id` → `users(id) ON DELETE CASCADE`（用户被删则退出比赛）。

## 3. 内存房间注册表

在 `server.js` 顶部（`initDatabase` 之后可用）建一个模块级对象：

```text
const roomRegistry = new Map(); // code -> room
// room = {
//   code, raceId, hostUserId, status, articleId, articleTitle, content, charCount,
//   maxPlayers, isPublic, passwordHash, createdAt, startsAt, finishedAt,
//   players: Map<key, { userId|null, guestId|null, nickname, isGuest, ready,
//                       progress, finishedAt, speed, accuracy, timeSeconds, rank, joinedAt, ip }>
// }
// key = 'u:' + userId  或  'g:' + guestId
```

硬要求：**房间状态只存这里**，数据库只在「建房」与「结束/取消」时写。进度、准备状态、倒计时一律不落库。

## 4. 端点（本批全部实现）

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/race/create` | 登录 | 入参 `{articleId, password, maxPlayers, isPublic}`；返回 `{code}`；同一用户同时只能主持 1 个房间 |
| POST | `/api/race/join` | **公开** | 入参 `{code, password, nickname?}`；登录用户带 token 则用账号身份，否则按游客处理（`nickname` 必填）；返回 `{token, nickname, raceId, state}`；游客拿到的 token 是房间内短期 JWT |
| POST | `/api/race/leave` | 用户或游客 | 房主离开 = 取消房间 |
| POST | `/api/race/ready` | 用户或游客 | 入参 `{ready}`；仅 `waiting` 阶段 |
| POST | `/api/race/kick` | 房主 | 入参 `{targetUserId}` 或 `{targetGuestId}`；不能踢自己；仅 `waiting` |
| POST | `/api/race/start` | 房主 | 全员已准备且 ≥1 人；写正文快照、置 `countdown`、`startsAt = Date.now() + 3000` |
| POST | `/api/race/tick` | 用户或游客 | 入参 `{progress?}`；返回整份快照（形状见 §5）；**一个往返完成「上报进度 + 拉状态」** |
| POST | `/api/race/finish` | 用户或游客 | 入参 `{accuracy}`；**速度由服务端算**：字符数 ÷ (服务端收到时刻 − `startsAt`)；写 `scores` 与 `race_participants`，返回 {`rank`} |
| GET | `/api/race/list` | **公开** | 公开房列表（最多 20 条）：`code`、房主昵称、文章标题/字数、人数/上限、状态；**不含密码** |
| GET | `/api/race/:code` | **公开** | 房间详情（成员昵称、准备状态、状态、人数）；私人房需 `?password=` 或统一返回「房间不存在或密码错误」 |
| GET | `/api/admin/races` | 管理员 | 全部房间列表（**含私人房**，绝不返回密码或 password_hash） |
| POST | `/api/admin/races/:code/cancel` | 管理员 | 强制解散；内存移除 + 库里置 `status='cancelled'`、`cancelled_reason='admin'`、`cancelled_by` 为管理员 id；写 `console.warn` |
| POST | `/api/admin/races/:code/kick` | 管理员 | 踢人：`{userId}` 或 `{guestId}`；比赛中踢出则该玩家判负并移出排名；写 warn |
| GET | `/api/admin/race-settings` | 管理员 | 读 `race_max_rooms`、`race_enabled`（缺失时返回默认 20 / true） |
| PUT | `/api/admin/race-settings` | 管理员 | 改这两个值；`1 ≤ maxRooms ≤ 50`，非法 400「房间数上限必须在 1 到 50 之间」 |

### 4.1 鉴权：新增 `raceAuth` 中间件

规则：

1. 请求头有 Bearer token → 先按普通 JWT 校验；`role==='guest'` 则查 `roomRegistry` 里 `token.raceCode` 房间的 `players` 是否有该 `guestId`，没有则 401「已不在该房间」。
2. 是真实用户时，照常走现有 `authMiddleware` 的数据库校验（含 `token_version` 比对），不要绕开它。
3. 游客 token：载荷 `{ role:'guest', guestId, nickname, raceCode, iat, exp }`，`exp` = 房间创建时间 + 4 小时。**不要**把游客 token 当成登录凭证去访问别的接口——`authMiddleware` 必须继续拒绝 `role==='guest'` 的 token（本批要加这一条判断，防止游客 token 被拿去访问个人中心）。

### 4.2 必做的防刷与约束

| 项 | 规则 |
| --- | --- |
| 房间码 | 6 位，字母表 `ABCDEFGHJKMNPQRSTUVWXYZ23456789`（去掉 I/L/O/0/1）；生成后**内存 + 数据库双查重**，重试至多 10 次 |
| 密码 | 必须 4 位数字，否则 400「房间密码必须是 4 位数字」；库里只存 `bcrypt.hashSync(password, 10)` |
| 加入限流 | 按 `ip|code` 计，5 次失败/10 分钟；失败统一文案「房间不存在或密码错误」 |
| 列表限流 | 按 ip 60 次/分钟（与现有登录限流同一套内存 Map 写法，别引库） |
| 容量 | 房间数 ≥ `race_max_rooms`（默认 20）时建新房返回 400「当前比赛房间已满（20/20）」 |
| 满员 | 人数 ≥ `maxPlayers` → 400「房间已满」 |
| 状态下限 | 非 `waiting` 阶段：加入/准备/踢人 全部 400 |
| 一人一房 | 同一 `userId` / 同一 `guestId` 同时只能在一个房间；重复加入同一房间视为重连（幂等返回快照） |
| 游客防占位 | 同一 ip 在同一房间只能 1 个游客席位；每房游客 ≤ 4 |
| 昵称归一化 | 去首尾空格、连续空格折一、全角转半角、比较时忽略大小写；长度 2~12；命中 `sensitive_words` 打码；**与登录用户重名或房内重名 → 自动加 `(2)(3)…`** 并在响应里回显最终昵称 |

## 6. 生命周期与清理

| 情形 | 处理 |
| --- | --- |
| 建房后 2 小时未开赛 | 标 `cancelled`，从内存移除，库内记一行 |
| 房主断线 | 5 分钟宽限；超时取消房间 |
| 服务端重启 | 启动时把库里 `status='racing'/'countdown'` 的行改为 `'aborted'`（内存态已丢失，宁可明确失败） |
| 全员完赛 / 到时限 | 置 `finished`，回写库 |
| 清理定时器 | `setInterval(…, 30000)` 扫 `roomRegistry`；进程退出时 `clearInterval`（有退出路径，禁止裸 setInterval） |

## 7. 验收口径（全部可复跑，用 `curl` 或 PowerShell `Invoke-RestMethod`）

| # | 场景 | 期望 |
| --- | --- | --- |
| 1 | 登录用户建房 | 200，返回 6 位 `code`；库里 `races` 出现一行 |
| 2 | 第二个登录用户加入（正确密码） | 200，返回 token 与快照；`players` 长度 2 |
| 3 | 密码错 / 房间不存在 | **同一句文案**「房间不存在或密码错误」；连试 6 次 → 第 6 次 429 或 400 |
| 4 | 游客加入（传 nickname） | 200，返回 `role:'guest'` 的 token；`is_guest=1` |
| 5 | 游客取与登录用户相同昵称 | 自动变成 `Luca(2)` 之类，且响应回显该昵称 |
| 6 | 拿游客 token 访问 `/api/auth/me` | **401**（游客 token 不能当登录凭证） |
| 7 | 非全员准备时房主点开始 | 400，提示还有谁没准备 |
| 8 | 全员准备后开始 | 200，`status=countdown`，`startsAt` 比 `serverNow` 大 3000 左右；库里 `content_snapshot` 有正文 |
| 9 | `countdown` 阶段加入 / 准备 | 均 400 |
| 10 | 9 人加入 8 人房 | 第 9 个 400「房间已满」 |
| 11 | `tick` 上报 progress=200 后又报 100 | 快照里 `progress` 仍是 200（只增不减） |
| 12 | `finish` 后查库 | `race_participants` 有 `speed`/`time_seconds`/`rank_no`；`scores` 有一行 `source='race'`（游客为 `'race_guest'`） |
| 13 | 房间数打到 20 后再建房 | 400「当前比赛房间已满」 |
| 14 | 手改库把某房间 `status` 置 `racing` 后重启服务 | 该行变 `aborted`，接口提示比赛已中断 |
| 15 | 并发 8 个循环各调 `tick` 20 次 | 无 500；每人快照只含本房间玩家；服务端日志无异常 |
| 16 | 管理端列表 `GET /api/admin/races` | 普通用户 → **403**；未登录 → **401**；管理员 → 200 且含私人房、**响应里没有任何密码字段** |
| 17 | 管理员解散房间 | 200；参赛者下一次 `tick` ≤1.2s 内拿到 `status='cancelled'`、`cancelledReason='admin'`；库里该行有 `cancelled_reason='admin'` 与 `cancelled_by` |
| 18 | 管理员改上限为 2 后再建第 3 个房间 | 第 3 个 400「当前比赛房间已满（2/2）」；改成 `0` 或 `51` → 400 校验错误 |
| 19 | 管理员关闭 `race_enabled` 后建房 | 400「管理员已暂停创建比赛」；打开后恢复正常 |
| 20 | 回归 | 首页打字、排行榜、个人中心统计、登录/改密（token_version）全部不受影响 |
