> 用户原话：「点击选中了东西就没了 而且就算是只有几行这个窗口也要上下长一点啊 这样很难看 为什么这左上角还有三个点」

## 0. 我在生产页面上量到的现状（1440 视口，SQL 那篇 171 字符）

| 项 | 读数 |
| --- | --- |
| 编辑器整体 | **970 × 240 px**（头部 36px + 内容约 204px） |
| 装饰圆点 | `.code-dot` **3 个**（8×8，纯装饰，无任何功能） |
| ghost 文本 | 171 字符、高度 **152px**（5 行） |
| 底部滚动条 | **常驻**（内容宽度并未超过容器） |

## 1. 三处修复

### A 选中文字后内容看不见（最要紧）

**根因**：输入层是一个 `color: transparent` 的 `textarea`，叠在 ghost 原文之上；用户拖选/双击选中时，**浏览器把选区高亮画在 textarea 自己那层**，正好盖住下面的 ghost 字形——看起来就是「一选中，字全没了」。

| # | 要求 |
| --- | --- |
| A1 | 把输入层的选区改成**低透明度**：`#code-input::selection { background: rgba(124,196,255,.22); color: transparent; }`（`::-moz-selection` 同步）。目标是**透过选区仍能看清 ghost 字形** |
| A2 | 若低透明度在你的浏览器上仍看不清（贴截图说明），改为**自绘选区**：输入层选区背景设完全透明，由 JS 在 ghost 层给选中范围的字符加 `.sel` 类（背景 `rgba(124,196,255,.18)`），并在 `selectionchange`/`keyup`/`mouseup` 时刷新 |
| A3 | 全选（Ctrl+A）与双击选词两种情形都要验：**ghost 文字可见**，不允许出现整块纯色遮住内容 |

### B 编辑器太矮、空白难看

| # | 要求 |
| --- | --- |
| B1 | 内容区高度改**自适应行数**：`min-height: 240px`（约 8 行 × 24px + padding），内容更长时按实际行数增长，**上限 `max-height: 60vh`**（超过则纵向滚动） |
| B2 | 只显示 3–6 行时也要撑满 `min-height`，不允许出现「下面一大块纯黑空白 + 内容挤在左上角」的观感（截图对照） |
| B3 | 行号列与 ghost 的行高必须继续严格对齐（改高度后重测：拿第 1 行与第 5 行的 `getBoundingClientRect().top` 差值 = 4 × lineHeight） |
| B4 | 内容不高时**不要留出多余的可滚动空间**（`scrollHeight` 与 `clientHeight` 差 ≤ 2px） |

### C 去掉左上角三个圆点

| # | 要求 |
| --- | --- |
| C1 | **删除** `.code-dot` 三个 `span`（`code-typing.js` 里那行 `"<span class=\"code-dot\"></span>" ×3`），以及 `style.css` 里对应的 `.code-dot` 规则；头部只留「文件名 + 语言 + 统计」 |
| C2 | 头部左侧间距相应收一点，不要留出空白坑 |

### D 滚动条只在需要时出现

| # | 要求 |
| --- | --- |
| D1 | 横向：`overflow-x: auto`（**不要 `scroll`**），且把内容宽度改成 `max-content` 但**不加额外右侧 padding**；内容不超宽时**不得出现横向滚动条** |
| D2 | 纵向：按 B1 的上限决定；未达上限不出现纵向滚动条 |
| D3 | 验证：171 字符的 SQL 素材（最长行 71 字符）在 1440 视口下**无横向滚动条**（贴 `scrollWidth` 与 `clientWidth`） |

## 4. 停止点

- 若选区在 Chromium 上低透明度方案仍完全遮住 ghost（截图证明）→ 走 A2 自绘选区，**不要**改成「禁用选择」（用户需要能选中复制查看） |
- 若自适应高度会让比赛页布局跳动（例如思考区与排名卡挤压）→ **停**，先报比赛页截图，我决定比赛内是否用固定高度 |
- 若删圆点需要动头部 DOM 结构导致统计对不齐 → **停**，只删 span 与 CSS，不改布局骨架。
