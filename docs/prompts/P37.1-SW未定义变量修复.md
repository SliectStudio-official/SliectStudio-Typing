## 0. 缺陷（我在验收时抓到的原文）

`public/service-worker.js` 第 294 行：

```js
if (NETWORK_ONLY_API.includes(url.pathname) || NETWORK_ONLY_PREFIXES.some((prefix) => url.pathname.indexOf(prefix) === 0)) {
```

整份文件里 `NETWORK_ONLY_PREFIXES` **只出现这 1 次，从未声明**。我用 CDP attach 到 Service Worker 目标，抓到：

```text
Uncaught ReferenceError: NETWORK_ONLY_PREFIXES is not defined
service-worker.js:294:49  (scriptId 3)
```

触发方式：页面被 SW 控制后请求 `/style.css`（任何走到这一行的请求都会抛）。Chrome 会兜底走网络，所以页面表面正常，但 **SW 的缓存写入与离线兜底全部失效**，SW 控制台还会持续报未捕获异常。

## 1. 要改什么

| # | 要求 |
| --- | --- |
| A1 | 在 `NETWORK_ONLY_API` 旁边补前缀数组常量 `NETWORK_ONLY_PREFIXES`，值至少含 `/api/admin/` 与 `/api/user/`；若判断还需 `/api/article/` 也一并加，并在报告里说明理由 |
| A2 | 保持语义：命中前缀的请求**只走网络、不写缓存**，网络失败返回 **503** `{"error":"offline","message":"服务器不可达"}` |
| A3 | 改完 `node --check public/service-worker.js` 必须无输出 |
| A4 | 顺带自检：文件里 `NETWORK_ONLY_PREFIXES` 出现次数必须 ≥ 2（1 定义 + 1 使用）；并把“用了但没定义”的标识符整体查一遍，报告里列出你查过哪些名字 |

## 2. 横幅文案（小问题，一并改）

`public/nav.js` 里端口漂移横幅现在写「服务已换到 :<端口>」。实际含义是**探测到该端口有服务**，而探测范围写死 3000–3010；若当前端口不在范围内（例如部署在 5000），就会指到另一个碰巧在跑的实例上。

| # | 要求 |
| --- | --- |
| B1 | 文案改为：**「检测到 :<探测到的端口> 有服务，点此继续（当前 :<当前端口>）」** |
| B2 | 若探测到的端口与当前端口相同，显示「与服务器的连接已恢复，点此重试」 |
| B3 | 其它行为（点击跳转保留 path/search/hash、找不到端口时的断连文案与「重试」）保持不变 |

## 3. 验收（逐条贴读数，这次要看 SW 自身）

| # | 场景 | 判据 |
