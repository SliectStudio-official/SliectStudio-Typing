# P20-观战席模型（房内选席 + 房主控席 + 容量规则）

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。用户要求：**观战不是加入房间时勾选，而是在房间内选择**；右侧是观战席；房主可设席位数、可自己进入观战席、可决定玩家能否自助进席或由房主指定。
> **本批与 P19 并行**（P19 = 分段吞空格 + /api JSON 404 + 前端兜底 + 匹配底栏）。§5 有明确的分工与冲突规则，先读它再动手。

## 0. 语义与规则（按此实现）

### 0.1 席位是什么

| 概念 | 定义 |
| --- | --- |
| 选手席 | 房间的参赛位，上限 = `maxPlayers`（2–8），**只有选手计成绩** |
| 观战席 | 房间的观众位，容量 = `maxSpectators`，不计成绩，可看导播台 |
| 席位来源 | ① **房内选手转入**（自选或房主指定）② **房外凭码观战加入**（大厅「观战」按钮） |
| 加入房间 | 「加入」= 进选手席，**不再有"以观战身份加入"勾选** |

### 0.2 容量规则（用户口径）

| # | 规则 |
| --- | --- |
| R1 | 观战席容量 **不得超过房间人数的 10%**；**启用时不得低于 1 席** |
| R2 | 计算用房间的**声明人数上限**（`maxPlayers`），不用当前在线人数，避免开赛前人数波动导致席位跳变：`cap = Math.max(1, Math.floor(maxPlayers * 0.1))` |
| R3 | **提醒**：现有房间上限是 8 人 → `floor(0.8)=0` → 夹到 1，**实际恒为 1 席**。若产品上希望 8 人房能有 2 席，需改公式（见 §0.5 待确认项），本批**先按 R2 实现** |
| R4 | 房主设的席位数只能 **1 ≤ seats ≤ cap**；改 `maxPlayers` 时若 cap 变小，超出部分按"最后进席的人先出"退回到选手席（选手席满则拒绝改小并返回 400） |

### 0.3 房主控制

| # | 规则 |
| --- | --- |
| H1 | 房主可开关观战功能（`spectatorEnabled`）；关闭时观战席清空、外部观战加入被拒 |
| H2 | 房主可设席位数（1..cap） |
| H3 | 房主可选模式：`spectatorMode = 'free'`（**玩家可自主进入/退出观战席**）或 `'host'`（**只能房主指定**，玩家自己点无效） |
| H4 | 房主**可以自己进入观战席**；进入后**保留房主权限**（仍可设置、仍可开始比赛），但**自己不计成绩**；退回选手席后恢复 |
| H5 | 换席只允许在 `waiting` 阶段；`countdown` 与 `racing` 阶段一律拒绝（返回 400「比赛已开始，不能换席」） |
| H6 | 若所有选手都进了观战席（选手席为 0 人），开始比赛必须返回 400「没有选手，无法开始」 |

### 0.4 外部观战

| # | 规则 |
| --- | --- |
| E1 | 大厅房间列表每行新增「**观战**」按钮（替代加入表单里的勾选）；点击 = 以观战身份加入（`asSpectator: true`），仍需房间密码 |
| E2 | `spectatorEnabled = false` → 拒绝并提示「本房间未开放观战」 |
| E3 | `spectatorMode = 'host'` → **外部观战一律拒绝**（提示「本房间观战需房主安排」）；`'free'` 时按容量先到先得 |
| E4 | 观战席满 → 400「观战席已满（n/n）」 |

### 0.5 待用户确认（实现按默认，别停）

> 默认 `cap = max(1, floor(maxPlayers × 0.1))`。若用户要"8 人房给 2 席"，改为 `max(1, Math.ceil(maxPlayers × 0.1))` 即可（1 行改动）。**本批按 floor 实现**，并在报告里注明这一条。

## 1. A 组：后端（`server.js` 观战段，约 890–1180 行区域）

### 1.1 房间字段

```
room.spectatorEnabled = true;              // 房主开关
room.spectatorMode = 'free';               // 'free' | 'host'
room.maxPlayers = 2..8                     // 既有
room.maxSpectators = Math.max(1, Math.floor(room.maxPlayers * 0.1));
room.spectatorSeats = room.maxSpectators;  // 房主可下调，1..maxSpectators
room.spectators = new Map();               // 既有：su:<userId> / sg:<guestId>
```

### 1.2 端点

```
POST /api/race/spectate/settings   // 房主，waiting
  body { enabled?: boolean, mode?: 'free'|'host', seats?: number }
  → 200 { success:true, enabled, mode, seats, cap }

POST /api/race/spectate/self       // 房内成员（选手或观战者），waiting
  body { action: 'enter'|'leave' }
  → 200 { success:true, seat:'spectator'|'player', spectatorSeats, spectatorCount }

POST /api/race/spectate/assign     // 房主，waiting
  body { targetType:'user'|'guest', targetId, to:'spectator'|'player' }
  → 200 { success:true, seat, spectatorSeats, spectatorCount }
```

| # | 要求 |
| --- | --- |
| A1 | `POST /api/race/join` 的 `asSpectator` 分支**保留**（供大厅「观战」按钮与大屏观战用），但按 E1–E4 校验；同时**不得**再把它当"加入方式"暴露在表单里 |
| A2 | `self` 进入观战席：`free` 模式玩家可自助；`host` 模式仅房主可自助（其他人 400「观战由房主安排」）；容量满 → 400 |
| A3 | `self` 退出观战席（回到选手席）：选手席有空位才行；否则 400「选手席已满」；房主退出时同样规则 |
| A4 | `assign` 只允许房主；目标必须在房内；`to:'spectator'` 走容量校验；`to:'player'` 走选手席容量校验 |
| A5 | 换席时清掉该玩家的 `ready` 标记（回到选手席为未准备），并在房间广播信息里体现（tick 快照） |
| A6 | 快照 `buildSnapshot` 增加：`spectatorEnabled`、`spectatorMode`、`spectatorSeats`（容量）、`spectatorCount`（既有）、`isHost`（既有）、`mySeat`（`'player'`/`'spectator'`） |
| A7 | `/api/race/tick` 在 `countdown`/`racing` 阶段对换席请求返回 400（H5） |
| A8 | 开局校验：选手数 < 1 时 `/api/race/start` 返回 400「没有选手，无法开始」（H6） |
| A9 | 观战者心跳超时剔除逻辑保持不变；`spectatorSeats` 下调时按"最后进席先出"；不得改数据表 / `VERSION` / `CONTRACT_VERSION` |

## 4. 验收（逐条贴读数）

| # | 场景 | 判据 |
| --- | --- | --- |
| 1 | 加入表单 | 不再有「以观战身份加入」勾选；DOM 中搜不到该文案 |
| 2 | 大厅「观战」按钮 | 点它 → 成为观战者（`mySeat='spectator'`），选手列表不出现自己 |
| 3 | 容量 | 8 人房：房主把席位数设为 2 被拒（cap=1，贴出返回 400 的文案）；设为 1 成功 |
| 4 | 自助进席（free） | 普通玩家点「进入观战席」→ `mySeat` 变 spectator、观战席 n/N +1、选手席 -1、"已准备"分母同步 |
| 5 | 房主进席 | 房主点「进入观战席」→ 自己成为观战者，**仍能看到并操作开始比赛**；点「回到选手席」恢复 |
| 6 | host 模式 | 切到「房主安排」后：普通玩家的「进入观战席」按钮消失；玩家直接调 `/api/race/spectate/self` 返回 400「观战由房主安排」 |
| 7 | 房主指定 | `assign` 把玩家 A 移到观战席、再拉回；两次都改变 `mySeat` 与计数 |
| 8 | 开赛后 | `countdown`/`racing` 阶段调用 `settings`/`self`/`assign` 全部 400「比赛已开始，不能换席」；面板转只读 |
| 9 | 无选手开局 | 全员进观战席后 `/api/race/start` → 400「没有选手，无法开始」 |
| 10 | 观战席位满 | 席位数=1 时第二个人进席 → 400「观战席已满（1/1）」 |
| 11 | 关闭观战 | 房主关掉开关 → 观战席清空、外部观战 400「本房间未开放观战」 |
| 12 | 视觉 | 1280 / 1024 / 768 / 420 四档：两栏/堆叠、无横向溢出；**亮色与暗色两套主题各贴一张对比度读数**（面板文字对比度 ≥ 4.5:1） |
| 13 | 结算 | 观战者结算页只有"以观战身份参与"文案，无名次 |

## 6. 停止点

- 需要给 `races` / `race_participants` 加字段才做得出来 → 停，先报（本设计要求纯内存）；
- 需要改开赛/结算协议 → 停；
- 观战席容量规则与"10% 且不低于 1"无法同时满足（例如 cap 需为 0）→ 按"不低于 1"执行，并在报告里写明。
