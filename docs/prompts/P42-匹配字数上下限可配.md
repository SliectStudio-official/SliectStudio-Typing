# P42-比赛匹配池字数上下限可自定义

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。改 `server.js`（读/校验/过滤）、`public/admin.html`（两个输入框）、`public/admin.js`（读写与提示）。**做完必须重启。**

## 0. 设计四问（先答，再动手）

| 问题 | 回答 |
| --- | --- |
| **怎么分类** | 不是新模块，是既有「比赛设置」的一个扩展项：`settings` 表新增两行 key（`race_article_min_len` / `race_article_max_len`），走已有的 `GET/PUT /api/admin/race-settings`。不新增端点、不新增页面、不改表结构 ⇒ **不升 CONTRACT_VERSION** |
| **怎么设计** | 管理页「普通模式管理 → 比赛设置」加两个数字框（最短/最长字数），默认 **100 / 800**（与现状完全一致）。保存后**立即生效**（每次配对实时读设置，无需重启）。两框下面一行提示「当前范围内：普通文章 N 篇 / 代码素材 M 篇」，让管理员一眼看出池子是不是空的 |
| **怎么做** | 复用 `getRaceSettings()` 的既有写法（读 key → parseInt → 越界回落默认）；配对池过滤把写死的 100 / 800 换成 `settings.articleMinLen / articleMaxLen`；「200–400 字优先」改成与自定义区间求交集，交集为空则不区分优先级 |
| **是否有真实参考** | 有：同一函数里已有 `race_max_rooms / race_max_total_players / race_max_duration_minutes` 三个同构设置项（读、校验、PUT 分支、前端三个 input 全部现成），照抄形状即可；不引入任何新依赖 |

## 1. 起因（用户遇到的真问题）

用户的库里 7 篇 `approved` 文章：

| 文章 | 字数 | 现状 |
| --- | --- | --- |
| 经典诗词（散文） | **72** | 被写死的下限 100 排除 |
| 英文短文 | 245 | 进池 |
| 5 篇代码素材 | 115–176 | 只在「允许匹配代码」时才进池 |

结果普通匹配的池子只有 1 篇 → 永远单卡、永远同一篇。用户要求：**字数上下限可自定义**（只做上下限，不做候选张数）。

## 2. 服务端（`server.js`）

| # | 要求 |
| --- | --- |
| A1 | `getRaceSettings()` 增加读两个 key：`race_article_min_len`、`race_article_max_len`；缺省 **100 / 800**；非法或越界回落默认 |
| A2 | 校验边界：`20 ≤ minLen < maxLen ≤ 2000`；不满足时读取路径回落默认、写入路径返回 400（见 A4） |
| A3 | 返回对象增加字段 `articleMinLen`、`articleMaxLen`（camelCase，与现有一致） |
| A4 | `PUT /api/admin/race-settings` 支持 `articleMinLen` / `articleMaxLen`（兼容下划线写法），校验：整数、20 ≤ v ≤ 2000、且 **min < max**（两个一起提交按组合校验；只提交一个时与当前另一值组合校验）。错误文案：「文章最短字数必须在 20 到 2000 之间」「最短字数必须小于最长字数」 |
| A5 | 配对池过滤（约 1257–1262 行）把 `content.length < 100` 与 `> 800` 换成 `settings.articleMinLen` / `settings.articleMaxLen` |
| A6 | 「200–400 字优先」改为与自定义区间求交集：优先下界 = `max(200, minLen)`，上界 = `min(400, maxLen)`；若下界 > 上界则全部 rank 0（不区分优先级），一行注释说明原因 |
| A7 | `GET` 与 `PUT /api/admin/race-settings` 的响应都追加池子统计 `pool: { normal, code }`：当前范围内 approved 且未下架的普通文章数、当前范围内的代码素材数（两个 COUNT，用当前生效的 min/max） |
| A8 | 不改匹配其它逻辑（队列、最多 3 篇、代码池优先、日志格式不动）；`[匹配] 候选不足 三篇→N 篇` 照旧打印 |

## 6. 停止点

- 若池子统计需要额外索引或明显拖慢配对 → 先报实际耗时（本库文章量级应可忽略）；
- 若 `settings` 的 upsert 在 MySQL 分支不可用 → 复用已有 `setSetting()`，不要自己写 SQL；
- 若保存后提示行不刷新（响应没有 `pool`）→ 停，先报响应原文。
