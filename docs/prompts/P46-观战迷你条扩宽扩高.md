# P46-观战迷你打字条扩宽扩高（窗口按宽度自适应）

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。改 `public/race.js`（窗口计算）+ `public/style.css`（尺寸）。**不用重启。**

## 0. 用户反馈

> 「观战区域的文字是不是可以适当扩宽、扩高一些　现在这样的话效果不好」

截图是导播台「全场实时战况」里那一行迷你打字条，现在显示成 `… html>|<html…`，只有十来个字符、条子又薄又小。

## 1. 根因（已定位）

| 位置 | 现状 | 后果 |
| --- | --- | --- |
| `race.js:1730–1731`（战况列表每行） | `data-mini-front = 6`、`data-mini-back = 6` | 只显示 **光标前 6 字 + 光标 + 后 6 字 = 13 字**，其余靠 `…` 省略 |
| `race.js:1705–1706`（导播焦点条） | 桌面 12/12，≤480px 时 6/6 | 同样偏小 |
| `race.js:1540–1541` | 读取属性的默认值也是 6/6 | 没设置时更短 |
| `style.css:5000–5015 .race-mini-line` | `font-size: 12.5px; line-height: 1.2; padding: 1px 8px` | 条子又薄又小，和旁边 13px 的行文字不协调 |

## 2. 改动要求

### 2.1 JS：窗口按可用宽度算（关键）

| # | 要求 |
| --- | --- |
| A1 | 新增一个纯函数算出前/后字符数，例如 `function miniWindowSize(el, fontSizePx)`：`charW` 取等宽字体经验值（14px 时约 **8.4px**，可用 `fontSizePx * 0.6` 近似），`visible = Math.floor((el.clientWidth - 24) / charW)`；**front = 35%、back = 65%**（前方少、后方多，符合“已经打完的在左、待打的多在右”） |
| A2 | 边界：`visible < 20` 时按 20 算（窄屏至少 20 字）；`el.clientWidth` 为 0 或取不到时回退 front=20 / back=30 |
| A3 | 在**渲染战况列表与左侧导播焦点条的那一刻**计算并写入 `data-mini-front` / `data-mini-back`，**三处写死值全部替换**：战况行 `race.js:1730–1731`（6/6）、左侧焦点条 `race.js:1705–1706`（桌面 12/12、≤480px 6/6）、`applyMiniBars` 兜底 `1540–1541`（6/6）。**左侧焦点条同样必须自适应**（它所在左栏只有约 340px，按宽度算出来约 35–40 字；绝不能再是写死的 12/12） |
| A4 | `applyMiniBars()`（1540 附近）的默认值从 6/6 改为 20/30，作为兜底 |
| A5 | **性能**：`clientWidth` 只在渲染时读一次（不要放进 rAF 每帧读布局）；窗口尺寸变化时已有的重渲染路径会重算，若没有则监听一次 `resize` 重新渲染（仅观战视图可见时） |
| A6 | 不改 `setMiniContent` 的渲染逻辑、`miniWindow` 的切片规则、`…` 的位置规则、追加动画（rAF）行为 |

### 2.2 CSS：把条子放大

| # | 选择器 | 改成 |
| --- | --- | --- |
| B1 | `.race-mini-line`（5000） | `padding: 6px 10px; font-size: 14px; line-height: 1.5; border-radius: 10px; min-height: 32px;`（原来是 1px 8px / 12.5px / 1.2） |
| B2 | `.race-mini-focus`（**左侧「导播焦点」那条，重点改**） | `font-size: 16px; line-height: 1.6; min-height: 38px; padding: 8px 12px;`（比战况条再大一号；左栏只有约 340px 宽，字号大一点才好读） |
| B3 | `.race-mini-caret` | 保持 2px 竖线；随字号放大不要被裁（`vertical-align: middle` 或 `line-height: inherit`） |
| B4 | `.race-board-row .race-mini-line` | 保留 `grid-column: 1 / -1`，补 `margin: 4px 0 2px`，让它占满整行宽度 |
| B5 | ≤480px 的 `.race-board-row .race-mini-line { display: none }`（5033–5035） | **改成显示**（`display: block`），字号 `12.5px`、padding `4px 8px`、`min-height: 26px`；手机上也能看到战况 |
| B6 | 暗色/浅色主题 | 只调尺寸，不改配色变量；不动 `.race-mini-before/after/caret` 的颜色 |

## 3. 验收（逐条贴读数）

| # | 场景 | 判据 |
| --- | --- | --- |
| 1 | 条子占满整行 | 观战（导播台）→「全场实时战况」某选手行：`mini.clientWidth` 与 `row.clientWidth` 相差 **≤ 4px**（贴两个数值） |
| 2 | 高度够 | `mini.getBoundingClientRect().height` **≥ 32**（贴数值） |
| 3 | 字号与行高 | computed `font-size = 14px`、`line-height ≥ 21px`（贴读数） |
| 4 | **可见字符数** | 条内文本（`before + caret + after`）长度在 1440px 宽下 **≥ 30**；连续采 3 次贴数值 |
| 5 | 随宽度自适应 | 把窗口拉到 1900px 宽后重渲染：可见字符数**明显变大**（贴 1440 与 1900 两组数值） |
| 6 | 窄屏 | 375px 宽下：条子仍在（display 不为 none）、可见字符数 **≥ 16**、无横向溢出（`scrollWidth === clientWidth`）（贴读数 + 截图） |
| 7 | **左侧导播焦点条（重点）** | 左上「导播焦点」下的迷你条：computed `font-size = 16px`、高度 **≥ 38**、`clientWidth` 与左栏内容宽度相差 ≤ 4px（贴三个数值 + 截图） |
| 8 | 回归 | 战况行的名次/昵称/进度条/百分比/`观战中` 文本显示正常；点行切换焦点仍生效；选手端比赛页不受影响；控制台 0 错误；`node --check public/race.js` 无输出 |
| 9 | **左侧焦点条窗口自适应** | 左侧焦点条内文本长度（`before + caret + after`）在 1440px 宽下 **≥ 30**；把窗口缩到 1000px 宽后仍 **≥ 20**（证明不是写死的 12/12）（贴两组数值） |

## 5. 停止点

- 若 `clientWidth` 在观战页首次渲染时是 0（视图尚未显示）→ 必须在视图可见后再算一次（或在 `showView('spectate')` 之后触发重渲染），报告里说明你的做法；
- 若放宽窗口后 rAF 动画出现掉帧（每帧重排）→ 停，先报你的测量方式与帧率；
- 若 480px 以下放开显示导致行内文字挤压/换行难看 → 先报截图，我决定是否只在 ≥600px 显示。
