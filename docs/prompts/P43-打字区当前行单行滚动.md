# P43-打字区当前行单行滚动（去掉被裁掉的省略号）

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。改 `public/style.css`（两处）+ `public/typing-engine.js`（当前行跟随滚动）。**不用重启。**

## 0. 用户反馈

> 「为什么会出现省略号　这是什么字符」
> 「保持单行　允许自动滚动　但是只能在这种情况下才滚动　不是整篇文章都单行」

## 1. 根因（已定位）

用户看到的那一行是**正在打的那一段**，末尾的 `…` 不是文章里的字，是 CSS 画出来的：

| 位置 | 现状 | 后果 |
| --- | --- | --- |
| `style.css` 约 879–889 `.typing-line-text` | `white-space: nowrap; overflow: hidden; text-overflow: ellipsis` | **所有段**都单行，超宽就裁掉并画 `…`，用户看不到后半段只能盲打 |
| 约 907 `.char.current` | `border-bottom: 2px solid var(--primary)` | 当前字符的光标，正好落在裁掉的位置，看起来像“省略号加了划线”，容易误解 |

我查过库：8 篇文章**没有任何** `…` 或 `...`，确认这个省略号是渲染产物。

## 2. 要达到的效果（用户口述的原话）

| 段的状态 | 期望 |
| --- | --- |
| **正在打的那一段**（`.typing-page.active`） | **单行**显示，超宽时**自动横向滚动**，让当前字符始终可见；**不要出现省略号** |
| 已完成 / 未开始的段 | **正常换行**（不是单行），完整显示、不滚动、不截断 |

也就是：**只让“当前这一行”滚动，不要整篇文章都变单行。**

## 3. 改动要求

### 3.1 CSS（`public/style.css`）

| # | 选择器 | 改成 |
| --- | --- | --- |
| A1 | `.typing-line-text`（约 879） | 去掉 `nowrap / overflow:hidden / text-overflow:ellipsis`，改为 `white-space: pre-wrap; word-break: break-word; overflow: visible;`（正常换行、完整显示） |
| A2 | 新增 `.typing-page.active .typing-line-text` | `white-space: nowrap; overflow-x: auto; overflow-y: hidden; text-overflow: clip; scroll-behavior: auto;`（单行 + 允许横向滚动，**不画省略号**） |
| A3 | 新增滚动条隐藏（仅活跃行） | `.typing-page.active .typing-line-text::-webkit-scrollbar { height: 0; }` 与 `scrollbar-width: none`，避免出现横条挤占高度 |
| A4 | 不许动 `.code-*` 与 `.race-*` 其它规则；`@media` 里对应的 `.typing-line-text` 字号规则保留 |

### 3.2 JS（`public/typing-engine.js`）

| # | 要求 |
| --- | --- |
| B1 | 每次刷新字符状态后（输入、翻段、初始化），把**当前段**的 `.typing-line-text` 横向滚动到让 `.char.current` **落在可视区中部附近**（用 `scrollLeft` 计算，不要用 `scrollIntoView`，避免整页跳动） |
| B2 | 只滚动 `.typing-page.active` 里的那一个元素；已完成/未开始的段**一律不动** `scrollLeft` |
| B3 | 计算方式建议：目标 = 当前字符 offsetLeft - 容器宽度/2 + 字符宽/2，再 clamp 到 `[0, scrollWidth - clientWidth]` |
| B4 | 输入很快时不要用平滑动画（`scroll-behavior: auto`），避免跟不上光标 |
| B5 | 翻到下一段时，让**新的活跃段**在纵向视口内可见（外层滚动容器用 `scrollIntoView({ block: 'nearest' })` 或等价计算），且不要打断正在输入的焦点 |
| B6 | 不改判定逻辑、不改分段规则、不改 `input` 的取值与事件 |

## 4. 验收（逐条贴读数）

| # | 场景 | 判据 |
| --- | --- | --- |
| 1 | 长句完整显示（活跃段） | 找一篇有 40 字以上长句的文章（如《从计算工具到信息网络：计算机发展史简述》）：活跃段 `.typing-line-text` 的 `scrollWidth > clientWidth`（说明确实是单行溢出），且计算样式 `text-overflow = clip`（贴三值） |
| 2 | 自动滚动跟随 | 连续输入到该段后半段，每输入 10 个字采样一次 `scrollLeft` 与 `.char.current` 相对容器的 left：**当前字符始终落在 [0, clientWidth-10] 区间内**（贴 4 组读数） |
| 3 | 非活跃段不单行 | 已完成段与未开始段的 `.typing-line-text` 计算样式 `white-space = pre-wrap`，且 `scrollWidth === clientWidth`、SCROLLLEFT = 0（贴读数） |
| 4 | 没有省略号 | 页面截图里活跃段末尾**看不到 `…`**；并在 Console 断言 `getComputedStyle(el).textOverflow === 'clip'`（贴值 + 截图） |
| 5 | 翻段不跳页 | 打完一段自动翻到下一段时：新活跃段完整出现在视口内，焦点仍在 `input`（贴 `document.activeElement.className` 与两段的 `getBoundingClientRect().top`） |
| 6 | 比赛页同样生效 | 比赛（普通文章局）达到 30% 以上时，同样的三条读数（`scrollWidth/clientWidth`、`scrollLeft`、`textOverflow`） |
| 7 | 回归 | 练习页普通模式完整打完一篇（结算出现）；代码模式输入框（`.code-editor`）表现不变；控制台 0 错误；`node --check public/typing-engine.js` 无输出 |

## 5. 允许改什么 / 不许改什么

## 6. 停止点

- 若去掉 `nowrap` 后已完成段换行导致页面高度剧烈抖动（活跃段被挤出视口）→ 停，先报两张截图，我决定是否给已完成段加 `max-height`；
- 若 `.char.current` 的 `offsetLeft` 在跨段时取不到（元素被重建）→ 停，先报你的取法；
- 若某些浏览器横向滚动条隐藏不掉（出现横条）→ 报告里写明浏览器版本与实际表现。
