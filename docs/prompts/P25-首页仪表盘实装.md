> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。

## 2. 不许丢掉的东西（本批最大风险）

现在的 `public/index.html` 里有 **73 个 id** 被 `public/script.js` 直接 `getElementById` 使用，覆盖：练习区（`article-select`/`start-btn`/`typing-*`/`stat-*`/`result-*`）、排行榜弹窗（`lb-*`）、登录注册（`auth-*`/`login-*`/`register-*`）、投稿（`submit-article-*`）、历史（`history-*`）、提示（`toast-container`）等。

| # | 要求 |
| --- | --- |
| K1 | **73 个 id 一个都不能少**：仪表盘与练习视图之间切换，练习视图整体放进一个容器（如 `#view-practice`）默认 `display:none`，内部 id 结构原样保留 |
| K2 | 练习视图默认隐藏时，`script.js` 启动**不得报错**：凡依赖元素可见宽高的逻辑（打字区宽度测量、进度条宽度、`measureMaxLen`）必须**延迟到练习视图真正显示之后**再执行；现有代码若在 `DOMContentLoaded` 就测量，必须改成"显示时测量 + 监听 resize" |

## 3. 布局策略：横屏等比缩放，竖屏转垂直列表（用户口径）

> 用户原话：「**首页按比例缩放吧 竖屏才变成垂直列表**」。

### 3.1 判据

| 条件 | 布局 |
| --- | --- |
| **横屏且宽度 ≥ 900px**（`innerWidth >= 900 && innerWidth >= innerHeight`） | **等比缩放画布**：固定 1920×1080 画布，`transform: scale(s)` 后居中，观感与 `design/index.html` 完全一致 |
| **竖屏或宽度 < 900**（`innerHeight > innerWidth` 或 `innerWidth < 900`） | **垂直列表**：不缩放，按 §3.3 单列流式布局 |

### 3.2 缩放实现

| # | 要求 |
| --- | --- |
| Z1 | `s = min(innerWidth / 1920, innerHeight / 1080)`，用 `transform: scale(s)` 等比缩放并居中，窗口内**不出现滚动条** |
| Z2 | 画布内尺寸、字号、间距**一律用设计稿原值（px）**，不要为"响应式"改数值 —— 适配交给缩放 |
| Z3 | 用 `transform`（GPU 合成），**不要用 `zoom`**；图标是内联 SVG，缩放后不糊 |
| Z4 | 缩放层内点击命中必须正常（`transform` 不影响命中）；hover 与点击区域随缩放同步，不得"看得见点不到" |
| Z5 | 监听 `resize` 与 `orientationchange` 重算 `s`，节流 ≤ 每 100ms 一次，不得抖动 |
| Z6 | 横屏但很矮（如 1280×600，`s≈0.55`）**仍按缩放处理**（用户口径），字号偏小属预期；是否加"`s < 0.55` 时改列表"的保险见 §10 |
| Z7 | 背景照片与压暗层随画布缩放，`background-size: cover` 不变形 |

### 3.3 竖屏 / 窄屏的垂直列表

| 视口 | 布局 |
| --- | --- |
| 竖屏且宽度 768–1023 | 三张动作卡改**两列 + 第三张独占一行**；资料卡移到卡片下方、宽度 100% |
| 竖屏 ≤767（含 420） | 全部**单列**；四项统计改 **2×2 网格**；动作卡最小高度 64px |

| # | 要求 |
| --- | --- |
| B1 | 任何断点都不得出现横向滚动条（`scrollWidth <= clientWidth`） |
| B2 | 亮/暗两主题对比度：正文 ≥ 4.5:1，次要说明 ≥ 3:1；背景照片上必须有压暗层保证可读 |
| B3 | 竖屏列表**不再缩放**，字号用常规值（正文 14–16px），可读性优先 |
| B4 | 横竖屏切换（旋转窗口）时布局正确切换，不留残影、不丢点击 |

## 4. 背景照片（保真优先，不用省这点空间）

> 我实测过：`design/assets/bg-photo.jpg` 是 1920×1081 / **1024KB**，用 System.Drawing 重编码后 **q92 → 217KB**、q88 → 168KB。
> 也就是说**高保真只要 200KB 出头**，局域网场景完全不差这点流量。所以本批**不为体积牺牲清晰度**：

| # | 要求 |
| --- | --- |
| G1 | 转换 `design/assets/bg-photo.jpg` → `public/assets/bg-photo.webp`，**质量优先**：目标视觉与原图无可辨差异，**允许 ≤ 400KB**（webp 在同质量下通常比 jpeg 小 25–35%，大概率落在 150–250KB） |
| G2 | 兜底 `public/assets/bg-photo.jpg`（不支持 webp 时用）：**q92 左右，允许 ≤ 350KB**，不要为了小而降质量 |
| G3 | 长边**保持 1920**，不要降到 1600 —— 横屏缩放后大屏显示器上差异可见 |
| G4 | 用 `<picture>` 或 CSS `image-set` 切 webp/jpg；`background-position: center`、`background-size: cover`，不变形 |
| G5 | 放 `public/assets/`，必须被现有静态资源指纹机制覆盖（`?v=` 生效），不得写死缓存时长 |
| G6 | 报告里贴两个文件的实际字节数与编码参数（质量值、是否 webp 有损） |
| G7 | 字体：设计稿用 OPPO Sans 4.0，**不允许下载字体文件**；统一系统回退栈（`system-ui, "Segoe UI", "Microsoft YaHei", sans-serif`），报告贴实际渲染字族 |

## 10. 停止点

- 设计稿里有、但没有数据来源的元素（例如资料卡里的某个图形/等级标记）→ **停**，列出清单让我决定"删掉"还是"后续补数据"；**严禁造数据或写死示例数字**；
- 若把练习视图收进隐藏容器后发现 `script.js` 改动会超过 400 行 → **停**，先报拆分方案（契约 §9 要求超 400 行先报）；
- 若"继续上次的练习"必须精确到"上次打到第几个字"→ **停**，本批只到文章粒度（卡内文档要改的话另批）；
- 横屏极矮窗口（`s < 0.55`，例如 1280×600）会让字号小于 12px：**默认仍按缩放**（用户口径），若你觉得不能接受，我再改成"`s < 0.55` 转列表"的保险 —— 这条等我拍板，别自己加；
- 若 webp 编码工具缺失或只能产出 > 400KB → **停**，先报工具与参数，不要擅自降分辨率。
