# P37-服务端韧性 + 端口漂移守卫（面板托管不再莫名炸掉）

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。本批动 `server.js`（韧性 + 启动自证）与 `public/nav.js` / `public/style.css`（端口漂移横幅）。**做完必须重启。**

## 0. 起因（真实事故）

用户用面板（Sliect Launcher）托管，遇到三件事：

| 现象 | 已查明的成因 |
| --- | --- |
| 面板里启动会“炸掉” | 面板前台捕获输出；管道关闭后 Node 写 `console.log` 抛 **EPIPE**，而 `server.js` 没有 `stdout.on("error")` 兜底、也没有 `uncaughtException` 兜底 → 进程直接退出 |
| 管理页 `Failed to fetch`，但服务器正常 | launcher 会在 3000–3010 里挑空闲端口；**服务换到 3001 后，旧标签页还停在 3000** → 请求打空端口 → 浏览器报 `Failed to fetch` |
| 出问题只能靠猜 | 启动日志没有数据库绝对路径、没有明确“监听在哪”，也没人知道端口被占时跳了号 |

## 1. 服务端韧性（`server.js`）

| # | 要求 |
| --- | --- |
| A1 | 启动最前面就挂 `process.stdout.on("error", noop)` 与 `process.stderr.on("error", noop)`（只吞 `EPIPE`/`ECONNRESET`，其它错误照常打印）。**目标：管道断开时进程不退出** |
| A2 | `process.on("uncaughtException", handler)` 与 `process.on("unhandledRejection", handler)`：打印 `[崩溃兜底]` + 方法/路径（拿不到就写 `-`）+ 错误栈，**追加写** `tmp/server.log`，**不退出进程** |
| A3 | 全局错误中间件 `app.use((err, req, res, next) => …)` 放在所有路由之后：日志里记 `METHOD URL` + 栈，响应 `500 { "error": "服务器内部错误" }`，**不把栈回给浏览器** |
| A4 | `server.on("error")`：遇到 `EADDRINUSE` 打印中文提示（端口号 + 如何查占用进程 `netstat -ano | findstr :<port>` + 如何换端口 `set PORT=3001`）并以退出码 1 退出；其它监听错误打印栈并以 1 退出 |
| A5 | 不吞业务错误：以上只是**兜底**，原有 `try/catch` 与 4xx 行为一格不改 |

| # | 要求 |

| B2 | 端口那行同时打印 `PORT` 环境变量是否被外部指定（是/否），便于排查“为什么会跳到 3001” |

## 3. 端口漂移守卫（`public/nav.js` + `public/style.css`）

`nav.js` 已在 `index.html` / `admin.html` / `race.html` / `profile.html` 引入，本批只改它 + 样式；`home.html` / `setup.html` 不在范围（报告里说明）。

| # | 要求 |
| --- | --- |
| C1 | 每 **15 秒**对同源发一次 `GET /api/version`（`cache: "no-store"`，含 3 秒超时）；连续 2 次失败才认为“断开”，避免偶发抖动误报 |
| C2 | 判定断开后，**依次探测同 host 的 3000–3010**（`http://<host>:<port>/api/version`，每个 1.5 秒超时），找到就停 |
| C3 | 找到新端口：页面顶部出现横幅「**服务已换到 :<新端口>，「点此继续」**」，点击 `location.href` 跳到新端口 + 当前路径 + 当前 hash；横幅不遮挡页面内容（`position: fixed; top:0`，`z-index` 高于导航） |
| C4 | 找不到：横幅文案改为「**与服务器的连接已断开，服务可能已停止**」+ 「重试」按钮（重试 = 重新走 C1/C2） |
| C5 | 恢复正常（探测成功）后横幅自动消失，15 秒轮询继续 |
| C6 | 探测请求**不得**产生后端噪音：`/api/version` 本来就不写日志，确认即可；前端不得 `console.log` 刷屏（只在状态切换时打一次） |
| C7 | 横幅只在“断开/换端口”时出现，正常浏览期间 `display:none`、不占位 |
| C8 | 不引第三方库；用 `fetch` + `AbortController` |

## 4. 验收（逐条贴读数）

| # | 场景 | 判据 |
| --- | --- | --- |
| 1 | 启动自证 | 贴启动日志四行（监听地址 / 数据库文件 / 数据目录 / 页面根目录），路径为绝对路径且真实存在 |
| 2 | 端口占用提示 | 先占住 3000 再启动：出现中文 `EADDRINUSE` 提示（含端口号与查占用命令），进程退出码 **1**（贴输出与 `$LASTEXITCODE`） |
| 3 | **EPIPE 不崩** | 把服务输出接到会提前关闭的管道启动（例如 `node server.js | Select-Object -First 3`），**5 秒后** `curl /api/version` 仍返回 200（贴两条读数） |
| 4 | uncaughtException 兜底 | **临时**在启动后加 `setTimeout(()=>{ throw new Error("selftest"); }, 1500)` 跑一次：进程**不退出**、日志出现 `[崩溃兜底]` 与栈；随后删掉该行（报告里注明未进提交） |
| 5 | unhandledRejection 兜底 | 同上方式临时加 `Promise.reject(new Error("selftest2"))`：进程不退出、日志有记录 |
| 6 | 全局错误中间件 | 临时让某路由 `throw`：浏览器拿到 **500 `{"error":"服务器内部错误"}`**，`tmp/server.log` 里有 `METHOD URL` 与栈，响应体不含栈 |
| 7 | **端口漂移提示** | 服务在 3000 时打开页面 → 把服务换到 3001（占住 3000 起第二份 / 或改 PORT）→ 15–30 秒内页面出现「服务已换到 :3001」横幅；点击后 URL 变 3001 且页面正常（贴横幅文案、跳转前后 URL） |
| 8 | 服务停止提示 | 直接杀掉进程：横幅变「与服务器的连接已断开，服务可能已停止」+「重试」（贴文案）；重新启动后点「重试」横幅消失 |
| 9 | 正常时不打扰 | 正常浏览 30 秒：横幅 `display:none`、`getBoundingClientRect().height = 0`（贴读数） |
| 10 | 回归 | 练习页（普通+代码）、比赛页建房/匹配、个人中心、管理页四个 tab 各贴一条读数；控制台 0 错误 |
| 11 | 语法与版本 | `node --check server.js`、`node --check public/nav.js` 无输出；`set-version.ps1 -Check` 无 WARN |

## 6. 停止点

- 若 15 秒探活会让你觉得“多此一举”，先按 15 秒做，别擅自改成 5 分钟；
- 若探测端口需要跨域头（同 host 不同端口属于**跨源**）→ **停**，先报：这种情况下需要后端给 `/api/version` 加 `Access-Control-Allow-Origin`（同机不同端口），我决定是否放行；
- 若 `uncaughtException` 兜底后发现进程已处于不一致状态（例如 DB 事务未结）→ **停**，先报，我决定是否改为“记录后退出并让面板重启”。
