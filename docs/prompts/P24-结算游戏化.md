# P24-比赛与结算的游戏化（对决条 / 超车提示 / 连击 / 冲刺 / 名次卡）

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。**本批是纯前端**：不改服务端、不改数据表、不加端点、不加依赖。
> 依据 `docs/设计四问模板.md`，四问见 §0.1。

## 0. 用户要什么

> 「比赛过程太干了，只有进度条和百分比。想要打起来有感觉：落后能看见差距、被超过去有提示、连打对了有反馈、快结束有冲刺感、结算页有个像样的名次卡。」

现状（我核过代码）：

| 模块 | 现在有什么 | 缺什么 |
| --- | --- | --- |
| 比赛视图 | 左侧信息列（文章 / 排名 / 我的进度 / 观战席）、右侧打字区、顶部 sub-nav | 没有"我和对手"的对抗感 |
| 名次变化 | 排名列表每 tick 重排，但没有"刚刚被超过"的提示 | 用户感知不到超车 |
| 打字反馈 | 只有光标与进度条 | 连续正确没有任何正反馈 |
| 收尾 | 最后 10% 与前面毫无区别 | 缺少冲刺阶段的紧张感 |
| 结算页 | 一串 `race-result-row` 文本行 | 没有卡片感、没有胜负表达 |

## 0.1 四问（已答）

| 问 | 答 |
| --- | --- |
| **怎么分类** | 纯前端表现层：四个独立小件（对决条 / 超车提示 / 连击 / 冲刺）+ 一块结算重做（名次卡）。**只用快照里已有的字段**：`players[].progress / speed / accuracy / timeSeconds / rank / finishedAt`，加上自己打字引擎的逐字结果 |
| **怎么设计** | 对决条只在 1v1（`players.length === 2`）出现；超车靠"上一次 tick 的 rank 与这一次"求差；连击由前端逐字比对得出，不落库；冲刺是纯阈值（≥90%）；名次卡从结算快照渲染 |
| **怎么做** | 见 §1–§5。动效统一 150–300ms、尊重 `prefers-reduced-motion`、只用主题令牌；**必须容忍 2–3 秒轮询**（P22 后大房是 3 秒一次），不能出现"动画没播完就被下一帧打断" |
| **真实参考** | 搜索不可用，**未取到任何外部原文**。以下均为本项目自定：对决条采用"拔河式双端进度"这一通用形态；超车提示 / 连击 / 冲刺是竞速类产品的常见反馈，但我**没有引用任何具体产品的实现或代码**。若要求出处，只能说没有 |

## 1. A 件：对决条（1v1 专用）

| # | 要求 |
| --- | --- |
| A1 | **只在 `snap.players.length === 2` 时显示**，位置在比赛视图顶部（sub-nav 下方、打字区上方），高度 ≤ 44px；3 人及以上**完全不渲染**（不占位、不留空容器） |
| A2 | 形态：一条水平轨道，**左端是"我"、右端是对手**，两条填充从两端向中间推进；我的填充宽度 = `我的 progress / charCount`，对手同理；中间相遇点位置反映两人进度差 |
| A3 | 轨道上方左对齐我的昵称 + 百分比，右对齐对手昵称 + 百分比；**领先方**用 `--primary` 填充、落后方用 `--muted-soft`（领先方由进度决定，不由身份决定） |
| A4 | 对手完赛（`finishedAt`）后右端显示「已完成」，我的填充继续推进不受影响 |
| A5 | 更新跟随 tick；两次 tick 之间用 ≤300ms 的宽度过渡补齐，禁止突跳 |
| A6 | 观战者视角不渲染对决条（观战台已有 P23 的迷你条与战况列表） |

## 2. B 件：超车提示

| # | 要求 |
| --- | --- |
| B1 | 每次 tick 比较**本人 rank 的上一次值**与当前值：数值变小（名次前进）→ 飘「超过 {昵称}」；变大 → 飘「被 {昵称} 超过」。对象取当前排名表中紧邻自己的那一位 |
| B2 | 位置在打字区正上方居中；样式为一行小胶囊（**不是** toast，不遮挡打字区），**700ms 淡出**；同一时刻只允许 1 条，冷却 **800ms**，超出则丢弃并计数（不排队、不堆积） |
| B3 | 首次进入比赛（`prevRank == null`）**不提示**；tick 失败后重连的第一次 tick **不提示**（避免误报） |
| B4 | 一帧内名次连跳多级只提示**最靠近自己的那一次**（例如连掉 3 名 → 提示"被 X 超过"，X 取紧邻的上一名） |
| B5 | 本人已完赛后不再提示；观战者不提示 |
| B6 | 名次只能来自服务端快照，**不得前端自行排序推断**（与 P22 排名截断保持一致） |

## 3. C 件：连击

| # | 要求 |
| --- | --- |
| C1 | 由打字引擎的逐字结果计算**当前连续正确字数**：正确 +1，错误清零（退格重打也清零）；**只统计本人**，不涉及他人 |
| C2 | 达到 **10 / 25 / 50 / 100** 四个里程碑时，在打字区右上角显示轻量徽标「连击 ×N」并做一次 180ms 放大回弹；未到里程碑时数字静默增长（不闪烁、不做动画） |
| C3 | 打错时徽标**立刻消失**；下一个里程碑可再次触发（每局不限次数） |
| C4 | 连击**不落库、不上报、不参与结算**；刷新页面从 0 开始 |
| C5 | 连击计算**只读**打字引擎状态，不得影响现有正确率统计与错字日志 |

## 4. D 件：冲刺阶段

| # | 要求 |
| --- | --- |
| D1 | 本人 `progress / charCount ≥ 0.9` 且未完成 → 打字区改为 `--primary` 描边 + 右上角出现「冲刺」标签；低于 90% 或已完赛立即撤掉 |
| D2 | 只影响**视觉**（描边、标签），不改文字颜色、不改分段、不影响输入 |
| D3 | 状态变化不做大幅动画（避免最后关头分散注意力），仅 150ms 描边渐入 |
| D4 | 420px 下「冲刺」标签缩为一个小圆点，不换行、不遮挡文字 |

## 5. E 件：结算名次卡

| # | 要求 |
| --- | --- |
| E1 | 结算页由文本行改为**卡片列表**：每人一张卡，卡内固定 5 项 —— 名次（大号数字）/ 昵称 / 速度（整数 字/分）/ 正确率（整数 %）/ 用时（秒，保留 1 位小数）；缺失值显示 `—` |
| E2 | 卡片按名次升序；**本人卡加 `is-me` 描边高亮**并在昵称后加「（你）」；中途退出者（`abandonedPlayers`）在末尾单独一张灰卡「中途退出 · 停在 N 字」 |
| E3 | 1v1 时卡片上方加一句胜负：本人第 1 → 「胜」；本人第 2 → 「负」；本人中途退出 → 「未完成」；同名次 → 「平」。字号明显大于卡片正文；颜色：胜 `--primary`、负 `--muted-soft`、未完成与平 `--body` |
| E4 | 3 人及以上**不加**胜负句，只显示卡片列表 |
| E5 | 观战者结算：不渲染本人卡与胜负句，只显示卡片列表 + 保留现有「你以观战身份参与了本场比赛」 |
| E6 | 卡片入场按名次依次 60ms 间隔淡入，总时长 ≤400ms；`prefers-reduced-motion` 下直接显示 |
| E7 | 旧 `#result-list` 由卡片容器取代；**若其它脚本仍引用该 id，保留一层包裹节点**，报告里写明是否还有引用 |

## 6. 全局约束

| # | 要求 |
| --- | --- |
| F1 | 只用主题令牌（禁写死颜色，K-34）；亮/暗两主题各贴对比度：文字 ≥ 4.5:1、描边与光标 ≥ 3:1 |
| F2 | 动效统一 150–300ms；`@media (prefers-reduced-motion: reduce)` 下**全部取消**（不是缩短） |
| F3 | **必须容忍 2–3 秒轮询**：不得出现两条提示挤在一起、动画未播完被打断、旧提示残缺 |
| F4 | 420px 不出现横向溢出（`scrollWidth <= clientWidth`）；对决条可缩为只有进度条、不显示昵称 |
| F5 | 100 人房：不渲染对决条；超车提示照常但只针对紧邻名次；比赛视图新增 DOM 节点总数 ≤ 12 |
| F6 | 不得改动：P20 观战席面板与换席、P21 退出与解散投票、P22 排名截断与轮询档位、P23 迷你条取窗口逻辑 |
| F7 | 新增样式类统一前缀：对决条 / 超车 / 连击 / 冲刺用 `.race-fx-*`，结算卡用 `.race-result-card` |

## 9. 停止点

- 若实现"连击"必须新增逐字对错上报（服务端字段）→ **停**：本批只允许前端本地计算；
- 若对决条需要快照里没有的数据（例如对手的逐字节奏）→ **停**，先报；
- 若 `#result-list` 仍被其它脚本引用（`script.js` / `nav.js` / admin）→ **停**，先报引用点，不要直接删；
- 1v1 判定必须用**当前 tick** 的 `players.length === 2` 实时算，不要缓存首次值（房内有换席）。
