# P18.2-接口 404 必须是 JSON + 前端非 JSON 兜底

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。用户实测「点快速匹配，公开房间区出现一整段 HTML」引出两个真缺陷，本批只修这两个。

## 0. 现场（用户截图复现）

点「快速匹配」后，「公开房间」区块里直接显示出一段原始 HTML：

```
<!DOCTYPE html><html lang="en"><head><meta charset="utf-8"><title>Error</title></head>
<body><pre>Cannot POST /api/race/match/join</pre></body></html>
```

两个问题叠加：

| # | 缺陷 | 违约依据 |
| --- | --- | --- |
| 1 | 未匹配的 `/api/*` 请求落到 Express 默认 404，返回 **HTML 错误页** | `AGENTS.md` §5：错误响应一律 JSON（`{ "error": "中文文案" }`），**不允许返回 HTML 错误页** |
| 2 | 前端把响应**原文**当内容渲染，用户看到 `<pre>Cannot POST …` | §5「无数据」：失败不许渲染成正常结果；也违反"失败要可见且可读" |

> 说明：本次的根因还有一条与代码无关——线上实例当时仍在跑旧 `server.js`（匹配端点不存在）。重启后端点正常。但**这两个缺陷本身必须修**：以后任何一次改服务端忘记重启、任何一次路径拼错，用户都会再看到 HTML 垃圾。

## 1. A 组：后端补 JSON 404 与 JSON 兜底（`server.js`）

| # | 要求 |
| --- | --- |
| A1 | 在所有路由之后、错误中间件之前，加一个 `/api` 前缀的 404 中间件：`res.status(404).json({ error: '接口不存在：' + req.method + ' ' + req.path })` |
| A2 | 该中间件只作用于 `/api` 开头（静态资源与页面仍返回 HTML，不要动） |
| A3 | 现有错误中间件（`server.js:3126` 一带）补一条：若 `req.path` 以 `/api` 开头且响应尚未发送，强制返回 **JSON**（`res.status(err.status || 500).json({ error: err.message || '服务器内部错误' })`），不得让 Express 默认 HTML 处理器兜底 |
| A4 | 保持既有错误文案与状态码不变（400/401/403/404/500） |
| A5 | 不改任何业务路由的行为 |

A 组验收：

| 场景 | 期望 |
| --- | --- |
| `GET /api/nope` | **404**，`content-type: application/json`，body `{"error":"接口不存在：GET /api/nope"}` |
| `POST /api/race/match/join`（未登录） | **401** JSON「未登录」 |
| `GET /nonexistent.html` | 仍返回 HTML 404（页面行为不变） |
| 触发一个 500（临时让某接口抛错） | 仍 JSON，不是 HTML |

## 2. B 组：前端统一非 JSON 兜底（`public/race.js` + 必要时 `public/nav.js` / `public/script.js`）

| # | 要求 |
| --- | --- |
| B1 | 所有 `fetch` 调接口处，**先判 `content-type` 是否含 `application/json`**：不是 JSON 时**不要 `JSON.parse`、也不要把 body 文本渲染进 DOM**，统一转成错误文案「接口返回异常（HTTP &lt;状态码&gt;），请刷新重试」 |
| B2 | 该文案必须写到**对应区块的错误位**（大厅房间列表区就是 `#public-rooms` 内的错误提示），不得显示原始 HTML、不得显示堆栈 |
| B3 | 已存在的"接口返回 `error` 文案就显示文案"的行为保留 |
| B4 | 抽一个小工具（如 `readJson(res)`）在 `race.js` 内部统一使用，避免每处各写一遍；`nav.js` 的通知/匹配轮询同样改成用它 |
| B5 | 不得吞掉错误：控制台仍要 `console.error` 记一条（含 URL 与状态码） |

B 组验收：

| 场景 | 期望 |
| --- | --- |
| 人为让 `/api/race/match/join` 返回 404 HTML（用未重启的旧实例或临时改成 `Cannot POST`） | 大厅显示「接口返回异常（HTTP 404），请刷新重试」，**页面任何位置都不出现 `<pre>` 或 `Cannot POST`** |
| 让某接口返回 `{"error":"队列已满，请稍后再试"}` | 照旧显示该中文文案 |
| 正常匹配 | 行为不变（底部条照常出现） |

## 3. 允许改什么 / 不许改什么

| 允许 | 不许 |
| --- | --- |
| `server.js`（仅新增 404/JSON 兜底中间件）、`public/race.js`、`public/nav.js`（仅 fetch 兜底） | 改业务端点行为、改页面结构、改数据表、改 `VERSION` / `CONTRACT_VERSION` / `AGENTS.md`、加依赖 |

## 4. 停止点

- 若发现还有别处把响应文本直接塞进 DOM → 一并改（属同一缺陷），但只改接口错误路径；
- 若要动静态资源的 404 行为 → 停，那是页面行为。

## 5. 交付格式

四段式 + `docs/reports/P18.2-执行报告.md`，第一行写本文件 sha256；必须贴：① 四条 A 组 curl 的 `content-type` 与 body 原文；② B 组"非 JSON 兜底"的实测截图或 DOM 读数（证明页面里搜不到 `Cannot POST`）。
