# P23-观战台：看到每个人打到哪了（迷你打字条 + 插值模拟）

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。用户要求：现在的观战台只能看到「进度百分比」，**要看得出每个人正在打到哪一句**。
> 依据 `docs/设计四问模板.md`，四问见 §0.1。**与 P22 协同**：P22 会把文章正文改成按需下发（`wantContent`），观战者也要走这条通道，见 §3。

## 0. 现状（`public/race.js` 的 `renderSpectate`）

| 现在有什么 | 缺什么 |
| --- | --- |
| 焦点选手面板：`进度 42% · 118/281 字` + 速度/正确率/用时 | 看不到**他正在打哪一行、打到哪个字** |
| 战况列表每行：名次 / 昵称 / 进度条 / 百分比 / 速度 | 同上；只能靠百分比想象 |
| 数据源 | 快照里已有 `players[].progress`（**原文绝对字符偏移**）与 `race.content`（正文） |

## 0.1 四问（已答）

| 问 | 答 |
| --- | --- |
| 分类 | 纯前端渲染增强；**不加表、不加端点**（progress 与 content 都已具备）；100 人时受渲染预算约束 |
| 设计 | 用「原文绝对偏移」取光标前后各 N 字的窗口渲染成迷你打字条；两次 tick 间差值 ≤12 时用 rAF 插值"模拟连续打字" |

| 参考 | 无外部原文可引（搜索不可用）。依据通用直播/观赛交互：文字竞速类产品常用"选手当前行 + 光标位置"而非百分比。**本项目自定** |

## 1. A 组：迷你打字条（核心）

### 1.1 取窗口

```
pos   = min(progress, content.length)          // 已输入到原文第几个字符
start = max(0, pos - FRONT)                    // FRONT 默认 12
end   = min(content.length, pos + BACK)        // BACK  默认 12
before = content.slice(start, pos)             // 已打（含换行要折叠成 '↵'）
cursor = content[pos] || ''                    // 光标处的下一个字符
after  = content.slice(pos + 1, end)           // 未打
```

| # | 要求 |
| --- | --- |
| A1 | 渲染成三段：`before`（正常色 `--ink`）、光标（2px 竖线 `--primary`，`animation` 慢闪，`prefers-reduced-motion` 下不闪）、`after`（`--muted-soft`） |
| A2 | 文本必须**单行**：`white-space: nowrap; overflow: hidden; text-overflow: clip`；换行符渲染为 `↵`（不可见字符会让行断掉） |
| A3 | 等宽字体 `--font-mono`，字号 14px（焦点区）/ 12.5px（列表行）；背景 `--surface-strong`、圆角 8px、内边距 4px 8px |
| A4 | 窗口两端的截断要给出提示：`start > 0` 时左侧加省略号 `…`，`end < content.length` 时右侧加 `…` |
| A5 | **不依赖分段**：不要调用 `TypingEngine`，直接用 `content` 切片（观战者屏幕宽度与选手不同） |

### 1.2 放在哪

| # | 要求 |
| --- | --- |
| A6 | **焦点选手面板**（`#spec-focus-*` 那一块）在速度/正确率下方加一行完整迷你条（FRONT/BACK 各 12 字） |
| A7 | **战况列表**每行在进度条**下方**加一行更短的迷你条（FRONT/BACK 各 6 字）；但只给 **前 8 名 + 当前焦点**渲染，其余行保持现状（P22 后 100 人房渲染预算有限） |
| A8 | 已完赛选手：迷你条显示最后一行的结尾并置灰，右侧标注「已完成 · 第 N 名」；已转观战席的选手不渲染迷你条（保持现有「观战中」行） |
| A9 | 比赛未开始（`waiting` / `countdown`）时不渲染迷你条，只显示"尚未开始" |

### 1.3 插值模拟（"模拟每个人打到哪里"）

| # | 要求 |
| --- | --- |
| A10 | 记住每位选手上一帧的 `pos` 与时间戳；当 `0 < 新pos - 旧pos ≤ 12` 时，在 **300ms** 内用 `requestAnimationFrame` 逐字推进（视觉上像在连续打字）；`> 12` 直接跳到新位置（掉线补偿/退避轮询导致的跳跃不要慢放） |
| A11 | 全局只允许**一个** rAF 循环驱动所有迷你条（不要每行一个循环），循环在所有动画结束后自动停止；页面切走/停止轮询时取消 |
| A12 | 插值只影响**显示**，不得回写 `progress`、不得影响排序与名次（名次仍以服务端为准） |
| A13 | 服务器时间与本地时间差不需要补偿；跳跃时不做插值 |

## 2. B 组：样式与可读性

| # | 要求 |
| --- | --- |
| B1 | 新增 `.race-mini-text` / `.race-mini-before` / `.race-mini-caret` / `.race-mini-after` 四个类，**只用主题令牌**（禁写死颜色，K-34） |
| B2 | 亮/暗两套主题各贴对比度：`before` ≥ 4.5:1、`after` ≥ 3:1（次要文本允许低一档）、光标与背景 ≥ 3:1 |
| B3 | 420px：焦点区迷你条允许少显示（FRONT/BACK 各 6 字），列表行迷你条可隐藏；不得横向溢出（`scrollWidth <= clientWidth`） |
| B4 | 列表行高度增加后，左侧面板不得出现双滚动条（外层 `.race-side` 与列表容器只允许一层滚动） |

## 3. 与 P22（正文按需下发）的协同

| # | 要求 |
| --- | --- |
| C1 | P22 之后 `tick` 默认不再带 `content`。**观战者进入观战视图时必须在 tick 请求体里带 `wantContent: true`**（或在首帧会话里要一次），并把 `content` 缓存在内存；缓存缺失时迷你条显示「正在加载正文…」，不得渲染空文本 |
| C2 | 正文只缓存一份（`state.content`），不要每个选手各存一份 |
| C3 | 若 P22 尚未落地（`content` 仍在每次 tick 里），本批逻辑要照样工作（有 content 就用，没有就按 C1 处理） |

## 4. 验收（逐条贴读数）

| # | 场景 | 判据 |
| --- | --- | --- |
| 1 | 取窗口 | 造一个 `progress=118` 的选手：贴出 `start/pos/end` 与渲染出的 `before`/`after` 字符串，证明与 `content.slice` 一致 |
| 2 | 单行不乱 | `#spec-focus` 的迷你条 `scrollWidth <= clientWidth + 1`，且 `clientHeight` 不超过单行行高 ×1.2 |
| 3 | 换行折叠 | 让 `pos` 落在含 `\n` 的位置，迷你条里出现 `↵` 且没有断行 |
| 4 | 列表预算 | 100 人房：带迷你条的行数 **≤ 9**（前 8 + 焦点），其余行无迷你条（贴行数与行内是否有迷你条） |
| 5 | 插值 | 两次 tick `progress` 从 100 → 108（delta=8）：贴出 3 个中间帧读数（如 102/105/108），总时长约 300ms |
| 6 | 跳跃不慢放 | `progress` 100 → 140：下一帧直接显示 140（无中间帧） |
| 7 | rAF 单循环 | 同时有 5 位选手在推进时，`requestAnimationFrame` 回调计数为 **1 条循环**（贴计数） |
| 8 | 名次不受影响 | 插值过程中 `#spec-board` 的排序与百分比文本不因插值变化（贴两帧对比） |
| 9 | 完赛/观战中 | 完赛选手显示置灰尾段 + 「已完成 · 第 N 名」；转观战席选手无迷你条 |
| 10 | 主题与断点 | 亮/暗对比度读数；420px 无横向溢出、列表行迷你条隐藏 |
| 11 | 正文按需（P22 后） | 观战者首帧 tick 请求体含 `wantContent:true` 且响应有 `content`；后续 tick 无 `content` 但迷你条仍正常 |

## 6. 停止点

- 若为拿下 100 人性能必须改服务端（例如让服务端下发"每人当前行"）→ 停，先报方案（默认**不改服务端**）；
- 若 `progress` 在比赛开始前就有非 0 值（异常）→ 停，先报；
- 若要显示"打错的位置"（逐字对错）→ 停：现有数据只有 `accuracy` 汇总，没有逐字对错，属新数据需求。
