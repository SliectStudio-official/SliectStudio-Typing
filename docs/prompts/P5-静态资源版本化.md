# P5-静态资源版本化（K-13）

> 读的提示词就是本文件。开工时把本文件 sha256 算出来，写进执行报告第一行。
> 你是本项目的执行方 AI。开工前读 `AGENTS.md` 的 §0、§4、§5、§7，再读 `docs/CURRENT.md` 五块。
> 本批只做一件事：让前端资源**改了就能到客户端**。这是 P4 验收暴露的问题——旧 Service Worker 缓存让已修好的 `admin.js` 在老浏览器上继续执行旧代码。

## 0. 上一轮不确定项的处理决定

| 不确定项 | 决定 | 理由 |
| --- | --- | --- |
| 版本号体系（待拍板 #1） | 本批**不使用版本号**，改用**内容指纹**：对 `public/` 下的 `.js` / `.css` 算 sha256 短哈希做查询参数 | 版本号体系要等用户文档；指纹方案不依赖版本号，发版自动生效，也不会与将来的版本号冲突 |
| P4 验收发现的「旧缓存跑旧 JS」 | 本批处理，作为唯一目标 | 不修这条，前面所有前端修复都等于没上线 |
| 其余杂项（K-18 / K-16 / K-15 / K-10 / K-11 / K-12 / 安全响应头） | 拆到 P6，不在本批 | 本批改动涉及静态层与 SW，风险面已经够大，不做加法 |
| 跨模块豁免 | 批准本批动 `server.js`（A 组）与 `public/service-worker.js`（B 组），两次提交、各自可回滚 | 静态层的指纹与 SW 的缓存名必须同时对上，拆开下发会留下「HTML 带 ?v= 但 SW 仍用旧缓存名」的坏中间态 |

## 2. 逐项交付

### A 组（先做，单独提交）：服务端资源指纹与 HTML 引用重写

| # | 交付物 | 位置 | 要求 |
| --- | --- | --- | --- |
| A1 | 资源指纹表 | `server.js` 启动段 | 扫描 `public/` 根目录下所有 `.js` 与 `.css`（**排除 `service-worker.js`**，它必须保持稳定 URL），对每个文件取 `sha256` 十六进制前 8 位，得到映射表 `{ '/style.css': 'ab12cd34', ... }`；再把所有哈希按文件名排序拼接后取 sha256 前 12 位作为整体 `assetVersion`。文件不多，启动时同步读一次即可，不要每次请求重算 |
| A2 | HTML 引用重写 | `server.js`，必须在 `express.static` **之前** 注册 | 只处理 `GET` 的 `/`、`/index.html`、`/admin.html`、`/profile.html`、`/setup.html`：读出文件内容，把指向本地资源的 `href="x.css"` 与 `src="y.js"`（含已经带 `?v=2` 这种旧参数的，一律改写成新值）替换成带 `?v=<该文件哈希>` 的形式；其它字节一个不动（不做格式化、不加 meta）。响应头维持现状的 `Cache-Control: public, max-age=0, must-revalidate` |
| A3 | 只读端点 | `server.js` | 新增 `GET /api/asset-version`（匿名，返回 `{ version: assetVersion, files: assetHashes }`）。这是 B 组派生缓存名用的唯一数据源；**不要改 `/api/version`**，也不要往它里面塞字段 |

实现约束：静态资源的 `Cache-Control`（js/css 的 `immutable, max-age=604800`）**保持现状不动**——URL 现在内容变了才变，长缓存才是安全的；不要为了省事把它们改成 `no-cache`，那会回退 `.trae/documents` 里已做过的加载优化。

### B 组（A 组通过后，单独提交）：Service Worker 缓存名派生与旧缓存清理

| # | 交付物 | 位置 | 要求 |
| --- | --- | --- | --- |
| B1 | 缓存名派生 | `public/service-worker.js` 顶部 `const CACHE_NAME = 'typing-practice-v7'` | 改成模块级 `let CACHE_NAME` + 异步获取函数：在 `install` 里 `fetch('/api/asset-version')` 取 `version`，拼成 `'typing-' + version`；取不到（离线首装、服务不可达）时回退 `'typing-fallback'`，**不得让 install 失败**（catch 后继续） |
| B2 | 旧缓存清理 | 同文件 `activate` | 删除所有以 `typing-` 开头但**不等于当前** `CACHE_NAME` 的 cache（现有逻辑是「不等于」全删，改成前缀判断即可）；保留 `skipWaiting` / `clients.claim` 现有行为 |
| B3 | 预缓存列表 | 同文件 `CRITICAL_ASSETS` | 改成从 `/api/asset-version` 的 `files` 生成带 `?v=<hash>` 的地址，外加 `'/index.html'` 本身；获取失败时退回现有列表，不得因为拿不到清单而装不上 |

实现约束：**不许动** IndexedDB 离线文章（`openIDB` / `offlineArticles` / `pendingScores`）、离线回退策略、以及任何 `postMessage` 协议；只改缓存名与预缓存清单这两件事。

## 3. 验收口径

### A 组

| 步骤 | 期望 |
| --- | --- |
| 改动前记录 | `/api/asset-version` 返回 404（新增端点前），便于报告对比 |
| 启动后 `GET /api/asset-version` | 200，`version` 为 12 位十六进制，`files` 覆盖 `public/` 下全部 `.js` / `.css`，**不含 `service-worker.js`** |
| `GET /` 与 `GET /admin.html` 的响应正文 | 所有本地 `.js` / `.css` 引用都带 `?v=<hash>`，且哈希值与 `/api/asset-version` 的 `files` 一一对应；`loading-indicator.js?v=2` 已变成新哈希；`style.css` 的 preload 与 stylesheet 两处都被改写 |
| `GET /style.css?v=<hash>` | 200，`Content-Type: text/css`；`GET /script.js?v=<hash>` 200 `application/javascript`（带参数不影响静态匹配） |
| 临时给 `public/theme-toggle.js` 追加一行注释后重启 | `/api/asset-version` 的 `version` 与该文件哈希都变化，`GET /admin.html` 里该引用同步变化 |
| 复原后重启 | 哈希回到原值，报告贴出「改前 / 改后 / 复原」三组哈希 |
| 浏览器实测（已装 SW） | 打开 `admin.html` → DevTools Network 里 `admin.js?v=<新哈希>` 为 200（不是 from disk cache 的旧地址）；Sources 里看到的是当前代码 |
| 回归 | `/api/version` 仍返回 `version.json` 原内容；三个页面能正常打开、登录后能进管理面板 |

### B 组

| 步骤 | 期望 |
| --- | --- |
| DevTools → Application → Cache Storage | 只存在 **一个** `typing-<version>` 缓存，没有旧的 `typing-practice-v7` |
| 临时改 `public/theme-toggle.js` 后重启并刷新页面 | 出现新名字的 cache，旧名字的 cache 被清掉（贴两张 Cache Storage 截图或列出名字） |
| DevTools 勾 Offline 后刷新 `index.html` | 仍能打开（离线回退未被破坏），控制台无 install/activate 报错 |
| 离线文章功能 | 打开离线文章列表仍能读到缓存内容（IndexedDB 未受影响） |
| 首装失败路径 | 停掉服务后用 `localhost` 打开（或临时把 `/api/asset-version` 改成 500 验证一次）→ SW 仍能 install，缓存名回退为 `typing-fallback` |

无凭据端点用命令行，带登录态的操作在浏览器里做（token 从 `localStorage` 取，凭据不进命令行）：

```powershell
node --check server.js
node --check public/service-worker.js
curl.exe -s http://localhost:3000/api/asset-version
curl.exe -s http://localhost:3000/ | Select-String -Pattern '\.(js|css)(\?v=[0-9a-f]+)?'
curl.exe -sI "http://localhost:3000/style.css?v=00000000"
```

## 4. 停止点

- HTML 重写后页面白屏、样式丢失、或 SW 注册失败 → 立刻停，先把重写范围收回到只处理 `index.html` 再报
- 任何静态资源出现 404 或 `Content-Type` 变化 → 停
- 离线回退或离线文章功能失效 → 停（说明动了不该动的 SW 逻辑）
- 需要改 HTML 源文件、需要构建步骤、需要新依赖 → 停
- 任一验收与期望不符且原因不明

## 5. 交付格式

四段式加执行报告，写进 `docs/reports/P5-执行报告.md`，第一行写 `docs/prompts/P5-静态资源版本化.md` 的 sha256。报告必须含：

1. 改了什么：A / B 两组分开列，`server.js` 写清中间件注册位置（相对 `express.static` 的前后）。
2. 怎么验证：贴 `/api/asset-version` 的实际返回、`/admin.html` 重写后的资源引用片段、三组哈希（改前 / 改后 / 复原）、Cache Storage 的缓存名清单。
3. 怎么回滚：A 组删掉指纹计算与中间件、删 `/api/asset-version` 路由；B 组把 `CACHE_NAME` 与预缓存列表改回 `'typing-practice-v7'` 与静态清单。
4. 不确定项：至少写「`theme-toggle.js` 已复原且逐字节一致」「离线路径未受影响」两条结论。
5. 数据结构与关系清单：预期「无变化」。
6. 上线提示：一句话说明「本次发布后客户端会在一次刷新内换用新资源；如仍异常让用户 Ctrl+F5」。
