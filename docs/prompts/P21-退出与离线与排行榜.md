## 2. B 组：全员离线判定（房间不能永远挂着）

现状：`cleanupRooms()` 每 30 秒一轮，只有三条规则（房主 5 分钟无 tick、waiting 2 小时、racing 超过 `charCount×2` 分钟）。**没有"人都走了"的判定**——一场没打完的比赛要挂到 `charCount×2` 分钟（约 9–10 分钟）。

| # | 要求 |
| --- | --- |
| B1 | `racing`：所有**未完成且未退出**的选手 `now - lastSeen > 60s` → `cancelRoom(room, 'all_disconnected')` |
| B2 | `countdown`：同上，阈值 **30s** |
| B3 | `waiting`：所有选手与房主 `lastSeen > 120s` → `cancelRoom('all_disconnected')`（替代"等满 2 小时"） |
| B4 | 观战者全离线**不触发**（只清席位） |
| B5 | `cancelledReason='all_disconnected'`；前端在下次进入时提示「房间因所有选手离线已结束」 |
| B6 | 三个阈值定义成集中常量并注释理由，禁止散落字面量 |
| B7 | 取消时打**一行**日志（房间码 / 原因 / 离线人数），不得每 30 秒重复刷 |
| B8 | 与既有"房主 5 分钟无心跳"重叠时以 B1–B3 为先（更早触发）；不得同时打两次取消 |

## 4.5 E 组：头像菜单被公告条压住 + 玻璃模糊丢失

### 根因（两条，都在 CSS）

| 现象 | 根因 |
| --- | --- |
| 橙色公告条横穿头像菜单（截图） | `nav` 有 `z-index: 50` 且 `position: sticky`，形成层叠上下文；`.announcement-bar` 是 `z-index: 51`。于是 nav 内部任何弹出层（`.user-menu`=320、`.notify-drawer`=420）都**只能在 nav 的 50 层里比**，被 51 的公告条盖住 |
| 菜单没有毛玻璃 | `.user-menu` 只有 `background: var(--glass-bg)`（95% 不透明），**没有 `backdrop-filter`**；那条 `filter: blur(var(--blur-float))` 只是"关闭态→打开态"的整体模糊动画，打开后是 `blur(0)`，不是背景虚化 |

### 要求

| # | 要求 |
| --- | --- |
| E1 | 统一层级：把 `nav` 提到 **z-index: 60**（高于公告条 51、高于副导航 49）。验收时确认：公告条不覆盖 nav 及其弹出层，且公告条自己仍在副导航下方正常显示 |
| E2 | `.user-menu` 与 `.notify-drawer` 加毛玻璃：`backdrop-filter: blur(14px) saturate(1.2)`（含 `-webkit-` 前缀），背景 alpha 从 0.95 降到 **约 0.72**（否则背后内容不透，看不出模糊）；两套主题分别用对应令牌（亮 `rgba(250,249,245,.72)`、暗 `rgba(30,30,28,.72)`），不要写死颜色值以外的令牌 |
| E3 | 保留关闭态的 `filter: blur(var(--blur-float))` 入场动画；打开态 `blur(0)` 不变 |
| E4 | `prefers-reduced-motion: reduce` 下不加动画，但毛玻璃保留 |
| E5 | 通知面板（`.notify-drawer`）与移动抽屉同样加毛玻璃与层级修正；**移动抽屉与通知面板不得与匹配底栏（z-index 500）打架**：底栏 500、抽屉/通知 420 以内，保持"底栏在最上" |
| E6 | 不改变菜单的尺寸、圆角、内边距与内容结构 |

## 4.6 F 组：比赛数据与胜率显示在头像菜单

### 现状
头像菜单只显示练习三项（练习次数 / 累计字数 / 平均速度），来源 `/api/user/stats`。**没有比赛相关数据**，也没有胜率。

### 端点（新增，只读）

```
GET /api/user/race-stats      // authMiddleware
→ 200 {
    racedCount: 12,        // race_participants 里 user_id=我 的记录数
    finishedCount: 9,      // 其中 races.status='finished' 且 rank_no 非空
    winCount: 3,           // rank_no = 1 的次数
    winRate: 33.3,         // winCount / finishedCount * 100，保留 1 位小数；finishedCount=0 时返回 0
    bestRank: 1,           // 最好名次；无记录时 null
    hostedCount: 4         // races.host_user_id=我 的房间数
  }
```

| # | 要求 |
| --- | --- |
| F1 | 只读聚合，不改表结构与 `CONTRACT_VERSION`；SQL 用 `race_participants JOIN races`，**游客成绩不计**（只看 `user_id` 非空且等于当前用户） |
| F2 | 头像菜单统计区改为两行：第一行「练习」（练习次数 / 累计字数 / 平均速度，沿用现有数据）；第二行「比赛」（**场次 / 胜率 / 最佳名次**）。两行都是 3 格，保持现有格子样式 |
| F3 | 数据懒加载：只在**首次展开菜单**时请求 `/api/user/race-stats`（与现有 `/api/user/stats` 同一时机），一次会话只请求一次；失败时该行显示「—」并 `console.error`，不许显示 0 冒充真实数据 |
| F4 | 展示格式：场次「12 场」，胜率「33.3%」，最佳名次「第 1 名」；无记录时胜率显示「—」、最佳名次「—」 |
| F5 | 菜单高度增加后仍不遮挡页面底部关键操作（`max-height: min(70vh, 520px)` + 内容区滚动） |
| F6 | 两套主题下新增格子与数值对比度 ≥ 4.5:1（沿用 `--surface-strong` / `--ink` / `--muted`） |


## 4.7 G 组：滚动条统一（暗色下的白条）

### 根因

| 现象 | 根因 |
| --- | --- |
| 打字区右侧一条亮白粗滚动条，和暗色界面割裂 | ① `#race-typing { max-height: 62vh; overflow: auto }` 用的是**浏览器默认滚动条**；② 全站在暗色主题下**没有声明 `color-scheme: dark`**，浏览器仍按浅色渲染滚动条、表单控件与下拉箭头 |

### 要求

| # | 要求 |
| --- | --- |
| G1 | 主题声明：`:root { color-scheme: light }`、`[data-theme="dark"] { color-scheme: dark }`（若主题是靠 `data-theme` 切换；若是 class 则同步处理）。这一条同时修好滚动条、输入框、下拉箭头在暗色下的观感 |
| G2 | 新增滚动条令牌：`--scrollbar-size: 8px`、`--scrollbar-thumb: var(--hairline-strong)`、`--scrollbar-thumb-hover: var(--muted-soft)` |

| G4 | `#race-typing` 用更细的一档（**6px**）并只在 hover 时显示滑块（`::-webkit-scrollbar-thumb{background: transparent}`、`#race-typing:hover::-webkit-scrollbar-thumb{background: var(--scrollbar-thumb)}`），保留滚动能力 |
| G5 | 把现有 `.custom-select-dropdown` 的写死滚动条样式合并到 G3 的令牌体系，**全站只留一套定义**；报告里贴出删掉的重复规则行号 |
| G6 | 不改任何容器的 `overflow` 行为与高度（滚不滚、滚多少不变） |
| G7 | 亮/暗两主题各贴读数：`scrollbarColor` / `scrollbarWidth` 计算值、`color-scheme` 计算值、`#race-typing` 的 `scrollHeight` 与 `clientHeight`（证明仍可滚） |

## 4.8 H 组：解散比赛（房主发起 + 多数同意）

### 4.8.1 规则

| # | 规则 |
| --- | --- |
| H1 | **只有房主**可以发起解散；发起前必须有**二次确认**弹窗 |
| H2 | 房间内**选手数少于 3** 时：房主确认后**立即解散**，不走投票 |
| H3 | 房间内**选手数 3 人及以上**时：进入**投票**，需要**超过一半**的人同意才解散 |
| H4 | 票数门槛 `needed = floor(选手数 / 2) + 1`（3 人→2 票、4 人→3 票、5 人→3 票、6 人→4 票、8 人→5 票）；**房主发起即算自己投了同意**，占 1 票 |

| H6 | 投票时限 **30 秒**：到期未达门槛则**自动终止**（不解散），提示「解散投票未通过（x/y）」 |
| H7 | 投票期间**比赛照常进行**（不得暂停倒计时、不得冻结进度）；通过后立即 `cancelRoom(room, "vote_dissolved")` |
| H8 | 投票中有人退出/被移出：门槛按**当前**选手数重算；若人数降到 3 人以下，直接视为通过（走 H2 逻辑） |
| H9 | 房主在投票期间退出或房主身份转移 → 投票**作废**，房间提示「解散投票已取消」 |
| H10 | 同一时间只允许一个投票；重复发起返回当前状态（幂等），**不重置计时** |
| H11 | 房主可**撤回**投票（同样二次确认） |
| H12 | `waiting` / `countdown` / `racing` 都允许发起；`finished` / `cancelled` 一律 400 |

### 4.8.2 端点

```text
POST /api/race/dissolve/start    // 房主（二次确认由前端负责，服务端只认“已确认”请求）
  → 200 { result: "cancelled", reason: "dissolve_direct" }                       // 选手不足 3 人，已直接解散
  → 200 { result: "voting", needed: 3, agreed: 1, total: 5, expiresAt: <ms> }
  → 400 只有房主可以发起解散 / 投票进行中 / 房间已结束

POST /api/race/dissolve/vote     // 房内选手（观战者 403）
  body { agree: true | false }
  → 200 { agreed: 2, needed: 3, total: 5, passed: false, expiresAt: <ms> }
  → 200 { agreed: 3, needed: 3, total: 5, passed: true }                        // 通过即房间已被取消

POST /api/race/dissolve/cancel   // 房主撤回
  → 200 { success: true }
```
