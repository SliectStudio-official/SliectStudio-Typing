# P48-行内错字时输入框显示橙色（不再一律绿色）

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。改 `typing-engine.js`（共用规则 + 比赛页）、`script.js`（练习页）、`style.css`。**不用重启。**

## 0. 用户反馈

> 「如果有错误字符这个绿色的框就变为橙色」

截图：四行文字全红（有错字）、每个输入框都是**绿框**——绿框给人的暗示是「这行搞定了」，与实际（全是错的）矛盾。

## 1. 根因（这是 P47 带出来的，我的口径没写全）

P47 把 `completed` 类从「当前行全对才前进」改成「**该行填满**」，于是：

| 现状 | 问题 |
| --- | --- |
| `.typing-line-input.completed` 只看「长度达到段长」 | 用空格或错字填满一行也会变绿 |
| 我实测复现 | 第 1 行（段长 39）用 39 个空格填满 → class 为 `typing-line-input completed`、边框 `rgb(72,168,104)`（绿）、而 `.char.wrong = 32` |

## 2. 目标：行状态三档

| 状态 | 条件 | 输入框表现 |
| --- | --- | --- |
| **completed（绿）** | 该行**填满且全部正确**（`value.length >= 段长` 且 `wrong === 0`） | 沿用现有绿色（`border-color: var(--semantic-success)` + 浅绿底） |
| **has-error（橙，新增）** | 该行**存在错字**（`wrong > 0`），不管有没有填满 | `border-color: var(--semantic-warning); background: rgba(245, 158, 11, 0.07);` |
| 默认（无特色） | 未填满且无错字 | 保持现在的灰边 |

优先级：**has-error 高于 completed**（一行既填满又有错字时显示橙色，不能显示绿色），且该行不能同时带这两个类。

## 3. 实现要求

| # | 要求 |
| --- | --- |
| A1 | 在 `typing-engine.js` 的 `lineRules` 里加纯函数 `lineStatus(value, segment, wrongCount)`，返回 `completed` / `has-error` / `pending`（**规则单一来源**，练习页必须复用） |
| A2 | 比赛页 `syncLine`（约 426 行）改为用 `lineStatus` 切换两个类：先移除 `completed` 与 `has-error`，再按返回值加一个 |
| A3 | 练习页 `script.js` 的 `syncSegmentLine`（约 997 行附近）同样改用 `lineStatus`，与比赛页逐条一致 |
| A4 | `wrong` 的取法：比赛页取当前行 `charStates` 中该段区间内 `wrong` 的个数；练习页按 `segmentOffsets` 取该段区间。**只算本行，不要每次按键全篇重算** |
| A5 | `style.css` 新增 `.typing-line-input.has-error` 与 `.typing-line-input.has-error:focus`（聚焦时保留主色焦点环，但边框仍是警示色），并确认 `.typing-line-input.completed` 不被覆盖 |
| A6 | 不改「填满自动跳行」「退格回跳」「所有行填满才完成」「正确率公式」 |

## 4. 验收（练习页与比赛页各跑一遍，逐条贴读数）

| # | 场景 | 判据 |
| --- | --- | --- |
| 1 | **错字填满**（用空格把一行填满） | 该 input 的 `classList` 含 `has-error`、**不含** `completed`；computed `border-top-color` 为警示色（把 `--semantic-warning` 的实际 rgb 数值贴出来） |
| 2 | **全对填满** | `classList` 含 `completed`、不含 `has-error`；边框回到绿色 |
| 3 | **未满但有错字**（打 5 个字其中 1 个错） | 有 `has-error`、边框橙色 |
| 4 | **改正后仍未满** | `has-error` 消失、边框回默认灰 |
| 5 | **改正后填满** | 转 `completed` 绿色 |
| 6 | 聚焦表现 | 错字行获得焦点时：边框仍警示色、外层焦点环仍主色（贴 `box-shadow` 与 `border-top-color`） |
| 7 | 比赛页 | 同样的 1–3 条读数（用 `#race-typing` 前缀取值） |
| 8 | 回归 | 填满自动跳行、行首退格回跳、全满结算、正确率、代码模式 均不变；`node --check` 三个文件无输出；控制台 0 错误 |

## 6. 停止点

- 若 `--semantic-warning` 与 completed 的绿色在深色主题下区分度不够（截图看不清）→ 停，先给两张截图，我决定是否改用 `--semantic-error`（红）；
- 若按行统计 wrong 必须全篇扫描（性能顾虑）→ 必须只扫本行，做不到就停并报方案；
- 若三档状态导致自动跳行后新焦点行看着像「没完成」→ 报告里说明并附截图，我决定是否加额外的聚焦样式。
