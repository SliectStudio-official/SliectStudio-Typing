# P15-公告全站化、通知中心与比赛重连

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。三组分开提交：A 公告收口、B 通知中心、C 比赛重连。**别顺手动别的东西。**
> **修订 v3（2026-11-08）**：按用户要求，公告一律**沿用首页的形态**——复用首页样式、**常驻不随页面滚动**、三页位置与外观一致。v2 里"改成静态随滚动"的方案**作废**。

## 0. 现状与目标

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 公告 | `index.html` 用 `style.css` 的样式（DOM 顺序 site-nav → sub-nav → 公告）；`profile.html` 另有一份内联样式；`race.html` 由 `announcement-bar.js` 插入，但**插在了 site-nav 之后、sub-nav 之前** | 三页统一：样式只在 `style.css`、DOM 顺序固定为 `nav → sub-nav → 公告`、**sticky 常驻**、管理页不显示 |
| 通知 | 只有顶部公告条，没有「我的通知」；离开后比赛结果看不到 | 头像菜单里加「通知中心」，列出公告 + 我的比赛结果 + 未读角标 |
| 比赛重连 | 刷新或断线后要重新输房间码；座位与进度在服务端，客户端却回不去 | 自动回到原房间继续，支持 `race.html?code=XXX` 直达 |

## 1. A 组：公告统一到首页形态（只动前端）

### A0 必须修的三个缺陷

用户实测：比赛页公告条被副导航压住、只露半截。三处原因：

| # | 缺陷 | 证据 |
| --- | --- | --- |
| A0-a | **插入位置错**：`announcement-bar.js` 把公告插在 `#site-nav` 之后，而首页是插在 `.sub-nav` **之后** | 首页 DOM：`site-nav → sub-nav → announcement-bar`；比赛页：`site-nav → 公告 → sub-nav` |
| A0-b | **偏移写死且已失准**：`style.css` 里 `.announcement-bar { position: sticky; top: 74px; z-index: 48 }`，其中 74 = 44 + **30**，是副导航还是 30px 时的值；P11 把副导航改成 56px 后正确值应为 100px | `style.css:2636-2653` |
| A0-c | **层级低于副导航**：公告 `z-index: 48` < 副导航 `49`，一旦重叠就被彻底盖住；且 `profile.html` 内联了同名样式（同样 74/48），三处定义各不相同 | `style.css` 与 `profile.html:29-33` |

### A0 修法（按此实现，不要自创）

| # | 要求 |
| --- | --- |
| A0-1 | 公告**保持 sticky 常驻**（不随页面滚动消失），与首页一致 |
| A0-2 | 把三层高度抽成 CSS 变量并在断点覆盖：`:root { --nav-h: 44px; --subnav-h: 56px }`，公告用 `top: calc(var(--nav-h) + var(--subnav-h))`、`z-index: 51`；断点覆盖：≤768px 时 `--nav-h:56px; --subnav-h:52px`，≤480px 时 `--nav-h:52px; --subnav-h:48px`（与现有 `nav` / `.sub-nav` 的实际高度一致，改高度时同步改变量） |
| A0-3 | 插入位置改为 `.sub-nav` **之后**（页面无 `.sub-nav` 时插在主导航之后）；三个页面顺序必须一致 |
| A0-4 | 删除 `profile.html` 内联的 `.announcement-bar / .announcement-close / .announcement-level-badge` 样式，`style.css` 只保留一份定义 |
| A0-5 | 公告条宽度 100%，不得因为 sticky 造成横向滚动或遮住内容首屏（必要时给后续内容加等高的 margin 或让 sticky 元素不脱离文档流占位） |

### A1–A5 迁移到单点模块

| # | 要求 |
| --- | --- |
| A1 | `index.html` 删除内联的公告标记，改为引入 `announcement-bar.js`（放 `nav.js` 之后、页面脚本之前）；同时删除 `script.js` 里重复的公告逻辑：五个 `announcement*` 常量、`loadAnnouncement` 函数、`setInterval(loadAnnouncement, 60000)`、初始化处调用 |
| A2 | `profile.html` 同样迁移：删标记、删 `profile.js` 公告逻辑、引入模块 |
| A3 | `admin.html` **不引入**（它有「公告管理」区块），其 `announcement-list` 等 id 不得受影响 |
| A4 | 行为与首页一致：关闭按公告 id 记 `localStorage`（`announcement_closed_<id>`）；`allow_close=0` 时不显示关闭按钮；等级配色沿用 `level-notification / site-wide / warning`；60 秒刷新一次 |
| A5 | 模块不得注入 `.announcement-bar` 内联样式（`style.css` 已有） |

### A 组验收

| 项 | 期望 |
| --- | --- |
| 内容 | 三页公告内容与 `/api/announcement` 一致 |
| 管理页 | `admin.html` 没有公告条 |
| 关闭记忆 | 关闭后刷新不再出现（同一 localStorage 键） |
| 单一实现 | 全仓 `grep loadAnnouncement` 只命中 `announcement-bar.js` |
| 样式唯一 | HTML 里 `.announcement-bar` 0 命中；`style.css` 只有 1 处定义 |
| **DOM 顺序** | 三页公告条的 `previousElementSibling` 都是 `.sub-nav` |
| **常驻** | 向下滚动 1000px 后，公告条仍在副导航下方、完整可见、可点关闭；不压住正文首屏 |
| **五档断点** | 1920 / 1440 / 1200 / 900 / 420：公告条与副导航**无重叠**、文字不溢出、关闭按钮不被裁切 |
| **无重复** | 同一页面只有一条公告条（不得出现静态标记 + 模块各一条） |

## 2. B 组：通知中心（后端 1 个只读端点 + 头像菜单面板）

### 2.1 端点

```
GET /api/notifications?limit=20      // 需要登录
→ 200 {
    items: [
      { id: "announcement:13", type: "announcement", title: "试运行公告", body: "…", time: "2026-05-23 21:32:45", link: null },
      { id: "race:ABC123", type: "race", title: "比赛 ABC123 已结束",
        body: "你第 2 名 / 共 5 人 · 281 字 · 62 字/分 · 90%", time: "2026-11-08 21:03:11", link: "race.html?code=ABC123" }
    ]
  }
```

| 规则 | 说明 |
| --- | --- |
| 公告 | 复用 `getActiveAnnouncement()`，最多 1 条 |
| 比赛结果 | `race_participants` JOIN `races`，只取 `user_id = 当前用户` 且 `races.status IN ('finished','aborted')`，按 `finished_at` 倒序最多 10 条 |
| 排序 | 两类合并后按 `time` 倒序 |
| 已读 | **服务端不存**，前端用 `localStorage` 记已读 id（上限 200 条，超出丢最旧）——本批不新增表 |
| 游客 | 未登录调该端点 → 401；菜单里只显示公告 + 一行「注册后可保留比赛记录」 |

### 2.2 前端

| # | 要求 |
| --- | --- |
| B1 | 头像菜单新增「通知中心」入口，右侧显示未读角标（>9 显示 `9+`），无未读时不显示 |
| B2 | 点击展开通知面板（菜单内展开或右侧抽屉，自选，移动端不得溢出）；每项显示标题、正文一行、时间；有 `link` 的可跳转 |
| B3 | 展开即标记已读并归零角标；提供「全部标为已读」 |
| B4 | 角标在页面加载后拉一次（仅登录态），不要跟着 1.2s 轮询；最多 60 秒刷新一次 |
| B5 | 空态写「暂时没有通知」；失败显示接口 `error` 文案；不许渲染成空白 |

B 组验收：造 2 场已完成比赛 → 角标显示 2 → 展开后归零且刷新仍已读 → 点比赛通知跳到 `race.html?code=…`；未登录时只有公告且不报错。

## 3. C 组：选手重连（后端 1 个只读端点 + 前端恢复逻辑）

### 3.1 端点

```
GET /api/race/active
  鉴权：用户 token 或 游客 token 都可（沿用 raceAuth 的判定，但**不能因为找不到房间就 401**）
→ 200 { code: "ABC123", state: <buildSnapshot 结构>, isSpectator: false }
→ 200 { code: null }            // 当前不在任何房间
```

查找顺序：先按 `req.user.id` 找选手席位，再找观战席位；游客按 token 里的 `raceCode` 与 `guestId` 找。找到时把快照一起返回，省一次 tick。

### 3.2 前端

| # | 要求 |
| --- | --- |
| C1 | `race.html?code=ABC123` 只用于「我已经在这个房间里」的直达；不在房间内则提示「请用房间码和密码加入」，不要偷偷猜密码 |
| C2 | 加载时：有 `localStorage.token` → 调 `/api/race/active` → 有 code 就 `enterRoom(code)` 并提示「已恢复上次的比赛」；游客从 `sessionStorage` 的 `raceToken:<CODE>` 与 `lastRaceCode` 恢复 |
| C3 | 轮询连续 **3 次**失败才提示「连接中断，正在重试…」，期间保留界面与已输入内容；恢复后继续（进度以服务端为准） |
| C4 | 每次成功 tick 写 `localStorage.lastRaceCode`；离开房间或比赛结束后清掉，避免下次误恢复 |
| C5 | 不改房间生命周期：房主 5 分钟无心跳取消、2 小时未开赛取消、重启标 `aborted` 全部保持 |

C 组验收：比赛中刷新 → 自动回房且进度不丢（贴刷新前后 `me.progress`）；关标签页 30 秒再开 → 仍能回房；赛后刷新 → 落在大厅且不误恢复；游客同理；把服务端杀掉再起 → 提示「比赛已中断」而不是白屏。

## 5. 停止点

- 通知要求新表 → 停（本设计零新表，已读状态放前端）；
- 重连需要改房间生命周期 → 停，先报；
- A 组迁移后发现首页还有其它代码依赖公告的 id/变量 → 停，把依赖点列出来；
- **改 `nav` / `.sub-nav` 高度** → 停，这属于布局变更，需先报（否则 A0-2 的变量又要跟着改）。
