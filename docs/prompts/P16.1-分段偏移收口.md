# P16.1-分段偏移收口（首页进度与错字/朗读索引）

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。**只做一件事**：让分段结果带上「这段在原文的哪个位置」，把首页进度与错字/朗读索引改回按原文坐标算。
> 来源：P16 验收发现的两处回归（`docs/reports/P16-验收记录.md` 第三节）。

## 0. 缺陷与根因

| 缺陷 | 现状 | 根因 |
| --- | --- | --- |
| 首页进度最多 96.09% | 281 字文章分段后拼接只剩 270 字（9 个 `\n` 被 trim），`script.js:821` 分母仍是 `originalText.length=281` | 分段**丢掉了每段在原文中的起止位置** |
| 错字记录位置偏移 | `script.js:631 getSegmentStartOffset()` 用 `segments[i].length` 累加 | 同上 |
| 朗读高亮跳字 | `getCurrentWord(globalPos)` 的 `globalPos` 来自上面的错误偏移 | 同上 |
| 比赛页进度显示最多 ~96% | `typing-engine.js:211 offsetOf()` 同样累加 | 同上（完赛时服务端会置满，但比赛中显示不满） |

**不要改分母、不要改计分公式、不要改分段规则**——只把偏移换成真实的原文下标。

## 1. A 组：引擎导出带偏移的分段（`public/typing-engine.js`）

| # | 要求 |
| --- | --- |
| A1 | 新增导出 `window.TypingEngine.splitTextWithOffsets(text, maxLen)` → `{ segments: string[], offsets: number[] }`；`offsets[i]` = 第 i 段第一个字符在**原文**中的下标 |
| A2 | `offsets` 必须跳过被 trim 掉的空白：若段与段之间原本有 `\n` 或空格，`offsets[i+1] >= offsets[i] + segments[i].length`，差值等于被跳过的空白数 |
| A3 | 硬换行块之间同理：块末到下一块首之间的换行字符计入空隙 |
| A4 | **保留**原有 `splitTextIntoSegments(text, maxLen)` 导出，行为与分段结果一字不变（内部可改为调用新函数后取 `.segments`） |
| A5 | 引擎内部 `offsetOf(index)` 改为读 `offsets[index]`，不再累加段长；`restore(typedCount)` 按 offsets 反查"落在第几段、段内第几个字符" |
| A6 | 不得改变分段规则（P16 的优先级与约束原样保留），不得改 `maxLen` 默认值 32 |

## 2. B 组：首页按原文坐标算进度与索引（`public/script.js`）

| # | 要求 |
| --- | --- |
| B1 | `segmentOffsets = splitTextWithOffsets(originalText).offsets`；`getSegmentStartOffset(i)` 改为 `return segmentOffsets[i]` |
| B2 | 进度：`pct = (segmentOffsets[当前段] + 当前段已输入字符数) / originalText.length * 100`，最后一整段输入完成时**必须正好 100%**（允许浮点误差 < 0.01） |
| B3 | 错字记录、`getCurrentWord(globalPos)`、`charStates` 渲染一律用上面的真实偏移（`charStates` 长度仍为 `originalText.length`） |
| B4 | 不改计分、计时、准确率、朗读开关、结算卡等既有逻辑 |
| B5 | **错字上报必须按段配对**：现在 `script.js:926-935` 用 `inputVal[i]`（各段输入框拼接、已丢掉被 trim 的空白）与 `originalText[i]` 对齐，第 1 个换行之后全部错位。改为逐段遍历：`for 每段 i: for 每字符 k: 若 charStates[offsets[i]+k] === 'wrong' → { expected_char: segments[i][k], typed_char: values[i][k] }` |

## 3. 验收（逐条贴读数）

| # | 场景 | 判据 |
| --- | --- | --- |
| 1 | 281 字文章（id=9）跑完全文 | `#text-progress` 宽度 = **100%**（浏览器读 `style.width` 或 `getBoundingClientRect`），报告里贴出输入前后两个数值 |
| 2 | 同上一半时 | 进度 = `(offsets[当前段] + 已输入) / 281`，报告贴出"当前段号 / offsets 值 / 计算值 / 界面显示值"四列 |
| 3 | 跨换行错字 | 在第 2 段（换行之后的第一段）第一个字故意敲错，错字记录里的位置对应原文下标正确：贴出 `originalText.slice(pos-5, pos+5)` 与错字字符，证明对得上 |
| 4 | 朗读 | 打开朗读逐段推进到第 3 段，当前高亮词与原文同一位置（贴出高亮词与原文片段对照） |
| 5 | 比赛页进度 | 两名选手跑完，界面 `进度 x / charCount` 在完赛时到满值；比赛中途读数不再出现"差几个字"的漂移（贴出同一时刻 offsets 计算值与界面值） |
| 6 | 刷新恢复 | 比赛中刷新回到房间，`restore(me.progress)` 后当前段号与段内位置正确（贴出 me.progress、段号、输入框内容长度） |
| 7 | 分段不变 | 改造前后同一文章的 `segments` 数组**逐段完全相同**（贴出 11 段对照） |
| 9 | 错字上报配对 | 在**换行之后的第 2 段**敲错 1 个字并完成全文，读 `/api/user/error-log` 的请求体：`expected_char` 必须等于原文该位置字符、`typed_char` 等于实际敲的字符；同时贴出第 1 段（换行前）敲错的对照，两处都对 |
| 10 | 累计字数/准确率不变 | 跑完同一篇文章，结算卡的「字数 / 速度 / 准确率」与改造前一致（贴前后两组数值） |
| 8 | 单一实现 | `grep -Rn "function splitTextIntoSegments" public` 只命中 `typing-engine.js`；`grep -Rn "offsetOf\|getSegmentStartOffset"` 不再有累加段长的写法 |

## 5. 停止点

- 若 `charStates` 的下标被别处（结算卡、错字统计）当"段内下标"用 → 停，先列出全部调用点再改；
- 若发现比赛页 `race.js` 也需要同步改显示 → 允许一并改（属同一缺陷），但只改显示口径，不动上报字段。
