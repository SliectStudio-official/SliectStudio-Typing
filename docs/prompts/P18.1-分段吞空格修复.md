# P18.1-分段吞空格修复（自适应 maxLen 下的内容损坏）

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。**这是 P18 C 组的阻塞缺陷**：自适应 maxLen 上线后，部分宽度下分段会**吃掉原文里的空格**，导致打字内容与原文不一致。只修这一个问题，别动别的。
> 来源：`docs/reports/P18-验收记录.md` 第三节。

## 0. 缺陷（规划侧独立复现，可复跑）

用生产文章 id=9（281 字）直接调引擎：

```
for n in 8..40: 调用 splitTextIntoSegments(text, n)
结果：n ∈ { 11, 24, 25, 26, 27, 28 } 时，拼接结果里出现 "AI世界"
而原文是 "AI 世界"（中间有一个半角空格）→ **该空格被吞掉**
```

连带后果：

| 现象 | 说明 |
| --- | --- |
| 段内容不是原文子串 | `text.indexOf(segment) === -1`，段里出现原文不存在的字符串 |
| `splitTextWithOffsets` 偏移失效 | 匹配失败后走 `cursor += segment.length` 的盲推兜底，offsets 全部错位（我在 n=27 上实测恒等式 `text.slice(offsets[i], offsets[i]+len) === segments[i]` **不成立**，且第 7 段前空隙含 `"。\n\n"` 非空白） |
| 用户视角 | 界面显示 `AI世界`，原文是 `AI 世界`——**照着原文打反而被判错**；进度与错字坐标跟着错 |
| 触发宽度 | n=24…28 对应约 600–768px 宽度；n=11 对应极窄屏 |

> 32 字（P16 默认）恰好不在此列，所以此前没暴露；一旦按屏幕自适应就把这个老 bug 翻出来了。

## 1. 修复要求

### A 组：分段必须可无损回放（`public/typing-engine.js`）

| # | 要求 |
| --- | --- |
| A1 | 硬约束：存在只含空白的 `gaps`，使得 `text === gaps[0] + segs[0] + gaps[1] + segs[1] + … + gaps[n]`。**行内空格不得丢失**；只允许丢弃"段尾/段首"处的空白，且必须体现在 gaps 里 |
| A2 | 断点落在空白上时，二选一并保持一致：① 空白留在上一段末尾（则该段末尾允许有空白，渲染时 trim 显示但计数要算）；② 空白整段作为 gaps。**无论哪种，A1 必须成立** |
| A3 | `splitTextWithOffsets` 的匹配循环**禁止盲推兜底**：`text.startsWith(segment, cursor)` 不成立时，`console.error` 打印段号/段内容/游标位置，并**从游标重新硬切**（用 maxLen 切）继续，绝不允许 `cursor += segment.length` 静默推进 |
| A4 | 新增内部校验函数 `verifySegments(text, segments, offsets)`：返回 `{ ok, reason }`，检查 A1 恒等式与空隙纯空白；在 `splitTextWithOffsets` 末尾调用，失败时 `console.error` 一次（不要每次输入都打印） |
| A5 | `splitTextIntoSegments(text, maxLen)` 与 `splitTextWithOffsets(text, maxLen, strictMax)` 的返回形状不变；P16 的分段优先级、开括号/收尾标点约束、英文不断词、`minLen` 规则全部保留 |
| A6 | `splitOversizedSegments` 也要满足 A1（它现在对切点后的空白处理同样可能吞字） |

### B 组：验收脚本（一次性，放 `tmp/`）

| # | 要求 |
| --- | --- |
| B1 | 写一个一次性脚本，对 **n = 8…40 全 33 档 × 至少 3 篇真实文章**（从生产库只读副本取，长度分别约 100 / 281 / 800 字）跑 `verifySegments` |
| B2 | 每档输出：段数 / 恒等式是否成立 / 空隙是否纯空白 / 是否有段不是原文子串 / 最长段 / 是否 0 失败 |
| B3 | **要求：33 档 × 3 篇 = 99 组全部 0 失败**，报告里贴出汇总表（可用「档位区间 → 失败数」压缩，但失败项必须逐个列出） |

### C 组：页面实测

| # | 要求 |
| --- | --- |
| C1 | 在 768px 与 600px 宽度打开首页练习那篇 281 字文章，找到含 "AI 世界" 的那一段，**照着原文输入（含空格）**，确认不判错、进度正常推进 |
| C2 | 同一段在 420px 与 1920px 下也各打一遍，结论一致 |
| C3 | 比赛页同样在两档窄宽度下打这一段，服务端 `progress` 与界面一致 |

## 2. 允许改什么 / 不许改什么

| 允许 | 不许 |
| --- | --- |
| `public/typing-engine.js`（分段与偏移相关） | 改分段优先级/规则、改 `measureMaxLen` 的取宽逻辑、改首页计分与进度公式、改 `server.js`、改数据表、改 `VERSION` / `CONTRACT_VERSION` |
| 一次性脚本放 `tmp/` | 把校验函数暴露成全局调试接口（可以内部调用） |

## 3. 停止点

- 若修 A1 必须改变分段规则（例如必须跨硬换行合并）→ 停，先报；
- 若发现吞字是 `measureMaxLen` 传入非法 n（如 0、NaN、非整数）导致 → 先补入参校验再报；
- 若 33 档里有档位无法在不违反 P16 规则的前提下做到 0 失败 → 列出该档位与原因，不要悄悄放过。
