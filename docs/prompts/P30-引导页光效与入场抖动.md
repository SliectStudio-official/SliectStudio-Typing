## 1. A 件：删除静息态光效（用户要求"删掉"）

| # | 要求 |
| --- | --- |

### A0 补充：截图里那道斜向亮带的真实来源（我核对后的判断）

截图里三张卡上各有一道**从右下往左上斜切的亮带**。我把 `style.css` 里所有渐变翻了一遍，**没有任何 135° 斜向渐变**，所以它不是我们画的装饰。

最可能的原因是 **`backdrop-filter` 与 3D 变换叠加的渲染缺陷**：卡片自身有 `backdrop-filter: blur(20px)`，同时又有 `transform: translate3d(0,0,30px)`，而父层设了 `perspective` 与 `transform-style: preserve-3d`。Chromium 在这种组合下会用三维空间的斜切方式采样背景，模糊层边界被斜着切一刀，看起来就是一道亮带。

| # | 要求（硬要求） |
| --- | --- |
| A0.1 | 带 `backdrop-filter` 的元素**一律不许有任何 3D 变换**：不许 `translateZ` / `translate3d(...,z)` / `rotateX/Y` / `perspective()`，也不许放在 `transform-style: preserve-3d` 的子树里。卡片与资料卡的 `transform` 只能是二维 `translate(x,y)`（幅度仍 ≤4px）或 `none` |
| A0.2 | 深度感改由**背景层**承担：照片 / 网格 / 压暗层继续按 `translate3d` 做视差；卡片与资料卡只做二维平移，不再参与 Z 分层 |
| A0.3 | 改完必须验证亮带消失：贴**同一位置**改动前后两张截图（1440 宽、鼠标静止） |
| A0.4 | `.dash-actions` 上的 `transform-style: preserve-3d` 一并去掉（它会把子元素强推进 3D 渲染上下文） |
| A1 | **静息态零光效**：不 hover、不在匹配时，页面上不得有**任何**流动光带、跟随光斑、环形描边、呼吸发光、扫描线动画。逐项确认后删除或永久置 0（`opacity:0` + `animation:none` + `display:none`） |
| A2 | 已知嫌疑清单（逐个处理）：<br>· `.dash-action::after` 径向光斑（`radial-gradient(220px circle at var(--fx-mx) var(--fx-my))`）→ **删除**<br>· `.dash-action::before` conic 环形描边 + `fxBorderSpin` → **删除**（hover 也不再出现）<br>· `.fx-scan` 扫光 → 静息态彻底不出现；**若刷新前在匹配中残留 `is-matching`，加载时必须清掉**<br>· `.fx-grid` 网格线 → 不透明度从 0.05 降到 **≤0.03**，且不要有动画 |
| A3 | hover 只保留**朴素反馈**：背景 `rgba(255,255,255,.05 → .09)`、描边 `.11 → .20`，不许再加光效 |
| A4 | 匹配态保留原样（卡片变蓝 + 蓝色呼吸 + 扫光），那是**状态反馈**，不是静息装饰 |
| A5 | 删除后 `home.js` 里只用于光斑的 `--fx-mx/--fx-my` 计算可以一并删（若还被别处用则保留，报告说明） |

## 2. B 件：修"顿一下然后瞬移"

**我查到的可疑根因**（`style.css` 约 4828–4830 行）：
| # | 要求 |
| --- | --- |
| B1 | **把 3D 变换与入场动画解耦**：3D 位移只加在**外层包裹**（如给每张卡加一个 `.dash-action-slot`），入场动画只作用于内层；或用可动画的自定义属性（`--enter-y`）参与 `transform` 计算，使**同一帧内**始终只有一套完整 transform |
| B2 | 入场**不得改变水平位置**：从首帧到稳定（≥2s），三张卡的 `getBoundingClientRect().left` 全程变化 **≤1px**；也不得有任何一帧出现 Z 位移突变导致的尺寸跳变（`width` 变化 ≤1px） |
| B3 | 三次错峰入场（0/80/160ms）与总时长 ≤600ms 保持不变；`prefers-reduced-motion` 下仍然直接显示 |
| B4 | 入场结束后**不得再有任何延迟应用**的 transform（不许 setTimeout 加类、不许等数据到位再套 transform） |
| B5 | 资料卡与 hero 同样检查：数据加载（头像/姓名/统计）引起的宽度变化不得推动左侧卡片水平位置（左右两栏用固定列宽或 `min-width` 锁定） |

## 3. 验收（逐条贴读数）

| # | 场景 | 判据 |

| 1 | **静息态无光效** | 不 hover 不在匹配：贴一张静态截图 + 逐个元素读数（`animation-name` 全为 `none`、`::after`/`::before` 的 `opacity` 为 0 或元素被删、`body.classList` 不含 `is-matching`） |
| 2 | 刷新残留清理 | 先在匹配态刷新页面：加载后贴 `body.classList`（不含 `is-matching`）与 `.fx-scan` 的 `display:none` |
| 3 | hover 朴素 | hover 一张卡：贴 `background` / `borderColor` 变化值，且 `::before`/`::after` 已不存在（贴 `getComputedStyle(el, "::before").content` 为 `none` 或元素无该伪类） |
| 4 | 匹配态不变 | 点快速开始：卡片变蓝 `rgba(68,74,255,.2)`、蓝描边、呼吸与扫光出现（各贴一条） |
| 5 | **无水平跳变** | 用 Performance/Rect 采样（每 16ms 一次，0–2000ms）贴三张卡 `left` 序列：**最大最小值差 ≤1px**，且 `width` 差 ≤1px |

| 7 | 数据加载不推动卡片 | 让 `/api/user/profile` 延迟 1 秒返回：贴加载前后三卡的 `left`（差 ≤1px） |
| 8 | 减弱动效 | `prefers-reduced-motion` 下贴三卡 `animation-name: none` 且位置稳定 |
| 9 | 回归 | 纵向三卡、铺满无黑边、主站字号（16/22/14/20/12）、模糊 `blur(20px) saturate(1.1)`、视差三层仍工作（各贴一条读数） |
