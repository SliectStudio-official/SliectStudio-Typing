## 2. 逐项交付

### A 项：K-16 编辑用户时不再无条件回写 role

- 位置：`public/admin.js` 第 750-783 行「用户列表 → 编辑」的点击处理器。
- 现状：第 764 行用 `confirm('是否设为管理员？确定=管理员，取消=普通用户')` 取角色，第 769 行 `body.role = newRole` **无条件**提交。管理员只想改邮箱、在弹窗里点了「取消」，目标用户的 role 就被写成 `user`；对唯一管理员这样操作会让全站失去管理员。
- 改法：
  1. 删掉第 764 行的 `confirm` 与第 769 行的无条件赋值。
  2. 改成第三次 `prompt`（与前三步同样风格，不新增弹窗组件）：`prompt('角色（admin / user，留空不修改）：', user.role)`。
  3. 返回 `null` → 中止，不发请求（与前三步一致）。
  4. 输入去空格后为空 → **不加** `role` 字段。
  5. 输入为 `admin` 或 `user` → 加到 `body.role`。
  6. 其它任何值 → `alert('角色只能是 admin 或 user')` 并中止，不发请求。
  7. 其它三处字段（username / email / password）的既有处理逻辑不要动。
- 验收口径（页面级，Network 面板为准）：

| 步骤 | 期望 |
| --- | --- |
| 编辑某用户，角色输入框留空，只改邮箱 | 请求体里 **没有** `role` 字段；该用户 role 不变 |
| 编辑某用户，角色输入 `admin` | 请求体含 `"role":"admin"`；该用户变成管理员 |
| 再把该用户角色输入 `user` | 变成普通用户 |
| 角色输入 `abc` | 弹出「角色只能是 admin 或 user」，Network 里**没有**该 PUT 请求 |
| 编辑唯一管理员并留空角色 | 该管理员仍是 admin（前端不发 role；即便发了，P3 的服务端防线也会 400） |
| 全流程任意 Ctrl+C 取消（返回 null） | 不发请求，列表无变化 |

### B 项：K-15 待审文章作者显示「匿名」

- 位置：`public/admin.js` 第 500 行。
- 现状：`escapeHtml(a.author || '匿名')`，而 `GET /api/articles/pending` 返回的字段叫 `author_name`，取不到值就静默落到「匿名」。
- 前置动作（吸取上一批的教训）：先用 grep 确认接口返回的字段名，**不要凭印象改**：
  ```powershell
  Select-String -Path server.js -Pattern "author_name" -Context 0,1
  ```
- 改法：改成 `escapeHtml(a.author_name || '匿名')`。保留「无作者时显示匿名」的兜底。顺手在全文件再 grep 一次 `a.author`，若还有别处用错一并改（同一字段名问题），并在报告里列出全部改动点。
- 验收口径（页面级）：

| 步骤 | 期望 |
| --- | --- |
| 用 `__verify_投稿人` 账号投稿一篇文章（在 `tmp/` 空库实例上做，不要污染生产库） | 文章进入待审 |
| 打开 `admin.html` → 待审核 | 该条显示「作者：__verify_投稿人」，不是「匿名」 |
| 把该文章 `author_id` 置空（或用一条 `author_id` 为 NULL 的历史待审文章） | 仍显示「匿名」（兜底保留） |
| 审核通过 / 拒绝操作 | 仍正常，列表刷新正确 |

## 4. 停止点

- 发现 `role` 不只在编辑用户处被无条件提交（例如别处也在发 role）→ 先报读数，不扩大改动
- 待审列表里还有别的字段名不匹配（`author` 之外）→ 报出来，本批只修 author 这一处
- 页面出现白屏、列表不渲染、按钮失效 → 停
- 需要改 `server.js`、需要改 HTML、需要新依赖 → 停
