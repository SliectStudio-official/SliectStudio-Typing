# P4-输出侧安全

> 读的提示词就是本文件。开工时把本文件 sha256 算出来，写进执行报告第一行。
> 你是本项目的执行方 AI。开工前读 `AGENTS.md` 的 §0、§4、§5、§7，再读 `docs/CURRENT.md` 五块。
> 本批只做两件事：把用户可控内容在**输出**时转义干净（前端），把**不该下发的字段**拦住（服务端）。

## 0. 上一轮不确定项的处理决定

| 不确定项 | 决定 | 理由 |
| --- | --- | --- |
| P1 验收的两条环境偏差（Node v25 / 开发模式签名） | 不影响本批，继续在现有执行环境作业 | 本批同样是纯 JS 改动，无原生 ABI 依赖 |
| 待拍板 #3 / #4 鉴权修法 | 本批不涉及，鉴权类问题一律留到 P3 | 本批不碰 token 与 role 判定 |
| 待拍板 #9 安全响应头（CSP 等） | 本批不涉及，留到杂项批 | 本批只做转义与字段过滤，不加中间件层的头 |
| 跨模块豁免 | 批准本批同时动 `public/`（A 组）与 `server.js`（B 组），必须**两次提交、各自可回滚** | 前端转义与服务端校验是同一件事的两半，分开下发会让「先修一半」的中间态看起来像已修 |

## 2. 逐项交付

### A 组（先做，单独提交）：转义缺口

现状事实：三个前端文件各自有一份**完全相同**的 `escapeHtml`，都只替换 `& < >`（`public/admin.js:2053`、`public/script.js:1306`、`public/profile.js:142`）。

| # | 交付物 | 位置 | 改法 |
| --- | --- | --- | --- |
| A1 | 三份 `escapeHtml` 补引号 | 上述三处 | 在 `& < >` 之后追加 `.replace(/"/g,'&quot;').replace(/'/g,'&#39;')`；三处必须完全一致，不加不删其它字符 |
| A2 | 用户管理页的邮箱未转义 | `public/admin.js:741` | `(user.email \|\| '无邮箱')` 改成 `escapeHtml(user.email \|\| '无邮箱')` |
| A3 | 属性拼接面复核 | `public/admin.js:1219` 等所有 `data-*="..."` 拼接 | A1 生效后属性值已被转义；逐处人工复核一遍，把「值来自用户或数据库且进了属性」的清单写进报告。`data-id` 为数字，不需要额外处理 |

除以上三处，本组不改任何渲染逻辑。已知 `profile.js` 用 `textContent`、公告与文章预览已包 `escapeHtml`，不要顺手改造。

### B 组（A 组通过后，单独提交）：服务端校验与字段过滤

| # | 交付物 | 位置 | 改法 |
| --- | --- | --- | --- |
| B1 | 邮箱格式与长度校验 | `server.js` 三处：`POST /api/auth/register`、`PUT /api/auth/me`、`PUT /api/admin/users/:id` | 抽一个 `normalizeEmail(input)`：空值/undefined 返回 null；去空格后长度大于 100 或不符合 `^[^\\s@]+@[^\\s@]+\\.[^\\s@]+$\\$ 返回 `{ ok:false }`；合格返回小写化后的值。三处统一调用它，不合法一律 400 `{ error: '邮箱格式不正确' }`。**不要改数据库里已有数据的邮箱格式，不要批量清洗** |
| B2 | 敏感列不下发 | `server.js` 的 `GET /api/admin/db/:table`（当前第 1405 行起） | 在 `res.json` 之前过滤 `rows`：剔除列名匹配 `/password\|hash\|secret\|token/i` 的键。同时把 `columns` 数组里同样匹配的列一并剔除，保证前端渲染与列头一致。**只改 GET**，POST/PUT 行为不变（管理员仍可通过用户管理接口改密码） |
| B3 | 复核是否还有其它端点下发整行用户数据 | `GET /api/admin/users`、`GET /api/user/profile`、`GET /api/auth/me` | 逐个确认响应里无 `password_hash`；有就按 B2 同样方式剔除。只报结论，不改无关字段 |

## 3. 验收口径

### 环境与数据准备（同 P1 约定）

1. 动手前把 `data/typing.db` 备份到 `tmp/typing-backup-<日期时间>.db`，报告写备份文件名。
2. 测试对象一律以 `__verify_` 开头；结束后清理并在报告写「已清理，剩余 0 条」。
3. 不得手写 SQL 绕过接口做验收（读操作除外）。

### A 组

| 步骤 | 期望 |
| --- | --- |
| 用数据库面板把某用户的 `email` 改成 `<img src=x onerror=alert(1)>`（此路输入服务端仍允许，见 B1 生效前） | 写入成功 |
| 打开 `admin.html` 用户管理页 | 该条显示字面文本 `<img src=x onerror=alert(1)>`，**不弹 alert**，控制台无报错 |
| 在 Console 检查该行 DOM | `document.querySelectorAll('img')` 数量不因该条增加 |
| 建一个名字含双引号的分类 `__verify_分类"注入`，打开分类页并点该条「编辑」 | 不弹脚本、页面结构与其它行一致、prompt 里显示原名（A1 生效后属性不再被截断） |
| 回归：文章列表、待审文章、公告、排行榜管理页各看一遍 | 显示与改动前一致，无乱码（注意 `&quot;` 不应出现在正常文本里） |

### B 组

| 步骤 | 期望 |
| --- | --- |
| 注册时 `email = not-an-email` | 400 `{"error":"邮箱格式不正确"}` |
| 注册时 `email = <img src=x onerror=alert(1)>` | 400 同上（本批后该 payload 进不了库） |
| 注册时 `email = A@B.C` | 200，库内保存为小写 |
| 注册时 `email = ` 空串或不传 | 200，`email` 仍为 null |
| 注册时邮箱长度 120 字符 | 400 |
| 管理员用 `PUT /api/admin/users/:id` 把某用户邮箱改成非法值 | 400；合法值 200 |
| `GET /api/admin/db/users` | 响应 `rows` 与 `columns` 里**都没有** `password_hash`；其它表（`announcements`、`articles`）字段完整 |
| 打开 `admin.html` 数据库面板用户表 | 列头无 `password_hash`，无空列错位，翻页与搜索仍可用 |
| 回归：数据库面板改一条公告内容 | 仍可编辑并保存 |
| `GET /api/admin/users`、`GET /api/auth/me`、`GET /api/user/profile` | 响应里无 `password_hash` |

无凭据端点用命令行，带凭据端点用浏览器 Console（token 从 `localStorage` 取，凭据不进命令行）：

```powershell
node --check server.js
node --check db-config.js
curl.exe -s -X POST http://localhost:3000/api/auth/register -H "Content-Type: application/json" -d "{\"username\":\"__verify_x1\",\"password\":\"pass123\",\"email\":\"not-an-email\"}"
curl.exe -s -X POST http://localhost:3000/api/auth/register -H "Content-Type: application/json" -d "{\"username\":\"__verify_x2\",\"password\":\"pass123\",\"email\":\"a@b.c\"}"
```

## 4. 停止点

- B2 过滤后前端数据库面板出现列错位、翻页异常或控制台报错（说明前端依赖了列顺序）→ 停下报读数，不要顺手改前端
- 发现历史数据里有不合法的邮箱，且新校验导致管理员改不动这些用户 → 报出来，不要批量清洗
- 需要改表结构、需要新增依赖、需要动 `public/*.html`
- 任一条验收与期望不符且原因不明

## 5. 交付格式

四段式加执行报告，写进 `docs/reports/P4-执行报告.md`，第一行写 `docs/prompts/P4-输出侧安全.md` 的 sha256。报告必须含：

1. 改了什么：A 组、B 组分开列，A3 的「属性拼接面清单」单列一节。
2. 怎么验证：贴每条验收的实际读数（含 `GET /api/admin/db/users` 的字段清单）。
3. 怎么回滚：逐处写明改回哪一行。
4. 不确定项。
5. 数据结构与关系清单：本批预期「无变化」，也要写。
