## 2. B 组：资源指纹按文件变更自动失效（根治 K-30）

**现象**：改完 `public/` 下的文件不重启服务时，HTML 里仍然引用旧的 `?v=<hash>`，浏览器与 Service Worker 会用旧缓存，改动`看不到`。本轮用户实际踩到：首页一直停在「正在加载」。

| # | 要求 |
| --- | --- |
| B1 | 资源指纹改为**按文件状态自动失效**：每次需要生成 HTML 时，先看该文件 `mtimeMs`+大小是否与上次一致，变了才重算哈希；不变则复用缓存 |
| B2 | 实现放在 `server.js` 现有 `buildAssetHashes` 一带，**不引新依赖**（只用 `fs.statSync`） |
| B3 | 请求 HTML 时最多对 6~8 个文件做 `stat`，不得对每个资源都重算 sha256；给出一次 HTML 请求的额外耗时读数（`curl` 前后各 5 次取中位数） |
| B4 | 服务端日志在「检测到资源变更并重算」时打一行 info（含文件名与新指纹），便于排查 |
| B5 | 不得改动 `/api/asset-version` 的输出形状与 SW 的缓存键规则 |

验收（这是本组的核心断言，必须真跑）：

| 步骤 | 期望 |
| --- | --- |
| 1 | 启动服务，记下 HTML 里 `nav.js?v=…` 与文件真实哈希，两者一致 |
| 2 | **不重启**，往 `public/nav.js` 末尾加一行注释保存 |
| 3 | 立刻请求 `/index.html` | 新的 `?v=` 已经变了，且等于当前文件哈希；日志出现`检测到资源变更`一行 |
| 4 | 恢复那行注释（删掉），再请求 | 指纹变回原值 |
| 5 | 并发 20 次请求 HTML | 无 500；指纹始终与文件一致 |

## 3. C 组：管理面板「比赛房间」区块

后端已就绪（`authMiddleware` + `adminMiddleware`），本组只做界面：

| 端点 | 用途 |
| --- | --- |
| `GET /api/admin/races` | 房间列表（含私人房，**响应里不得有密码字段**） |
| `POST /api/admin/races/:code/cancel` | 强制解散 |
| `POST /api/admin/races/:code/kick` | 踢出参与者（`userId` 或 `guestId`） |
| `GET/PUT /api/admin/race-settings` | 全局上限（1–50）与允许建房开关 |

| # | 界面要求 |
| --- | --- |
| C1 | 管理面板左栏菜单新增一项「比赛房间」（与现有 11 个区块同级、同样式、同样锚点切换） |
| C2 | 区块顶部一行只读信息：当前房间数 / 在线比赛人数 / 单房最高人数 / 上限值 |
| C3 | 房间表格列：房间码、房主、文章标题、人数 `x/y`、状态、是否公开、创建时间；行尾「解散」「成员」两个按钮 |
| C4 | 「解散」二次确认后调接口，成功后刷新列表并提示 |
| C5 | 「成员」展开该房间成员（昵称 / 是否游客 / 是否房主 / 准备状态 / 进度），每行可「踢出」 |
| C6 | 全局设置两个控件：最大房间数（数字 1–50）、允许建房（开关），保存后调 `PUT` 并回显 |
| C7 | 空态与失败都要显式：没有房间时写「当前没有进行中的比赛」，接口失败时把 `error` 文案显示出来，不许渲染成空表 |

验收：未登录 401、普通用户 403、管理员 200 三态都要点一遍；解散后**参赛者视角**下一次 `tick`（≤1.2s）能看到「房间已解散（管理员操作）」；关闭「允许建房」后建房返回「管理员已暂停创建比赛」。
