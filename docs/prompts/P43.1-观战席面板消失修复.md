# P43.1-自建房观战席面板消失（条件隐藏误用 remove() 永久删 DOM）

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。只改 `public/race.js`（约 20 行），**不用重启**。

## 0. 用户反馈

> 「我截图的是自建房　观战席的设置不见了」

截图为**自建房**（房主 Luca，房间 UB234U），右侧应有的「观战席 x/y」面板整块不显示，房主看不到「开放观战 / 自由进入·房主安排 / 席位数」这些控件。

## 1. 根因（已定位，代码级）

| 位置 | 现状 | 后果 |
| --- | --- | --- |
| `public/race.js:1568 syncMatchmadeUI(matchmade)` | `if (!matchmade) return; `然后 `panel.remove()`、`live.remove()` | **把 DOM 节点直接删掉**；之后再怎么进自建房也不会重建 ⇒ 观战席面板永久消失 |
| 同函数 | 只有 matchmade 分支，没有 else 恢复分支 | 即使不删节点，也没有“恢复显示”的路径 |
| `public/race.js:1977` | `dissolveBtn.remove()` | 同类型问题：进过匹配房后「解散房间」按钮也被永久删除，之后自建房应显示的解散按钮同样消失 |

触发条件：**同一个页面会话里进过一次匹配房**（或“已恢复上次的比赛”把匹配房恢复回来），随后退出再建/进自建房 → 观战席面板（以及解散按钮）不见。刷新页面可临时恢复，所以容易被当成偶发。

## 2. 改动要求（只改 race.js）

| # | 要求 |
| --- | --- |
| A1 | `syncMatchmadeUI(matchmade)` 改成**双向**：matchmade 为真时把 `#race-spectate-panel` 与 `#race-spectator-live` 设为 `display: none`；为假时恢复 `display: ''`（并用 `style.display` 控制，**禁止再用 `remove()`） |
| A2 | 去掉开头的 `if (!matchmade) return;`，保证两个分支都会执行 |
| A3 | `dissolveBtn`（约 1977）同样改成隐藏/显示，不要 `remove()`；若那里是“按条件创建按钮”，改成创建一次后只切 `style.display` |
| A4 | 恢复显示后**必须重新渲染内容**：观战席面板恢复时调用现有的 `renderSpectatorPanel(snap, isHost, seat)`，侧栏 `renderSpectatorLive(snap)`（这两个函数已存在，别新写渲染逻辑） |
| A5 | 确保 `syncMatchmadeUI` 在**每次进入房间渲染时**都被调用（含建房、加入房间、恢复上次比赛、匹配成功）——现有调用点在 742 行，`确认它对新进入的自建房也会被执行；若某些路径不经过 742，请补调用 |
| A6 | 全仓扫一遍：还有哪些地方用 `.remove()` 做“条件隐藏”（而不是真的销毁临时节点），列成清单写进报告；本轮只修上面三处，其余只列不改 |
| A7 | 不改观战席的业务规则（默认约 10% 席位、房主安排/自由进入、转观战按钮禁用条件、匹配房确实没有观战） |
