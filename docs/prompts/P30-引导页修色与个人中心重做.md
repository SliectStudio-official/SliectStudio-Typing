# C 部分：解散"没投票就散了"收口（提交 5）

## C0. 我先复现过：服务端行为是对的

在隔离副本里建 2 人房、双方各 tick 一次，房主调 `/api/race/dissolve/start`：

```text
start → {"result":"voting","mode":"vote","needed":2,"online":2,"agreed":1,"total":2}
P2 tick 顶层 dissolve → {"active":true,"mode":"vote","needed":2,"agreed":1,"online":2,"total":2,"myVote":null}
P2 同意 → {"agreed":2,"needed":2,"passed":true,"result":"cancelled","reason":"vote_dissolved"}
```

也就是说：**两人都在线时确实会进投票**，投票状态在快照**顶层** `snap.dissolve` 下发，前端也读这个字段（`race.js:1613` 等）。

那你遇到"显示要 2 人同意却直接解散"，只剩一种解释：**点确认那一刻，服务端把你对手判成了掉线**——`onlinePlayers()` 用的是 `now - player.lastSeen <= 45s`，只要对手 45 秒没心跳，`dissolveRule` 就从 `vote/needed=2` 变成 `direct`，于是 `start` 直接 `cancelRoom(room,"dissolve_direct")`。而你屏幕上那句"在线 2 人"来自上一条 tick 的缓存，于是看起来就像"没投票就散了"。

| # | 要求 |
| --- | --- |
