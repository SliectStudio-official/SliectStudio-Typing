## 0. 用户原话与我的定位

> 「现在有一个流光边缘，但是**模糊没了**，模糊要加回去，**匹配中的时候卡片的变色也没了**，变色也加回去，并且要有**变色颜色的流光边缘**」。

我在 `public/style.css` 里核到的现状：

| # | 现象 | 代码事实 |
| --- | --- | --- |
| 1 | 玻璃模糊丢了 | `#view-dashboard .dash-action`（约 4773 行）**根本没有 `backdrop-filter` 声明**；`.dash-profile` / `.dash-row` 同样没有。设计稿原本是 `backdrop-filter: blur(20px)` |
| 2 | 匹配态变色丢了 | 只剩一处 `background: rgba(68,74,255,.18)`（约 4850 行），**没有描边变色、没有 hover 加深、没有文字转白、没有 × 替换箭头** |
| 3 | 流光只有品牌色 | 流光伪元素是 `conic-gradient(… var(--primary) …)`（约 4803 行），匹配态也还是橙色 |

## 1. A 件：把玻璃模糊加回（设计稿 20px）

| # | 要求 |
| --- | --- |
| A1 | 新增令牌：`--glass-blur-strong: 20px`（若已有近似值就复用），玻璃元素统一写 `backdrop-filter: blur(var(--glass-blur-strong)) saturate(1.1)` **并同时写 `-webkit-backdrop-filter`** |
| A2 | 必须加模糊的元素：**三张动作卡**、**资料卡**、**资料卡里的四条链接行**、**通知面板**。其余一律不加 |
| A3 | 模糊元素总数 ≤ **6 个**（性能）；`blur` 半径不超过 20px |
| A4 | 流光伪元素必须画在**卡片边框一圈**（`conic-gradient` 只落在 1px 环上，可用 `mask` 或 `padding-box/border-box` 双层实现），**不得用半透明大块盖住卡片内部**，否则会把模糊糊掉 |
| A5 | 卡片内部背景保持设计稿的 `rgba(255,255,255,.05)`（5% 白）；模糊 + 5% 白叠加后，卡片内文字对比度仍 ≥ 4.5:1 |

## 2. B 件：匹配态配色整回来（设计稿 I10:272;10:260）

| # | 要求 |
| --- | --- |
| B1 | 新增令牌：`--match-blue: #444aff`、`--match-fill: rgba(68,74,255,.20)`、`--match-fill-hover: rgba(68,74,255,.28)`（设计稿原值） |
| B2 | `.is-matching` 时：卡片背景 = `var(--match-fill)`、hover = `var(--match-fill-hover)`、**描边 1px = `var(--match-blue)`**、标题与说明文字变**纯白** |
| B3 | `.is-matching` 时右侧**箭头隐藏、× 显示**（现有 `match-only`/`idle-only` 机制保留） |
| B4 | 匹配态标题显示正计时 `mm:ss`（P25.1 已有逻辑，保持不变），说明文字「正在寻找对手」 |
| B5 | 取消匹配后必须**完全复位**：背景、描边、文字色、箭头/× 全部回到 idle 外观（贴复位前后计算值） |

## 3. C 件：匹配态流光用蓝色

| # | 要求 |
| --- | --- |
| C1 | 流光色改用变量 `--fx-ring-color`：idle 三卡 = `var(--primary)`（品牌橙）；`.is-matching` = **`var(--match-blue)`** |
| C2 | 匹配态的**呼吸发光**（P25.2 A7）颜色也改成 `var(--match-blue)`，不能还是橙色 |
| C3 | 流光速度不因换色变快；半径仍 1px |
| C4 | 状态切换时流光颜色要**立即切换**（不保留橙色渐隐） |

## 4. D 件：匹配态字重、按钮与图标尺寸、扫光回归匹配态

我在 `public/style.css` 与 `public/home.html` 核到的现状：

| # | 现象 | 代码事实 |
| --- | --- | --- |
| 1 | 匹配态文字不够重 | `.is-matching` 只有背景与描边变化，**没有加字重**；标题仍是 600 |
| 2 | 取消匹配的 × 太大 | `.dash-match-close` 点击区 **44×44**、内层 svg **20×20**；而旁边的正计时标题只有 **16px** —— 视觉上大了一整圈 |
| 3 | 通知铃铛太大 | `.home-bell` 按钮 **32×32**、内层 svg **18×18**，比顶部条文字（约 13–14px）大太多 |
| 4 | 扫光常驻喧宾夺主 | `.fx-scan`（`style.css` 约 4715 行）是**无条件的常驻动画**：120px 高光带、`animation: fxScan 8s linear infinite`、`background: linear-gradient(… rgba(255,255,255,.045) …)` |

| # | 要求 |
| --- | --- |
| D1 | **匹配态文字加粗**：`.is-matching .dash-action-title { font-weight: 700 }`、`.is-matching .dash-action-desc { font-weight: 500 }`；idle 态保持 600 / 400 不变 |
| D2 | **取消匹配 × 缩到与时长同级**：视觉尺寸 **16×16**（与 `.dash-action-title` 16px 字号同高）；点击区降到 **32×32**（可接受的触控下限），垂直居中且与计时文字**同基线**；右侧留白随之从 36px 收到 28px |
| D3 | **通知铃铛缩小**：按钮 **28×28**、内层 svg **16×16**，与顶部条文字（13–14px）协调；`home-login` 按钮高度从 32px 同步降到 **28px**，两者对齐 |
| D4 | **扫光只在匹配时出现**：`.fx-scan` **默认 `display: none` 且不跑动画**；只有当页面存在匹配态（`.dash-quick.is-matching` 或 `body.is-matching`）时才显示并开始 8s 循环；取消匹配后**立刻停止并隐藏**（不能留在屏幕上继续跑） |
| D5 | 扫光本身仍然克制：不透明度 ≤ 0.045、高度 120px、`pointer-events: none`、`z-index` 不得盖住卡片点击；在 `prefers-reduced-motion` 下即使匹配中也不跑 |
| D6 | 网格叠层 `.fx-grid` **保留常驻**（用户没说它抢戏），但若报告里显示它比扫光更显眼 → 按 §7 停止点处理 |

## 5. E 件：文字对齐收口（按钮默认居中惹的祸）

**根因已定位到具体行**：`#view-dashboard .dash-row`（`style.css` 约 4913 行）**没有写 `text-align`**。而资料卡四条链接行的标签类型不一样：

| 行 | 标签 | 浏览器默认 | 实际表现 |
| --- | --- | --- | --- |
| 排行榜 | button | text-align: center | **文字居中**（你看到的问题） |
| 我的投稿 | button | text-align: center | **文字居中**（同一个毛病） |
| 查看个人数据 | a | 继承左对齐 | 左对齐（正常） |
| 管理面板 | a | 继承左对齐 | 左对齐（正常） |

所以"上面两个居中、下面两个左对齐"不是设计问题，是 button 的 UA 默认样式没被覆盖。

| # | 要求 |
| --- | --- |
| E1 | 四条链接行统一左对齐：`.dash-row` 显式写 `text-align: left; justify-content: flex-start;`，`.dash-row-label` 再兜一层 `text-align: left`；**不许靠"把 button 换成 a"绕过**（语义上它们确实是按钮） |
| E2 | 四行的文字左起点必须完全相同（容器内边距一致），箭头仍靠右 |
| E3 | 同类问题一起查：页面上所有 button 容器里若有左对齐文字（三张动作卡、状态条、通知条按钮）都要显式 `text-align: left`；`.dash-action` 已有，逐个核对 |
| E4 | 资料卡内其它文字保持居中（头像、昵称、四项统计按设计稿居中），**只把四条链接行改左对齐** |

## 8. 停止点

- 若加上 `backdrop-filter` 后卡片内文字变虚、对比度掉到 4.5:1 以下 → **停**，给我两档（模糊 20px / 12px）截图；
- 若 `backdrop-filter` 与卡片的 `transform: perspective(...)` 指针视差冲突导致模糊错位 → **停**，先报现象，不要擅自砍掉视差或模糊其中之一；
- 若扫光改成"只在匹配时出现"后，匹配态看不出任何变化（因为卡片已经变蓝）→ **停**，先给两个方案（保留匹配扫光 / 干脆去掉扫光）；
- 若 × 缩到 32×32 后你自己觉得难点 → 报告里注明，我再决定是否放宽到 36×36，**不要擅自放大**；
- 若要实现 `conic-gradient` 只在 1px 环上必须引入 `mask-composite` 而这台机器的浏览器不支持 → **停**，给出替代方案（双层元素）再动手。
