# P47-普通模式输入放开：自由跳行 + 够字自动跳 + 退格自动回跳

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。改 **`public/typing-engine.js`（比赛页）** + **`public/script.js`（练习页自己那套状态机）** + 必要的 `public/style.css`。**不用重启。**

## 0. 设计四问

| 问题 | 回答 |
| --- | --- |
| **怎么分类** | 不是新模块，是**共用打字引擎的输入行为**改造。练习页与比赛（普通文章）都用 `typing-engine.js`；**代码模式用 `code-typing.js`，本批不动** |
| **怎么设计** | 从「串行强制：必须把当前行一字不差打完才能走」改成「**可自由跳行 + 够字数自动跳 + 退格自动回跳 + 任意行可回改**」。正确率本来就只统计「已输入字符」（`pending` 不计入分母），所以放开后正确率才真正有意义 |
| **怎么做** | 取消非当前行输入框的 `disabled`；`charStates` 按行重算；行填满（`value.length >= 段字符数`）即自动聚焦下一行（不判断对错）；行首 Backspace → 焦点跳到上一行末尾；全部行填满才算完成 |
| **是否有真实参考** | 有：多数在线打字站点允许行间自由移动与回改（如 typing.com / 各类考级练习系统）。本项目不引任何库，纯改引擎事件与状态机 |

## 0.1 现状补充（执行方发现，已确认，按方案 1 执行）

我核实过：**练习页与比赛页用的是两套不同的状态机**，两处都要改。

| 页面 | 实际实现 | 本次要改的位置 |
| --- | --- | --- |
| 比赛页（`race.html`） | 完整使用 `typing-engine.js`（`TypingEngine.create()`），DOM 也由它建 | `typing-engine.js` |
| **练习页（`index.html`）** | **`script.js` 自己的状态机**：只借用 `TypingEngine.splitTextWithOffsets / measureMaxLen / splitTextIntoSegments` 做分段，DOM 与输入逻辑都在 `script.js`（`startPractice` ~755、`buildSegments` ~998、`updateSegmentStates` ~1067、`handleSegmentInput` ~1128、自动前进判定 ~1169–1178、`segmentInputs.forEach(input => input.disabled = true)` ~1251） | **`script.js`** |

**决定：两套都改，行为必须完全一致（同一张规则表 R1–R9）。**

| 约束 | 说明 |
| --- | --- |
| 不做架构迁移 | **不要**把练习页整体迁到 `typing-engine.js`（那是重构，`script.js` 里统计、结算、上报、`charStates`、`getSegmentStartOffset` 都深度耦合，风险远大于收益） |
| 规则单一来源（推荐） | 把“是否该自动前进 / 是否该回跳”的纯判断抽成小函数放进 `typing-engine.js` 并挂到 `window.TypingEngine`（例如 `shouldAdvance(value, segLen)`、`shouldJumpBack(input)`），两处共用，避免两套规则日后漂移；若抽出来别扭，就各自实现，但**必须在报告里用同一张规则表逐条对照说明两边一致** |
| 验收两边都要跑 | §3 的第 1–5 条**练习页与比赛页各跑一遍**（共两组读数） |
## 1. 用户原话

> 「现在的普通模式输入似乎有点限制太死了？设计成可以自由跳行等　自动跳行判断字数够就可以跳行　并且删除的话也要可以自动跳回去　不然现在的正确率这些设计没啥用」

现状（`typing-engine.js`）：

| 位置 | 现状 | 后果 |
| --- | --- | --- |
| 约 392 行 | `input.disabled = index !== currentIndex \|\| !enabled \|\| finished` | 只有当前行能输入，**点其它行没反应** |
| 约 467–470 行 | `allCorrect = segment.split('').every(...)` 全对才 `currentIndex++` | **打错一个字就卡在这一行**，必须删干净才能过 |
| 约 449 行 | `if (index !== currentIndex) return;` | 非当前行的输入一律忽略，行间无法移动 |
| 退格 | 行首按退格无特殊处理 | 不能回到上一行改字 |

## 2. 目标行为（按下面实现，边界都写清）

| # | 规则 |
| --- | --- |
| R1 | **自由跳行**：所有行的 `.typing-line-input` 都**不再 disabled**（仅 `!enabled` 或已 `finished` 时整批禁用）；点击任意行即可在该行输入，`currentIndex` 跟随**最后获得焦点的那一行** |
| R2 | **够字自动跳**：当前行输入长度 `value.length >= 段字符数` 时，自动把焦点移到**下一行**（`selectionStart` 放到下一行末尾），**不判断对错**；最后一行填满时若前面仍有未满的行，焦点跳到**第一个未满的行**，并给一条轻提示（`#typing-line-hint` 之类，写「还有 N 行没打完」即可，2 秒淡出，不加弹窗） |
| R3 | **退格自动回跳**：在某行 `selectionStart === 0 && selectionEnd === 0` 时按 `Backspace`，把焦点移到**上一行的末尾**（`selectionStart = selectionEnd = 上一行 value.length`），**不删除上一行任何字符**；用户再按一次 Backspace 才开始删上一行 |
| R4 | **任意行可回改**：任何行（含已完成行）都可编辑；每次 input 只重算**该行**的 `charStates`（`correct / wrong / pending`），不整篇重算 |
| R5 | **完成条件**：从「当前行全对」改为「**所有行都填满**」（每行 `value.length >= 段字符数`）。全部填满→ `finished = true` → `emit(true)` → `onFinish(state())`（保持现有回调签名） |
| R6 | **进度统计不变**：`state().typed` = 各行 `value.length` 之和；`correct / wrong` 仍按逐字比对；`accuracy = correct / (correct + wrong)`，**未输入的字符不计入分母** |
| R7 | **方向键**：`↑ / ↓` 在当前行时把焦点移到上/下一行（位置 clamp 到该行长度），不改变任何内容（可选但建议加，方便键盘党） |
| R8 | **不动的**：禁止粘贴（`paste` 仍拦截）、`sanitize`/字符归一化逻辑、`codePointAdvance` 的码点处理、`code-typing.js`、比赛服务端接口 |
| R9 | **视觉**：非当前行不再变灰（原本 `:disabled` 的样式只在整批禁用时出现）；当前聚焦行仍由 `:focus` 高亮即可；`.typing-page.completed` 的绿底保留（判定条件按 R6 的“该行填满”来设置，不再依赖 `index < currentIndex`） |

## 3. 验收（逐条贴读数，练习页 + 比赛页各走一遍）

| # | 场景 | 判据 |
| --- | --- | --- |
| 1 | **自由跳行** | 打开一篇 5 段的文章，直接点**第 3 行**输入 5 个字符：该行 `value.length = 5`、`document.activeElement` 是第 3 行的 input、第 1 行仍是 0（贴三项） |
| 2 | **打错也能过行** | 在第 1 行故意打错 2 个字，把该行**打满**（长度达到段字符数）：焦点**自动跳到第 2 行**（贴 `activeElement` 的父 `.typing-page` 索引与第 1 行 `value.length`） |
| 3 | **退格回跳** | 在第 2 行行首（`selectionStart=0`）按一次 Backspace：焦点回到**第 1 行末尾**（`selectionStart = 第1行长度`），第 1 行字符数**未变化**；再按一次 → 第 1 行少 1 个字符（贴三次读数） |
| 4 | **回改修正后正确率回升** | 第 1 行先打错 2 字（记录 `state().accuracy` 与 `wrong`）→ 删掉重打正确 → `wrong` 归 0、`accuracy` 升到 100（贴前后各一组） |
| 5 | **完成条件** | 只在**所有行都填满**时触发结算：故意留最后一行差 1 个字 → 不结算；补上该字 → 立即结算（贴两次 `finished`/结算出现情况） |
| 6 | **比赛同样生效** | 比赛（普通文章局）里：点第 2 行能输入；第 1 行打满自动跳第 2 行；`tick` 上报的 `progress` 与 `state().typed` 一致（贴一次请求体与响应里的 `progress`） |
| 7 | **比赛回退不虚高** | 回退删除 3 个字符后：`state().typed` 减少 3；服务端 `progress` 仍为历史最大值（贴两次 tick 读数，说明取 max 是既有行为） |
| 8 | **代码模式不受影响** | 练习页切「代码模式」：输入、Tab 缩进、回车、禁粘贴行为与改动前一致（贴一条读数 + 截图） |
| 9 | 回归 | 粘贴仍被拦截（`paste` 事件被阻止，贴 `prevented` 值）；中文输入法输入不乱序（贴一段含中文的输入结果）；`node --check public/typing-engine.js` 无输出；控制台 0 错误 |

## 5. 停止点

- 若「所有行填满才算完成」会导致**比赛无法结束**（例如有人一直留着某行不打）→ 这是预期行为（比赛有时间上限兜底），但你要在报告里确认：`idle` 到时间上限时服务端能正常结束本局；
- 若取消 `disabled` 后**手机端**软键盘弹出行为异常（每行都能弹键盘导致滚动跳动）→ 停，先报截图，我决定是否只在桌面端放开自由跳行；
- 若 `R3` 与「行内选择删除」冲突（有选区时按 Backspace 必须只删选区）→ 先保证：**有选区时不回跳**，只执行普通删除；
- 若引擎被比赛观战的迷你条复用（`setMiniContent` 不经过引擎）→ 确认无需同步改动，报告里说明；
- 若 `script.js` 里放开 `disabled` 后，练习页的**计时/正确率/结算**出现统计错位（`cachedCorrect/cachedWrong`、`prevInputValue` 那套缓存）→ 停，先报你准备怎么保持缓存与 `charStates` 一致，别硬改。
