# P35.4-代码编辑器“输入态不显示代码”修复（CSS 优先级）

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。**只改 `public/style.css` 的代码编辑器段**（预计 3–6 行），不碰 JS 逻辑。
> 用户原话：「输入态还是不显示代码啊 跟 HTML 的效果差远了」

## 0. 根因（我已定位到具体规则）

用户看到的：行号 1–5 有、光标有，**代码文字全黑不可见**；而原型 `design/code-mode-prototype.html` 里文字正常。

我用 CDP `CSS.getMatchedStylesForNode` 取到 `.code-input` 的**全部命中规则**，最后一条生效的是：

```css
select:focus, input[type="text"]:focus, ..., textarea:focus {   /* style.css:527 附近的全局表单聚焦规则 */
  background: var(--canvas-soft);   /* 深色主题下 = #1e1e1c */
}
```

对比读数：

| 项 | 读数 |
| --- | --- |
| `.code-input` 未聚焦时 | `background = transparent` ✓ |
| `.code-input` **聚焦后** | `background = rgb(30, 30, 28)`（`--canvas-soft`）✗ |
| 层级 | 输入层 `z-index:2` 在 ghost(`z-index:1`) 之上 |
| 结果 | 输入层一聚焦就把底下 ghost 原文**整块盖住** |

**特异性之争**：`.code-input`（0,1,0）输给 `textarea:focus`（0,1,1）。所以肉眼表现是「一开始还好，一聚焦/一输入就没了」。

## 1. 要改什么

| # | 要求 |

## 4. 停止点

- 若覆盖 `.code-input:focus` 会连带影响别的 textarea → **停**，先报（应当不会，选择器是限定的）；
- 若发现还有第三处规则在注入背景 → **停**，把 `CSS.getMatchedStylesForNode` 的完整列表贴出来；
- 若修完仍有字符看不见（说明不只是背景问题）→ **停**，贴聚焦后 `.ch-pending` 与 `.ch-ok` 的 `color` 计算值与 ghost 层级快照。
