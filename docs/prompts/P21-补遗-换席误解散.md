# P21-补遗（换席被误解散的修复 + 结束原因文案）

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> **这是 P21 的补充要求，不是新批次**：请在 P21 的 A 组/前端部分一并交付，报告里单列一节「补遗项」。
> 用户实测：「房主进入观战席提示房间已解散」。

## 0. 我复跑过的事实（先看，别重复走弯路）

| 环境 | 操作 | 结果 |
| --- | --- | --- |
| **P20 提交态**（`c765409`） | 房主建房（唯一选手）→ `POST /api/race/spectate/self {action:"enter"}` → 再 `tick` | `seat:"spectator"`、`status:"waiting"`、`players:0`、**房间仍在列表**、**服务端无取消日志** |
| **当前工作区**（含 P21 未提交改动） | 同上 | 结论相同：`status:"waiting"`、`cancelledReason:null`、无取消日志 |

**所以"进观战席"这个接口本身不会解散房间。** 用户看到的「房间已解散」只能来自这两条路径之一：

1. **按钮/事件串位**：P21 新增的顶部「退出比赛」在"房主 + waiting"态配置为 **`confirm: "退出并解散"` → `leaveRoom()` → 服务端 `host_leave` → `cancelRoom`**。一旦这个事件被换席按钮或焦点误触发，房间就真的被解散了，下一个 tick 便返回 `cancelled` → 前端 toast「房间已解散」。
2. **文案误导**：`race.js` 的 cancelled 分支只区分了 `admin`，其它原因（`host_leave` / `host_disconnect` / `all_left` / `time_limit` / `dissolve_direct` / `vote_dissolved` / `all_disconnected`）全部显示同一句「房间已解散」，用户无法判断是谁、因为什么解散的。

## 1. A 组：换席与退出彻底解耦（`public/race.js` / `public/race.html`）

| # | 要求 |
| --- | --- |
| A1 | 「进入/回到观战席」与顶部「退出比赛」必须是**两个独立按钮、独立事件**，不得共用一个 handler，也不得在换席成功回调里调用 `leaveRoom()` / `confirmExitRace()` / `backToLobby()` |
| A2 | 换席成功后**只**做两件事：刷新快照（`tick()`）与重渲染；**禁止**清 `state.code`、禁止清 `localStorage.lastRaceCode`、禁止跳大厅 |
| A3 | 顶部按钮的文案与行为按"身份 + 席位 + 阶段"判定。**房主在等待阶段按的不是"退出"，而是"解散"**——按钮上就要写出来，别让房主以为自己只是离开：

| 身份 / 席位 / 阶段 | 顶部按钮文案 | 点击后行为 | 二次确认 |
| --- | --- | --- | --- |
| **房主 + 选手席 + waiting** | **「解散房间」**（危险色） | 调 `leave` → 服务端 `cancelRoom("host_leave")` | 标题「解散房间」，正文「你是房主，解散后**所有选手会被请回大厅**，本局不产生成绩。」，确认按钮「**解散房间**」 |
| **房主 + 观战席 + waiting** | 「回到选手席」 | 调 `spectate/self {action:"leave"}`，**不解散** | 无（直接执行） |
| 选手 + 选手席 + waiting | 「退出比赛」 | 调 `leave` | 正文「退出后本局不再保留你的席位。」 |
| 选手 / 观战者 + 观战席 + waiting | 「回到选手席」 | 调 `spectate/self {action:"leave"}` | 无 |
| 非房主观战者（任意阶段） | 「退出观战」 | 调 `leave` | 正文「退出后不再占用观战席，比赛照常进行。」 |
| 房主 / 选手 + countdown / racing | 「退出比赛」 | 调 `leave`（房主由服务端**转移房主**，房间继续） | 正文「比赛已开始，退出后本局记为**中途退出**…」 |
| finished | 「退出」 | 调 `leave` | 正文「返回大厅并关闭本房间。」 |

> 关键点：**只有"房主 + waiting"这一格的文案是「解散房间」且用危险色**；同一颗按钮在其它格子仍是「退出…」。房主在 `countdown`/`racing` 退出**不会**解散房间（房主身份转移），所以那时写「退出比赛」是对的。

| A4 | 换席按钮与顶部按钮在 DOM 上至少相隔一个容器，且 `id` 不同；给换席按钮加 `data-action="seat-switch"`，退出按钮加 `data-action="exit-race"`，便于回归测试定位 |
| A5 | 换席接口返回 400（如 `观战由房主安排`、`观战席已满`）时，**只 toast 错误文案**，不得触发任何退出/跳转逻辑 |
| A6 | 房主在观战席时若点「开始比赛」，仍按既有逻辑校验"没有选手，无法开始"，不得顺带解散房间 |

## 2. B 组：结束原因文案映射（`public/race.js`）

把 cancelled 分支改成按 `snap.race.cancelledReason` 映射：

| `cancelledReason` | toast 文案 |
| --- | --- |
| `host_leave` | 房主已解散房间 |
| `host_disconnect` | 房主长时间离线，房间已解散 |
| `all_left` | 选手都已离开，房间已结束 |
| `all_disconnected` | 所有选手离线，房间已结束 |
| `time_limit` | 比赛超时，已结束 |
| `dissolve_direct` | 房主已解散本局 |
| `vote_dissolved` | 解散投票已通过，本局结束 |
| `admin` | 管理员已解散房间 |
| 其它 / 空 | 房间已结束 |

| # | 要求 |
| --- | --- |
| B1 | 文案集中在一个小映射对象里，缺失原因走兜底，不许写成一串 if |
| B2 | 观战者与选手看到**同一句**（不因身份不同而变） |
| B3 | 不得改动其它 toast 的文案与位置 |

## 3. 验收（逐条贴读数）

| # | 场景 | 判据 |
| --- | --- | --- |
| 1 | 房主（唯一选手）点「进入观战席」 | 换席 200；随后 tick `status="waiting"`、`cancelledReason=null`；**房间仍在公开列表**；服务端日志**无**「房间取消」行 |
| 2 | 房主在观战席时的顶部按钮 | 文案是「**回到选手席**」（不是「解散房间」「退出并解散」）；点击后 `mySeat="player"`、房间仍 waiting |
| 2b | 房主在等待厅的顶部按钮 | 文案是「**解散房间**」且为危险色（贴 `textContent` 与 `color` 计算值）；确认弹窗标题「解散房间」、确认按钮也是「解散房间」；取消后房间不变 |
| 2c | 同按钮的阶段切换 | 房主开赛（`countdown`）后同一按钮文案变为「退出比赛」并确认「退出不会解散房间」；贴两阶段文案对照 |
| 3 | 房主点顶部「退出比赛」并确认 | 房间 `cancelledReason="host_leave"`；**所有人看到的 toast 是「房主已解散房间」**，不再是笼统的「房间已解散」 |
| 4 | 事件隔离 | 点换席按钮后，`localStorage.lastRaceCode` 仍存在、`state.code` 未清空、URL 仍在 `race.html?code=…` |
| 5 | 三种解散原因 | 分别制造 `admin` / `vote_dissolved` / `all_disconnected`（或用管理端/tick 构造），逐个贴 toast 文案 |
| 6 | 回归 | 选手准备、开始比赛、观战者导播台、退出观战（离开房间）四项行为不变 |

## 5. 停止点

- 若"房主在观战席时保持房主权限"与 A3 的按钮文案冲突（例如房主在观战席还需要"开始比赛"按钮）→ 保留开始按钮，只改顶部退出按钮语义，别删功能；
- 若"解散房间"与 P21 H 组的"解散投票"按钮位置冲突 → 房主在 waiting 且选手数 ≥3 时，**同时**显示「解散房间」与「发起解散投票」两个入口会让房主困惑：按 H 组规则，≥3 人必须走投票，因此"解散房间"直解在这种情况下应**不可见**（只保留「发起解散投票」），<3 人时才显示「解散房间」；这条以 H 组为准，先读 H 组规则再实现；
- 若发现换席接口回执里 `status` 已是 `cancelled`（即服务端真的取消了）→ 停，把请求/响应原文贴出来，说明是服务端问题而不是事件串位。
