## 2. B 组：分段算法重写（必修）

### 2.1 单一实现

把分段函数收进 `public/typing-engine.js` 并导出（`window.TypingEngine.splitTextIntoSegments`）；**首页 `script.js` 改为调用同一个函数**（只把函数体换掉，渲染逻辑不动）。迁移后全仓只允许一份实现（`grep -rn "function splitTextIntoSegments"` 只命中 typing-engine.js）。

### 2.2 算法规则（按优先级，从上到下第一个可用者胜）

```text
输入：text（原文），maxLen（默认 32）
输出：段数组，拼接后必须 === 原文（除每段右端 trim 掉的空白外，不得丢字）

1. 先按硬换行 \n 切块：换行是硬边界，段内不得跨行
2. 在块内找断点，候选按优先级：
   a. 句末标点：。！？…．；英文 . ! ? 且其后是空白或块尾
   b. 逗号类：，、；：, ; : 其后可选空白
   c. 空白：空格 / Tab
   d. 拉丁词边界：若必须硬切，且切点落在 [A-Za-z0-9_'’-] 组成的词内部，则退到该词起点
   e. 以上都无 → 硬切 maxLen（不得切开代理对/组合字符）
3. 断点位置约束（违反则向前回退再找）：
   - 断点后（即下一段开头）不得是：，。！？、；：）】》”’ 等收尾标点
   - 断点前（即本段结尾）不得是：（【《“‘ 等开括号或连接符
   - 本段长度不得 < minLen（minLen = ceil(maxLen × 0.6)），否则把剩余内容并入本段
4. 每段右端 trim 空白；段内空白保留
5. 最后一段不足 minLen 且不是唯一段时，并入前一段（避免孤行）
```

### 2.3 必须给出的回归样例

用生产库里的这篇 281 字文章（标题「Token(词元)是什么」，内容首行 `Token (词元)`）作为固定样例，在报告里贴出**改造前后**的分段对照表（段号 / 长度 / 内容），并说明每处改善对应哪条规则。

额外构造 6 条边界用例并贴结果：① 连续英文长词（如 50 个字母）② 只有标点没有空白的中文长句 ③ 段尾正好落在开括号 ④ 段首正好落在收尾标点 ⑤ 含 `\n\n` 空行 ⑥ 最后只剩 2 个字。

### 2.4 B 组验收

| 检查 | 判据 |
| --- | --- |
| 不丢字 | 各段拼接（去掉右端 trim）=== 原文；长度合计与原文字数一致（差值为 trim 掉的空白数，需说明） |
| 行首规则 | 抽样 20 段：无一段以 `，。！？、；：）】》` 开头 |
| 行尾规则 | 抽样 20 段：无一段以 `（【《“‘` 或空白结尾 |
| 英文不断词 | 英文长词用例中，切割点不在词内 |
| 孤行 | 无长度 < minLen 的段（最后一段并入后仍需满足） |
| 单一实现 | 首页与比赛页对同一文章的分段逐段相同 |
