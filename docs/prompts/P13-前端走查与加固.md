P12.5–P12.7 的 `public/race.html`、`public/race.js`、`public/typing-engine.js`、`public/nav.js`、比赛相关样式，以及 `server.js` 的观战段，**都是规划侧直接改的**（见 `docs/reports/角色切换登记.md`）。只有一双眼睛，已经漏了两个浏览器端 bug。本批就是补上「查与改分开」。

## 1. 已知并已修的两个 bug（请核对同类是否还有）

### 1.1 首页卡在「正在加载」

| 项 | 内容 |
| --- | --- |
| 现象 | 打开 `index.html` 后加载遮罩一直不消失 |
| 根因 A | `nav.js` 原来只在**未登录**时渲染 `div#auth-area`、登录后只渲染 `div#user-area`；而 `script.js` 在**顶层**就执行 `loginBtn.addEventListener(...)` 等语句，元素为 `null` → 整个脚本中止 → 后面的 `init()` 与 5 秒兜底 `setTimeout(hideLoadingOverlay, 5000)` 都不会执行 |
| 根因 B | 重构导航时丢掉了三个 id：`submit-article-btn`（首页）、`nav-username`（个人中心）、`admin-username`（管理面板）；三处脚本直接取 `.style` → 同样 TypeError |
| 已修 | `nav.js` 现在**永远渲染** `auth-area` 与 `user-area`（自己按登录态设 display），并补回上述三个 id；另加一个全局守卫：页面脚本抛错时隐藏加载遮罩并在底部显示「页面脚本出错」提示条（失败要可见，不许静默卡住） |

### 1.2 顶层导航四页不一致（坑库 K-27）

已抽出 `public/nav.js` 单点渲染（`div#site-nav` 占位 + `display:contents` 保住 sticky）。四个页面只保留挂载点。
