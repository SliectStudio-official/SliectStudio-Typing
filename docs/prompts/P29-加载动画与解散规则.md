## 1. A 件：全站全屏加载动画

### 1.1 现状

| 项 | 事实 |
| --- | --- |
| 只有 `index.html` 有 | `#page-loading-overlay` **只存在于 `public/index.html`**，样式还写在该页 `<head>` 的**内联 `<style>`** 里（`style.css` 里没有对应规则） |
| 隐藏逻辑 | `public/script.js` 的 `hideLoadingOverlay()`：加 `.hidden` → 300ms 后 `remove()` |
| 其它页 | `race.html` / `profile.html` / `admin.html` / `home.html` **全都没有** |

### 1.2 要求

| # | 要求 |
| --- | --- |
| A1 | 抽成**共享模块** `public/page-loading.js`：立即把 overlay 节点注入 `document.documentElement`（不依赖各页 HTML 结构），并暴露 `window.PageLoading = { done(), fail(msg) }` |
| A2 | 样式从 `index.html` 的内联 `<style>` **搬到 `public/style.css`**（`.page-loading-overlay` / `.page-loading-spinner` / `.page-loading-text` / `.hidden`），保留原视觉：全屏、`z-index: 9999`、品牌色转圈 + 一行文字（如「加载中…」） |
| A3 | **五个页面全部接入**：`index.html`、`race.html`、`profile.html`、`admin.html`、`home.html`。脚本必须在 `<head>` 里**同步**引入（不带 `defer`/`async`）且**排在其它脚本之前**，保证第一帧就有遮罩，不能先闪出半成品页面 |
| A4 | **加载完成才消失**：各页初始化完成时调 `PageLoading.done()`，具体时机见下表 | A5 | **兜底**：`window.load` 之后最多再等 **1200ms** 强制 `done()`，任何单页接口挂住都不能把用户永久锁在遮罩里；失败时 `fail(msg)` 显示一行错误文案 + 5 秒后自动隐藏 |
| A6 | **不重复遮罩**：同一页内多次调用 `done()` 幂等；SPA 式的视图切换（如比赛页 lobby↔room↔race）**不要**再弹遮罩 |
| A7 | 淡出 300ms 后 `remove()` 节点；淡出期间 `pointer-events: none`，不得挡住点击 |
| A8 | `service-worker.js` 的 `CRITICAL_ASSETS` 增加 `/page-loading.js`，保证离线首屏也有 |
| A9 | 指纹：`page-loading.js` 必须走 `?v=` 指纹（现有机制只覆盖 `public/` 根目录 `.js`，放根目录即可） |


**A4 各页 `PageLoading.done()` 的时机**

| 页面 | 完成判据 |
| --- | --- |
| `index.html` | 文章列表首次渲染完成（沿用现有 `hideLoadingOverlay` 的调用点） |
| `race.html` | 房间列表 / 当前房间状态首次渲染完成 |
| `profile.html` | 个人信息与历史首屏数据到位 |
| `admin.html` | 仪表盘首屏统计到位 |
| `home.html` | `/api/user/profile`、`/api/user/stats`、`/api/user/race-stats`、`/api/version` 全部返回（成功或失败）之后 |

## 2. B 件：解散比赛的门槛整套重写

### 2.1 新规则（用户口径）

| 情形 | 结果 |
| --- | --- |
| 房间人数 **≤ 3**，**无人掉线** | 需 **全票通过**（每个人都有票且都同意）才解散 |
| **3 人**，**1 人掉线** | **2 票**通过即可（在线的两人都同意） |
| **2 人**，**1 人掉线** | **可以直接解散**（在线那一人确认即生效，不需要投票） |
| 房间人数 **≥ 4** | 沿用原规则：**超过半数**，即 `needed = floor(在线人数 / 2) + 1` |
| **匹配房**（`matchmade === true`） | **一律不能解散**，只能退出（P26 已实现，本批复核） |

### 2.2 口径需要固定下来的三件事（我拍了默认值，你别自己改）

| # | 项 | 默认 |
| --- | --- |
| B0.1 | **"在线"的定义** | `now - player.lastSeen <= 45000`（45 秒）；掉线者**不计票、不进分母**。这个阈值独立于 P21 B 的离线结束阈值（那是 60/30/120s），只用于解散投票 |
| B0.2 | **3 人掉 2 人**（只剩 1 人在线） | 按"2 人掉 1 人"同理，**直接解散**（剩下一人确认即生效） |
| B0.3 | 掉线者**中途回来** | 门槛**立即重算**（可能从"全票"恢复成"多数"）；已达成的解散不可撤回 |

### 2.3 服务端实现

| # | 要求 |
| --- | --- |
| B1 | 新常量 `RACE_VOTE_ONLINE_MS = 45 * 1000`；新增 `onlinePlayers(room)` 返回在线选手列表 |
| B2 | 新增 `dissolveRule(room)` 统一算出 `{ mode: "direct" \| "vote", needed, online, total }`：按 §2.1 四条 + §2.2 两条，**一处实现，所有端点复用** |
| B3 | `POST /api/race/dissolve/start`：先 `dissolveRule`——`mode === "direct"` → 直接 `cancelRoom(room, "dissolve_direct")` 并返回 `{ result:"cancelled", reason:"dissolve_direct" }`；`mode === "vote"` → 建房内投票，`needed` 用算出来的值，房主发起即计自己 1 票 |
| B4 | `POST /api/race/dissolve/vote`：投票后即时用 `dissolveRule` 重算并判断 `agreed >= needed`；**掉线导致的门槛下降也要能即时通过**——所以在 `/api/race/tick` 与 `cleanupRooms()` 里各加一次"若 `room.dissolve` 存在则重算并可能结算"的幂等检查 |

## 4. 停止点

- 若"全票"在 3 人房里因为房主自己算一票导致实际只需再 2 票就通过 → **停**：按"全票 = 所有在线选手都同意"实现，房主那一票只是其中一票，不是额外特权；
- 若 45 秒在线阈值与 P21 B 的 60/30/120s 冲突让你想统一成一个常量 → **停**，先报，两者语义不同（一个判"能不能投"，一个判"是否结束房间"）；
- 若共享 loading 模块需要改五个页面的初始化顺序 → **停**，先报影响面（`index.html` 的 `hideLoadingOverlay` 是有调用点的，别破坏离线分支）；
- 若"直接解散"情形下还想给掉线者一个恢复窗口（比如等 10 秒）→ **停**，那属于改规则，本批按用户口径立即生效。
