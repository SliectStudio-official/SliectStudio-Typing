# P17-头像上传：5MB 限制与二次裁剪确认

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。两组：A 后端限制与兜底、B 前端裁剪确认框。用户要求：**图片小于 5MB**、**上传后要弹二次裁剪框确认是否裁切**。

## 0. 现状（已定位）

| 位置 | 现在 |
| --- | --- |
| `server.js:193-211` | `multer.diskStorage` 存到 `public/avatars`，文件名 `<userId>_<时间戳><原扩展名>`；`limits.fileSize = 2MB`；`fileFilter` 只放 `.jpg/.jpeg/.png/.gif` |

## 1. A 组：后端限制与兜底

| # | 要求 |
| --- | --- |
| A1 | `limits.fileSize` 改为 **5 * 1024 * 1024**（5MB） |
| A2 | `fileFilter` 白名单改为 `.jpg / .jpeg / .png / .webp`，**移除 .gif**（裁剪产物是静态图，动图与裁剪语义冲突）；错误文案改为「仅支持 JPG/PNG/WebP 格式」 |
| A3 | 超限错误单独识别：multer 抛 `LIMIT_FILE_SIZE` 时返回 400 且文案精确为「图片不能超过 5MB」，不要复用笼统的「上传失败」 |
| A4 | 保留原有「删旧头像文件 + 更新 users.avatar」逻辑，不改存储路径与命名规则 |
| A5 | 服务端**不做缩放/裁剪**（无 sharp/jimp 等依赖可用）；前端产物已是 256×256，服务端只做大小与类型兜底 |
| A6 | 若上传文件名缺失扩展名（`req.file.originalname` 无后缀），按 mime 推导扩展名（`image/jpeg→.jpg`、`image/png→.png`、`image/webp→.webp`），不得落成无后缀文件 |

A 组验收（用 `curl` 直接打接口，绕过前端）：

| 场景 | 期望 |
| --- | --- |
| 6MB 的 jpg | 400，文案「图片不能超过 5MB」 |
| 4.9MB 的 png | 200，文件落盘，`users.avatar` 更新，旧文件被删 |
| `.gif` | 400「仅支持 JPG/PNG/WebP 格式」 |
| `.txt` 改名成 `.png` | 后端按扩展名放行即可（不要求做魔数校验），但要在报告里写明这是已知边界 |
| 无扩展名的 webp | 200，落盘文件名带 `.webp` |

## 2. B 组：前端二次裁剪确认框

### 2.1 流程

```
选择文件 → 校验大小(≤5MB)与类型 → 打开裁剪弹窗 →
  ├ 取消 → 关闭，不上传，头像不变
  ├ 重新选择 → 回到文件选择（清空 input.value 以便重选同一文件）
  └ 确认裁剪 → canvas 导出 256×256 → 以 Blob 上传 → 成功后刷新头像
```

### 2.2 要求

| # | 要求 |
| --- | --- |
| B1 | 文件选择后**先本地校验**：`file.size > 5 * 1024 * 1024` → 立即提示「图片不能超过 5MB（当前 x.x MB）」，**不发任何请求**；类型不在 `image/jpeg, image/png, image/webp` → 提示「仅支持 JPG/PNG/WebP」 |
| B2 | 裁剪弹窗：按 **1:1 正方形**裁剪，预览区用圆形遮罩（与头像展示一致）；底图为原图，可**拖动**平移、可**缩放**（滑杆或滚轮，缩放范围 1×–3×），拖动/缩放时**不得露出空白边** |
| B3 | 导出：`canvas` 尺寸 **256×256**，格式 **JPEG，质量 0.9**（体积约 20–60KB）；用 `canvas.toBlob` 生成 Blob 后以 `FormData` 的 `avatar` 字段上传 |
| B4 | 取消与关闭：点遮罩、点「取消」、按 `Esc` 都等同取消——**不发请求**、不动原头像、清空 `input.value` |
| B5 | 上传中显示状态（按钮禁用 + 「上传中…」），成功后就地刷新头像（沿用现有 `?t=` 破缓存方式），失败显示后端 `error` 文案 |
| B6 | 移动端：弹窗不超出视口；触屏可拖动、可双指或滑杆缩放（滑杆即可，双指非必需） |
| B7 | **零新依赖**：用原生 `<canvas>` + `URL.createObjectURL` 实现，禁止引 cropperjs 等库 |
| B8 | 图片方向：用 `img.decode()` 或 `createImageBitmap` 后再绘制，保证手机竖拍照片（EXIF 方向）不旋转 90° |
| B9 | 内存：关闭弹窗时 `URL.revokeObjectURL`，不得泄漏 |

### 2.3 B 组验收

| 场景 | 期望 |
| --- | --- |
| 选 6MB 图片 | 立即提示超限，Network 面板**没有任何请求** |
| 选 4.9MB 图片 | 弹出裁剪框，可拖动缩放且不露白边 |
| 点「取消」/按 Esc | 弹窗关闭、无请求、头像不变 |
| 点「确认裁剪」 | 请求体 `avatar` 为 ≤200KB 的 JPEG；成功后头像立刻变；`public/avatars` 出现 256×256 新文件，旧文件被删 |
| 上传后刷新页面 | 头像仍是新图（DB 已更新） |
| 手机竖拍照（含 EXIF） | 裁出来的头像方向正确，没有旋转 |
| 依赖检查 | `package.json` 无新增依赖；`grep -r "cropper\|Cropper"` 0 命中 |

## 4. 停止点

- 需要引依赖才能实现裁剪 → 停（原生 canvas 足够）；
- 发现 `public/avatars` 里现存头像会被误删（例如共享文件）→ 停，先报现状；
- 需要改头像展示尺寸/圆角等视觉规格 → 停，属另一批。
