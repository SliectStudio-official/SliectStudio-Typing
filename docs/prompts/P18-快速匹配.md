## 1. A 组：后端匹配队列（`server.js`）

### 1.1 数据结构

```
const matchQueue = [];              // [{ userId, username, nickname, joinedAt }]
const MATCH_QUEUE_LIMIT = 50;
const MATCH_TIMEOUT_MS = 30 * 1000;   // 仅用于给 hint
const MATCH_STALE_MS = 5 * 60 * 1000; // 超过即剔除
```

### 1.2 端点

```
POST /api/race/match/join     // authMiddleware
  → 200 { status: "waiting", waiting: 2, elapsed: 0 }
  → 400 你已在其他比赛房间中 / 队列已满，请稍后再试 / 管理员已暂停创建比赛

GET  /api/race/match/status   // authMiddleware
  → 200 { status: "idle" }
  → 200 { status: "waiting", waiting: 3, elapsed: 12400, hint?: "可继续等待，或返回大厅自建房间", roomFull?: true }
  → 200 { status: "matched", code: "ABC123" }

POST /api/race/match/cancel   // authMiddleware
  → 200 { success: true }
```

| # | 要求 |
| --- | --- |
| A1 | `join` 与 `status` 每次调用都尝试配对一次（不新增定时器/后台任务） |
| A2 | 配对：取队列最早两个**不同**用户 → 内部建房（`isPublic=0`、无密码、`maxPlayers=2`、`matchmade=true`）→ 两人入房 → 出队 → 房间置 `countdown`（`startsAt = now + 3000`） |
| A3 | 建房必须复用现有房间对象形状（`roomRegistry` 里既有代码要能直接读），不得另立结构 |
| A4 | `settings.race_max_rooms` 已满 → 不配对，`status` 返回 `roomFull:true` 并附 hint；原因只记一次日志 |
| A5 | `settings.race_enabled = false` → `join` 400「管理员已暂停创建比赛」 |
| A6 | 已在房间 → 400「你已在其他比赛房间中」；已在队列 → 幂等返回 waiting（不报错、不重复入队） |
| A7 | 队列条目超过 `MATCH_STALE_MS` 在下次配对时剔除并记日志 |
| A8 | 不改 `/api/race/create` 的密码校验；不改数据表 / `VERSION` / `CONTRACT_VERSION` |

## 2. B 组：前端匹配（不阻断）+ 全屏倒计时

### 2.1 全局底部匹配条（D8）

| # | 要求 |
| --- | --- |
| B1 | 匹配状态由 **`nav.js` 全局管理**（四页都有），这样用户在任意页面都能继续操作。标记写 `localStorage.raceMatchPending = "1"`，同时记住入队时间戳 |
| B2 | 有标记时每 **1 秒** 轮询 `/api/race/match/status`；无标记不轮询、不发请求 |
| B3 | 条固定在**屏幕底部**（`position: fixed; bottom: 0`，整宽，含安全区），左侧文案「**匹配中 00:12**」（实时秒数），右侧是「**取消**」按钮（D8 要求的关闭键），点击后调 `/api/race/match/cancel`、清标记、收起条 |
| B4 | **不阻断操作**：不得出现全屏遮罩、不得禁用页面滚动/点击/输入；不得抢焦点 |

| B6 | 等待满 30 秒后，把后端 `hint` 显示在条内（仍不自动取消）；`roomFull` 时显示对应文案并保留「取消」 |
| B7 | 收到 `status:"matched"` → 条变成「**匹配成功，正在进入比赛…**」并跳转 `race.html?code=…`；**例外**：若当前正在练习中（`#typing-pages` 有输入内容且未完成），不自动跳转，改显示「匹配成功 · 进入比赛」按钮，点击才跳转，避免打断练习 |
| B8 | 页面卸载/刷新不清标记（匹配还在继续）；只有 `matched` 跳转成功、`cancel`、或后端返回 `idle` 时才清 `raceMatchPending` |
| B9 | 420px 下条内文字与按钮不换行错位；条不遮挡页面底部关键操作（给 body 底部留出条高，或在条内加关闭后恢复） |

### 2.3 全屏 3 秒倒计时（D9）

| # | 要求 |
| --- | --- |
| B13 | 房间进入 `countdown`（`startedAt` 起 3 秒）时，显示**全屏遮罩**：`position: fixed; inset: 0`，覆盖导航与内容（`z-index` 高于 `--nav` 层），背景半透明 + 模糊，中央大号数字 **3 → 2 → 1 → GO**（数字按 tick 的 `countdownMs` 换算，不要用本地定时器自走，避免与服务端偏差） |
| B14 | 遮罩内显示文章标题与字数（「即将开始 · Token(词元)是什么 · 281 字」），并有一行「倒计时结束后自动开始打字」 |
| B15 | 数字切换用品牌色放大 + 淡出动效（复用 `--motion-base` / `--ease-out`），`prefers-reduced-motion` 下取消动效 |
| B16 | 倒计时结束（`racing`）时遮罩 200ms 内淡出，并把焦点交给第一个输入框 |

## 3. C 组：打字区一行放多少字 —— 真自适应（D10）

> 用户否决了"按断点写死字数"的方案（32/24/16），理由正确：**屏幕宽度是连续的，字数不该按断点跳变**。本组改为按实际渲染宽度量算。

### 3.1 算法

| # | 要求 |
| --- | --- |
| C1 | 用真实元素的**计算样式**量字宽：取一个已挂载的 `.typing-line-text`（或同字体同字号的临时节点），`ctx.font = getComputedStyle(el).font`，分别量 `measureText('中')` 与 `measureText('a')` 得到 CJK 宽与 ASCII 宽 |
| C2 | 取容器**内宽**（`container.clientWidth - paddingLeft - paddingRight`），留 2% 余量；逐字累加宽度直到超过可用宽度，得到本行可容纳字数 `n` |
| C3 | 夹紧到 **8 ≤ n ≤ 40**（防极窄/极宽屏幕出现 3 字一行或 60 字一行） |
| C4 | 把 `n` 作为 `maxLen` 传给 `splitTextIntoSegments` / `splitTextWithOffsets`（两者签名已支持 maxLen，默认仍为 32） |
| C5 | 重算时机：① 首次加载；② `resize` / `orientationchange`（防抖 **150ms**，宽度变化 < 24px 忽略）；③ 浏览器缩放导致 `font-size` 变化（读到的计算字号变了才重算）。**已开始打字后一律不重排**（重排会让进度与 offsets 错乱） |
| C6 | 测量失败（无 canvas 2d 上下文 / 字体未就绪）时兜底：`n = floor(可用宽度 / (fontSize * 1.0))`，再夹紧到 [8,40]；兜底不写死断点 |
| C7 | 首页与比赛页共用同一套测量逻辑（放在 `typing-engine.js` 里导出 `measureMaxLen(el)`），不要在两边各写一份 |
| C8 | 服务端 `charCount` 不变（仍是原文长度）；进度与错字一律按 offsets/原文坐标算，不得因重排跳变 |

### 3.2 说明为什么不用断点

| 方案 | 问题 |
| --- | --- |
| 按断点写死 32/24/16 | 768px 与 900px 之间、窗口拖动、浏览器缩放、系统 DPI 都会让它"要么放不下要么浪费"；且同一台机器拉一下窗口就跳变 |
| 按实际字宽量算 | 与字体、字号、缩放、容器宽度自动对齐，任何宽度都不会截断也不会浪费 |
## 4. 验收（逐条贴读数）

| # | 场景 | 判据 |
| --- | --- | --- |
| 1 | 两个登录用户同时匹配 | 10 秒内都拿到 `matched` 与同一 `code`；房间 `isPublic=0`、`maxPlayers=2`；3 秒后 `racing` |
| 2 | 单人匹配 | 条显示「匹配中 00:0x」逐秒增长；30 秒后出现 hint |
| 3 | **不阻断操作** | 排队时在首页滚动、点开文章、切到个人中心都能操作；无全屏遮罩；输入框可获得焦点 |
| 4 | 取消 | 点底部条「取消」→ `idle`、条消失、`raceMatchPending` 清除；再点匹配能重新排队 |
| 5 | 匹配成功后跳转 | 从**首页**匹配成功 → 自动跳 `race.html?code=…`；若正在练习打字 → 不跳转，显示「进入比赛」按钮 |
| 6 | 自己进房间 | 排队中手动建房成功 → 全局条自动取消并收起 |
| 7 | **全屏倒计时** | 进入 countdown 时截图/读数：遮罩 `position:fixed`、覆盖视口（宽高 = 视口）、z-index 高于导航；数字 3→2→1→GO 与 tick 一致；`racing` 后 200ms 内隐藏且焦点在第一个输入框 |
| 8 | 刷新恢复 | countdown 中刷新 → 遮罩重现且剩余秒数正确 |
| 9 | 自适应分段 | 同一 281 字文章，在 **1920 / 1440 / 1200 / 1024 / 900 / 768 / 600 / 420** 八档宽度各贴「量出的每行字数 n / 段数 / 被截断段数」；**每一档的被截断段数必须为 0**，且 n 随宽度单调变化（不是阶跃跳变） |
| 10 | 已开始不重排 | 打字开始后把窗口从 1920 拖到 420 → 分段数组与 offsets 完全不变（贴前后 JSON 一致），进度不跳变 |
| 11 | 缩放 | 浏览器 100% → 150% 缩放（或改字号令牌）后重新加载 → n 变小、仍 0 截断 |

## 6. 停止点

- 全屏倒计时会遮挡比赛输入导致无法开始 → 停，先报（正确做法是 `racing` 后立即撤遮罩）。
