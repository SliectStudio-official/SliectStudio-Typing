# P41.1-profile.js 补覆盖头（三处 PUT/DELETE 改走 apiWrite）

> 读的提示词就是本文件。开工时算本文件 sha256，写进执行报告第一行。
> 你是执行方 AI。**只改 `public/profile.js`**（约 20 行），**不用重启**。

## 0. 背景

P41 已经把**管理页**所有写请求改成 `POST + x-http-method-override`，服务端中间件也上线了（`server.js`，只认 PUT/PATCH/DELETE）。但**个人中心**还有 3 处没改，在“安全软件/代理重置 PUT·DELETE”的机器上会直接 `Failed to fetch`：

| 位置（`public/profile.js`） | 功能 | 方法 |
| --- | --- | --- |
| 约 684 | 删除自己投稿的私有文章 | `DELETE` |
| 约 1081 | 修改昵称（`/api/user/profile`） | `PUT` |
| 约 1127 | 修改密码（`/api/user/password`） | `PUT` |

## 1. 要改什么

| # | 要求 |
| --- | --- |
| A1 | 在 `public/profile.js` 里加一个与 `admin.js` **同款**的写请求封装（`apiWrite(url, options)`：`PUT`/`PATCH`/`DELETE` → 实际发 `POST` 并加 `x-http-method-override` 头；其余原样透传）。**不要**从 `admin.js` import（两页各自独立），就是复制那 10 行 |
| A2 | 上述 3 处 `fetch(...)` 改用该封装，方法字符串保持不变（仍写 `method: 'PUT'` / `'DELETE'`，由封装转换） |
| A3 | 报错文案、成功提示、二次确认（`confirm`）、刷新逻辑**一律不动** |
| A4 | 改完自查：`grep -n "await fetch(" public/profile.js` 里**不应再有** `method: 'PUT'` / `'DELETE'` 的直连调用（贴结果） |
