# 部署与更新说明

> 面向：在服务器上装/更这个站点的人。发布包只由 `node make-release.mjs` 生成，包内不含任何数据与密码文件。

## 一、包里有 / 没有

| 会覆盖的（程序本体） | **绝不会在包里的**（所以不会被覆盖） |
| --- | --- |
| `server.js`、`db-config.js`、`crawler.py`、`requirements.txt` | `data/`（数据库：`typing.db` + `-wal` + `-shm`） |
| `public/`（全部页面、脚本、样式、`icons/`、`assets/`） | `db-config.json`（含 MySQL 密码，装机时自己生成） |
| `VERSION`、`CONTRACT_VERSION`、`version.json`、`package.json`、`package-lock.json` | `launcher.config.ps1`（本机装机配置） |
| `start.bat`、`launcher.ps1`、`set-version.ps1`、`db-config.sample.json`、`README.md`、`LICENSE`、`.gitignore` | `node_modules/`（依赖，首次装机时 `npm install` 生成） |
|  | `public/avatars/`（用户上传的头像） |

打包有审计：命中 `data/`、`db-config.json`、`launcher.config.ps1`、`docs/`、`.git/`、`tmp/`、`public/avatars/` 任一项就直接失败不出包。

## 二、更新怎么做（推荐：整包覆盖）

```text
1. 停服务         关闭正在跑 node 的那个窗口（或结束监听端口的进程）
2. 备份数据库     复制 data\typing.db + data\typing.db-wal + data\typing.db-shm 到一个安全目录（三件套，缺一不可）
3. 解压覆盖       把新包解压到**原目录**，遇到同名文件选「覆盖」；不要删除目标目录，不要新建一套又一套
4. 启动           双击 start.bat（或 node server.js）
5. 验证           浏览器打开 http://localhost:3000/api/version，版本号应是新包上的版本
6. 强刷一次       Ctrl+F5（让 Service Worker 换到新缓存）
```

### 为什么是整包覆盖，而不是只换改动的文件

| 只换单个文件的后果 | 说明 |
| --- | --- |
| 指纹对不上 | 页面里 `style.css?v=xxxxxxxx` 是打包时按文件内容算的；只换 `server.js` 或只换某个 css，浏览器会拿旧缓存或请求 404 |
| 前后端版本不一致 | `server.js` 与 `public/` 是一次构建配对的，混版本会出现「接口多了字段但页面不认」这类怪事 |

**例外**：如果只是临时救火，改 `public/` 下的文件**不用重启服务**（刷新页面即可）；改 `server.js` / `db-config.js` **必须重启**，不重启等于没改。

## 三、覆盖后要不要迁移数据

| 情况 | 做法 |
| --- | --- |
| 数据规范版本 `CONTRACT_VERSION` 没变（本次 `v3` → `v3`） | **不用迁移**，直接跑；老库启动自动补齐新表 |
| 规范版本变了（例如 v3 → v4） | 升级前必须整库备份三件套，并按该版本的发行记录里的迁移说明做 |

服务启动时会核对库里的 `schema_version` 与代码的 `CONTRACT_VERSION`：**不一致直接拒绝启动**并打印双方版本（这是保护，不是故障）。

### 3.4 之后的一次性数据步骤（**不是开发机就要做**）

`3.4` 引入了「代码素材与普通文章隔离」：判定靠 `settings.code_category_ids` + 三个语言分类（`JavaScript` / `Python` / `SQL`）。
**这个数据迁移只做在开发机本机的库上**；任何其它库（含你自己的服务器）升级后要跑一次：

```text
1. 停服务
2. 在项目根目录执行：node docs\migrate\P35.2-代码分类迁移.cjs
3. 看输出：应显示建了 3 个语言分类、迁移 5 篇、写入 code_category_ids = [三个 id]
4. 启动服务，打开「管理页 → 代码模式管理 → 语言分类」，确认三个语言开关是打开的
5. 打开练习页「代码模式」，应能看到 5 篇素材；比赛页建房应出现「代码房间」tab
```

| 特性 | 说明 |
| --- | --- |
| 幂等 | 重复执行不会重复建分类、不会重复迁移（已验证：连跑两次第二次「迁移了 0 篇」） |
| 安全 | 只改 `articles.category_id` 与 `settings` 一行，不改表结构、不动 `VERSION` / `CONTRACT_VERSION` |
| 不做会怎样 | 代码模式素材为空、代码榜为空、建房没有「代码房间」tab、匹配开关不显示；普通模式的分类下拉里还会看到「代码」分类 |
## 四、回滚

| 场景 | 做法 |
| --- | --- |
| 新版本有问题 | 把上一版 `releases/LanTest-<旧版本>.zip` 按同样步骤覆盖回去（`data/` 不用动，规范没变时旧代码能直接读新库） |
| 数据被写坏 | 用第 2 步的备份**三件套整组覆盖**回去，再重启 |
| 只想退一个小改动 | 从包里单独取那一个文件覆盖。注意：`server.js` 要重启才生效 |

## 五、首次装机（不是更新）

```text
1. 解压到目标目录（例如 D:\LanTest）
2. 双击 start.bat —— 会依次：检查/安装 Node 25.3.0 → npm install → 自检 better-sqlite3 → 起服务 → 打开浏览器
3. 在**服务器本机**打开 http://localhost:3000/setup.html 创建管理员（局域网其它机器不能建，这是防抢占设计）
4. 之后局域网访问 http://<服务器IP>:3000
```

> 全新机器若 `better-sqlite3` 无 ABI 141 预编译包，需要装 Visual Studio Build Tools（`launcher.ps1` 会明确提示，不会静默继续）。离线装机的完整包要带 `node-v25.3.0-x64.msi`（`node make-release.mjs --with-node-msi`）。

## 六、更新前后各一次备份（别省）

| 步骤 | 命令要点 |
| --- | --- |
| 备份 | 复制 `data/typing.db`、`typing.db-wal`、`typing.db-shm` **三件**；只拷主库会让服务读成旧规范版本而拒绝启动 |
| 校验 | 打开备份目录里的副本确认能读（有 `schema_version` 且与 `CONTRACT_VERSION` 一致） |
