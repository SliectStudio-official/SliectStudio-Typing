# 代码模式可行性评估（设计四问）

> 触发：用户提出「让用户练习打代码」。本文件只做判断与方案，不含实现。
> 日期：2026-11-08 · 规划侧

## 一、四问

### 1. 怎么分类

| 项 | 结论 |
| --- | --- |
| 属哪类 | 练习内容侧的**专项模式**，不是新模块 |
| 落点 | 练习页（`index.html` / `script.js`）加一个「代码模式」筛选；数据侧复用现有 `categories` |
| 表结构 | **不需要改**。库里已经有 `categories` 名为「代码」的分类（id=3） |
| 依赖 | **不需要新增** |

### 2. 怎么设计（关键事实：我实测过）

| 事实 | 读数 / 结论 |
| --- | --- |
| 引擎已支持多行文本 | `splitTextWithOffsets` 按 `\r?\n` 切块；一段 8 行 JS 在每行 16/24/32 字下分别切成 11/10/8 段，全部合法 |
| 换行不要用户按回车 | 段间空白被 trim（130 字符原文切完拼回 122–123），**行尾回车不算输入** |
| 行首缩进**要用户打空格** | 段内保留 `  let total = 0;` 的前导空格 → 这是唯一的真实摩擦点 |
| 现有文章库 | approved 仅 **3 篇**（72 / 245 / 281 字），`代码` 分类下 **0 篇** |
| 成绩字段 | `scores.source` 现有值 `normal` / `race`，加代码成绩**不必改结构** |

### 3. 怎么做（最小可行方案）

| # | 内容 | 工作量 |
| --- | --- | --- |
| 1 | 素材：3–5 篇入门级片段（每篇 ≤200 字，2 空格缩进，**禁止 Tab**），挂到「代码」分类 | 内容为主，非代码 |
| 2 | 引擎加一个选项 `stripLineIndent`：切段时**跳过每段行首连续空白**，offset 相应前移（逐字符恒等式仍成立） | 小（约 15 行） |
| 3 | 练习页加「代码模式」开关：只列 `代码` 分类的文章；开启时结算卡片标注「代码专项」 | 小 |
| 4 | 榜单：`/api/leaderboard` 支持 `?category=` 过滤，代码成绩进「代码榜」，默认总榜不受影响 | 小 |
| 5 | 代码片段**不做语法高亮**（保持纯文本比对）；如以后要做，另立批次 | — |

### 4. 是否有真实参考

| 参考 | 做法 | 我们取什么 |
| --- | --- | --- |
| Monkeytype | Quote 模式下有半隐藏的「语言」选项，可切到编程语言；代码模式对符号与缩进精确 | 取「**藏在专项入口里，不做默认素材**」这一点 |
| CodeRacer | 专做代码打字，按语言分榜，统计 WPM / 错误率 / 准确率 | 取「**按语言/分类分榜**」；不取它的重度 UI |

> 两条结论性经验（用户提供的判断，我同意）：代码符号密度远高于自然语言，**直接做默认素材会让大多数人挫败**。所以必须是可选专项。

## 二、我的结论与建议顺序

**可以做，成本不高**（引擎已支持多行、分类已存在、无需改表），但**不该现在排在最前**：

| 顺序 | 事项 | 理由 |
| --- | --- | --- |
| 1 | 先把**内容供给**做起来（现在全站只有 3 篇） | 内容不够时加代码模式 = 让「3 篇里 1 篇是代码」，多数人反而更难练 |
| 2 | 再上代码模式（P34 中批） | 有素材才有意义 |

## 三、需要你拍板的 3 条

| # | 问题 | 我的建议 |
| --- | --- | --- |
| C1 | **缩进口径**：要求用户打行首空格，还是**忽略行首缩进**（只打有效字符）？ | **忽略**（引擎加 `stripLineIndent`）；否则新手第一分钟就会崩 |
| C2 | 代码成绩**进不进排行榜**？ | 进**独立「代码榜」**，不进总榜（口径不同，混排不公平） |

## 五、交互定稿（用户 2026-11-08 拍板，覆盖原「分段打字」设想）

用户原话：「窗口显示的得是正确代码的格式 可以辅助用户打缩进 但是回车不帮助 就做类似 VSCode 的输入框」。

| # | 定稿 |
| --- | --- |
| 1 | **显示层是原文的正确代码格式**：保留原缩进与换行，等宽字体，**不压平、不 trim、不折行**（超宽时容器横向滚动，光标自动滚到可见处，同 VSCode） |
| 2 | **输入层是一个编辑器式输入区**（单个 `textarea` 覆盖在渐隐原文之上），不是「每行一个 input」的分段模型 |
| 3 | **缩进可辅助**：按 Tab 补齐到下一个缩进位；按 Enter 后**自动带出上一行缩进**（VSCode auto-indent） |
| 4 | **回车不辅助**：不自动跳过换行、不在行尾自动进下一行，用户必须自己按 Enter |
| 5 | 待输入文字**渐隐**（约 30% 不透明度）；已输入字符**显示用户打的字符**；正确保持中性色、错误红色 |
| 6 | **不改 `typing-engine.js`**：新写 `public/code-typing.js`（约 250–350 行），代码模式专用；普通文章继续走现有引擎 |
| 7 | 手机端**禁用代码模式**（输入法组合输入会打断逐字符判定），给一句「代码模式请在电脑上练」 |
| 8 | 代码成绩进**独立「代码榜」**（`/api/leaderboard?category=`），**不进总榜、不进比赛池** |

### 仍待确认的 3 条（有默认）

| # | 问题 | 默认 |
| --- | --- | --- |
| D3 | **自动补齐的缩进字符算不算击键**？ | 不算：既不计入「已输入」分母，也不计正确字符；速度只反映真实击键（否则按 Tab 能刷速度） |
| D4 | 缩进单位 | **2 个空格**（素材禁止 Tab） |
| D5 | 错字能否退格改正 | 能：准确率按**最终态**算（正确/已输入），另显示「错误次数」计历史错 |

### 素材要求（谁来写都一样）

| 项 | 要求 |
| --- | --- |
| 语言 | JS / Python / SQL / 再加 1–2 门都行，但一次别超过 3 门 |
| 长度 | 每篇 ≤ 200 字符（含空白），保证 20–30 秒能打完 |
| 字符集 | **纯 ASCII**（中文注释会破坏等宽对齐） |
| 缩进 | **2 空格**，**禁止 Tab 字符** |
| 难度 | 入门级：不考语法知识，只考敲键盘（变量赋值、循环、函数调用、简单 SQL） |
