# 架构

> 依据：源码结构与我本轮的读码 + 命令实测（端点清单由 `server.js` 路由定义清点，表结构由 `db-config.js` 建表语句核对）。
> 图与代码冲突时改图；能用命令验证的依赖以命令输出为准。
> 最近更新：`3.1.261107.1938` 发版前（P20–P30 落地后）。

## 一、分层与依赖方向

| 层 | 位置 | 职责 | 依赖方向 |
| --- | --- | --- | --- |
| L1 静态资源层 | `public/`（`express.static` 提供，HTML 先经引用重写中间件） | HTML/CSS/JS/图标/头像；js/css 内容指纹作为 `?v=` 写进 HTML，指纹表由 `GET /api/asset-version` 暴露；`/service-worker.js` 由服务端响应时注入 `// asset-version: <版本>` 首行 | 只被浏览器消费 |
| L2 HTTP 路由层 | `server.js`（4184 行，**93 个路由**） | 参数校验、业务逻辑、响应组装 | 只能向下依赖 L3、L4 |
| L3 鉴权中间件 | `server.js` 内 `authMiddleware` / `adminMiddleware` / `raceAuth` | 校验 Bearer token，按 id 回查 `users` 取 role 再判权限；`raceAuth` 额外解析「我在哪个房间」的身份（选手 / 观战者） | 依赖 jsonwebtoken 与 L5 的只读查询 |
| L4 数据适配层 | `db-config.js`（687 行） | 方言差异隔离：get / all / run / exec / transaction / getTables / getColumns / getPrimaryKey | 只依赖 better-sqlite3 或 mysql2 |
| **L2.5 比赛运行时** | `server.js` 内的 `roomRegistry`（**进程内存**） | 房间状态机、选手与观战席、匹配队列、解散投票、服务端计时 | 依赖 L2 调用；**不落库**，只把关键时刻写进 `races` / `race_participants` |
| L5 存储 | `data/typing.db`（SQLite，WAL）或 MySQL `typing` 库 | 持久化 | — |

允许的方向：L1 ← 浏览器；L2 → L3、L2 → L4 → L5、L3 → L5（只读 `users` 取 role）。禁止：L4 反向依赖 L2；L3 除取 role 外不得直接读写 L5。

**L2.5 的硬约束**：房间状态只在内存，所以**只能单进程运行**（`AGENTS.md` §7）。多进程会让房间随机消失。这不是限制房间数——房间数上限由 `settings.race_max_rooms` 控制。

## 三、数据适配层的双分支

`createDatabase(config)` 按 `db-config.json` 的 `type` 返回同一形状的对象；调用方不感知方言。差异集中在四处：

1. 时间函数：`nowLocaltime` / `curDate` / `dateFn` / `daysAgo` 返回方言 SQL 片段，禁止在路由里手写时间函数。
2. 分页与长度函数：`CHAR_LENGTH` vs `LENGTH`、`SUBSTRING` vs `SUBSTR`，路由层用 `isMySQL(db)` 分支。
3. 事务：MySQL 分支把连接对象作为第一个参数传给回调，SQLite 分支不传（坑库 K-01）。
4. 元数据：`getTables` / `getColumns` / `getPrimaryKey` 各自实现，SQLite 走 PRAGMA，MySQL 走 INFORMATION_SCHEMA。

改任一侧都必须对称检查另一侧，这是本项目的固定成本。

## 四、比赛运行时（L2.5）

| 项 | 形状 |
| --- | --- |
| 房间注册表 | 进程内 `roomRegistry`：`code → room`；room 内含 `players`（`Map`，键 `u:<userId>` 或 `g:<guestId>`）、`spectators`、`status`、计时字段 |
| 状态机 | `waiting → countdown(3s) → reveal(1.5s，仅匹配房) → racing → finished / cancelled` |
| 计时 | **服务端权威**：`startsAt` / `finishedAt` / `revealEndsAt` / `maxDurationMs` / `remainMs`，前端只读快照 |
| 轮询 | `/api/race/tick` 每 1.2s（≤8 人）/ 2s（9–20 人）/ 3s（>20 人）；快照带 `dissolveRule`、`dissolve`、`players[].offline` |
| 匹配 | 进程内 FIFO 1v1 队列；配对成功建 `matchmade` 房（2 人、私密、**不可观战、不可解散**）；抽文候选按可用篇数自适应（3/2/1） |
| 观战席 | 手动房可开（free / host 两种模式、席位数、容量约 10%）；匹配房固定 0 席 |
| 解散 | 匹配房一律 400；手动房按 `dissolveRule`：在线 ≤1 直接解散、≤3 人全票、≥4 人 `floor(在线/2)+1`；**在线 = `lastSeen` 在 120 秒内** |
| 取消原因 | `host_leave` / `host_disconnect` / `all_left` / `all_disconnected` / `time_limit` / `duration_limit` / `dissolve_direct` / `vote_dissolved` / `opponent_left` / `admin` |
| 回收 | 结束房间保留 `RACE_ROOM_GRACE_MS = 60s` 供前端取结果，之后由 `cleanupRooms` 清出内存 |

## 五、前端结构

| 页面 | 脚本 | 职责 |
| --- | --- | --- |
| `home.html`（站点根路径 `/` 的默认页） | `home.js`（591 行） | **引导页**：欢迎语、三张动作卡、资料卡、指针与陀螺仪视差、匹配入口（1.5s 轮询） |
| `index.html` | `script.js`（1444 行） | 练习、排行、投稿、私人文章、离线文章入口 |
| `race.html` | `race.js`（1979 行） | 比赛大厅、建房与加入、等待厅、抽文（reveal）、比赛中、观战席、结算 |
| `profile.html` | `profile.js`（1268 行） | **两栏**：侧栏导航 + 8 个面板（概览 / 历史战绩 / 练习历史 / 错字本 / 我的投稿 / 私人文章 / 离线文章 / 账号设置） |
| `admin.html` | `admin.js`（2433 行） | 仪表盘、用户、文章、分类、公告、比赛、数据库面板、抓取 |
| `setup.html` | 内联 | 首次初始化管理员 |

共享脚本：`nav.js`（733 行，顶栏与头像菜单、**底部匹配条**）、`page-loading.js`（105 行，全站首屏遮罩）、`announcement-bar.js`、`custom-select.js`、`loading-indicator.js`、`theme-toggle.js`、`typing-engine.js`（494 行，分段与恒等映射）。

`service-worker.js`（395 行）负责静态资源缓存、IndexedDB 离线文章与离线比赛页兜底。

鉴权载体：token 存 `localStorage`，请求头带 `Authorization: Bearer`。前端认为能力边界由服务端 API 决定，页面本身不做权限拦截（`admin.html` 静态可达，数据接口有 admin 校验）。

## 六、外部进程

`crawler.py` 由 `server.js` 用 `execFile('python', ...)` 调用：抓取单页 90 秒超时、搜索 45 秒超时，stdout 返回 JSON、stderr 只取末 3 行。Python 依赖见 `requirements.txt`。
